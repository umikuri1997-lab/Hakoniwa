# 3Dから写す絵・モデル・リギング

`CLAUDE.md` の決まりのつづき（この話題の作業をするときに読む）。ぶつかったら `CLAUDE.md` が先。道具の場所・数字は `tools/art/` のスクリプトの名前で探す。

## 3Dから写す絵
- かげは、明るさ（明度）でなく、あざやかさ（彩度）でつける：かげほどあざやか・ハイライトほどうすく、明るさはかえない（持ち主がきめた。何度も言われている）。`furntone.py` の `SH`・`HI`。輪郭線だけ少し暗く。ほかのかげの付け方（木の `tone5` など）も、作りなおすときはこの決まりにする。
- 階段・坂・ハシゴの絵は、3Dの点を画面へ写した形（`iso-cliff.js`。ふちはぼかさず切る）を、形ごとに1回作ってとっておく。
- 3Dから写すチップの絵のわく（`iso_conn.py` の `PY0`・`HP` など）は、物のいちばん高い所まで入れる（わくで切れると、マスごとに上が四角く切れ、すき間が出る）。
- クォータービューのつながる物の絵（`iso_conn.py`）は、腕をとなりのマスまでのばして写し、見えている面のせかいの場所がそのマスの中のドットだけをのこす。マスのさかいの外へも1ドットのこす（`BLEED`。ぴったりで切ると、はんぱな倍率で絵のはしがうすくなり、つなぎ目に線が出る）。同じ線の上の箱・つつを2つに分けて、はしをつきあわせると、線とすきまが出るので、1本にまとめるか、もう一方の中までのばして上の面を少し下げる。
- 角度や形がゲームとずれる絵は、大まかな形を3Dで作り、ゲームと同じ見え方（x, y−0.8z）で写した参考の絵をいっしょにわたすと、そろう。3Dのお手本は、立体（三角形・奥行き）で作り、トゥーンシェーダー（かげは3だんの色）で写す。輪郭線はかかず、箱の角はすこし面取りする（`oblique3d.py`）。部品どうしの面をぴったり同じ所にかさねない（面があらそってざらざらの点が出る）。部材の納まり（どこにのる・どこをつらぬく・どこで止まる）を、実物と同じにする。手順はスキル `chip-art` の「3Dのお手本から絵をたのむ」。
- どの3Dも、まず、じっさいに作れる設計図（部品ごとの形・寸法・何にのるか・どこでとめるか）を考えて書いてから、その数字で組む。設計図は設計図のファイルのはじめにも短く書く。同じ物がならぶ所（天板の板など）は、同じ寸法にする（`tools/art/blueprint.py`：部品の表から、設計図と3Dの両方を作り、ささえにとどかない部品を赤で出す）。木・石像など、形が自由な物はのぞく。小物（はち植え・本・やさい など）は、CC0のフリーの3Dモデル（`tools/art/models`）を置く。トリポで作ったモデル（木・花・草・岩・小物）は `tools/art/models/tripo/README.md`（一覧の絵 `catalog.png`）を見てえらぶ。モデルを足したら、その一覧と `tripo_catalog.py` も足す。
- 新しい物の3Dを作る前に、Polyfork（`https://polyfork.dev`。無料のローポリ3Dモデル。さがし方は `/prompt.txt`、`/api/assets?q=…&free=1`）で使える物をさがし、あれば、それをもとに写す（持ち主がきめた）。形・色・材質は、ゲームの見え方と、ステージの洋風・和風の決まりに合わせて直す。GLB などのファイルはリポジトリに入れない（写す道具が、モデルの id からそのつどダウンロードし、リポジトリの外におく）。写したドット絵だけを入れる。使ったモデルの id・ページは、設計図のファイルのはじめに書く。
- 3Dの絵に、黒っぽいこいかげを使わない。トリポなどでもらったモデルは、くらい色・色むらをへらし、あざやかにしてトゥーンの色にしてから写す。
- いまあるテクスチャ（`tools/art/textures`）・マテリアル（`oblique3d` の `material`）で表せない材質が出てきたら、CC0のテクスチャを新しく取ってくる・マテリアルを足す（出どころは `textures/README.md`）。いまある物でまにあわせない。
- 3Dの物の柄（ふとんの月と星など）は、3Dの面にのるもよう（`sc.decal`：面の場所→色）で入れる。ます目の色や、はりつけた四角で描かない。布がたれる所は、ひろげた布の上の場所（`yorubed.py` の `unfold`）で柄をきめる。
- 料理の家具の上の食べ物は、あざやかな色（`cooktop.py`：あざやかさを上げ、モデルに白をまぜない）。白・クリーム色の物と、うつわ・道具はそのまま。
- 3Dから写す家具・建物（料理の家具と、その上の道具もふくむ）は、木と同じ5色のかげ（設計図に `TONE5=True`、`furntone.py`：左上の光・部品ごとのもとの色から5色と輪郭・平らな面はあみにせず、まるい面のさかいめだけ市松のあみかけ。持ち主がきめた）。だんのさかいめは光の向きとの内積の数（上の面・左の面→もとの色・正面→かげ・右の面→こいかげ）で、木のような順番（%）にしない（平らな面がまるごとあみになる）。料理の家具の上の食べ物だけは `TREESHADE`（持ち主がえらんだ）。
- かげ（`furntone.py`）は、輪郭線・部品のさかいの線のそばを明るくしない（`RIMHI` 0。持ち主がきめた。いまある絵は、写しなおすまでそのまま）。あみかけ（市松もよう）は最小限（持ち主がきめた）：はばは `DW`（設計図の `DITHER` でかえられる）。色のさかいめは、あみでぼかさず、段のまま見せる。
- つやのある物（金属・やきもの・ガラス・たべ物の皮）は、部品に `p.shiny=True`。たいらな水面（スープ・のみもの）は向きで光が出ないので、白い光のだ円をのせる（`cooktop.py`）。
- 3Dから写す家具は、かげを4だん（`GRAD=True`）にし、まるい物（`lathe`・`cyl`・`ball` など）は、なめらかなかげ（`sc.smooth`：ドットごとに面の向きをまぜて段をきめる）。ひくいドームなど上を向いたふくらみは `p.curve`（ないと1トーンに見える）。輪郭線はやわらかい色（GRAD のとき）。光る物（火・あかりのガラス・ランプのかさ）は、かげのかわりに色のグラデーション（`p.glow`・`p.decal`、火は `common.flame`）で、1トーンにしない。
- まるい物（噴水の池など）は、奥行きだけの遠近だと、たまごの形に見える。左右にも同じ遠近をかける（`FULLPERSP=True`）。水は、重さで放物線をえがく粒（`PWATER`）にする。
- 岩・石を、三角・四角などコードで組んだ形で作らない（持ち主：ぜったいだめ）。入れてある CC0 のモデル（`tools/art/models` の polyhaven・kenney・quaternius）・トリポのモデル（rock・stone_*・pebble*）を使う（`hullrock` はのぞく）。ほかの物も、合うモデルがあれば、まずそれを使う。
- 葉・草・苔など植物を、ただの丸（`ball` などの玉）で作らない（持ち主：二度としない）。トリポの植物のモデルか、葉の部品・粒で形を作る。
- 植物の3Dモデル（木・草・花・茂み）を作る・直すときは、スキル `.claude/skills/realistic-plant-3d`（持ち主がくれた物）を読む。この環境に Blender はないので、`pip install numpy trimesh matplotlib` をしてから、同梱の `scripts/plant_geometry.py`（numpy/trimesh で GLB）を使う（スクリプトは `scripts/` から同じ所の部品を読むので `python3 -I` にしない）。ドット絵にするときは `model3d-pixel` とこのファイルの決まりが先。
- コケ・つた・足もとの草むらは、葉の玉の部品でなく、粒で作る。写す範囲の外に出る粒は `PBOX` に入れる（入れないと切れる）。石の目地の線をうすくするのは部品の `olk`（まわりのふちの線もうすくするので、目地だけなら `OUTERK=True` も）、全体のコントラストは設計図の `CONTRAST`（輪郭線を作る前の色にだけかける）。粒のかたまりにも輪郭線（`POUT`）。
- 3Dから写す絵は、下のはし（`BOTTOM`）をそろえて切りぬくので、はねる・とぶ高さは絵に入れても出ない。ポーズはのびちぢみ・向きだけにし、高さはゲームで描く位置を上げる。
- 3Dから写す高い建物（灯台・見張り台など）は、遠近をかけない（`PARALLEL=True`。奥行きだけの遠近では、上ほどたてに大きくのびる）。
- 3Dのガラスは material `glass`（すける入れ物）・`glassc`（色ガラスの置き物）・`gwater`（ガラスの中の水）。うしろに何もない所にもかさねて、チップは半透明になる。部品は `p.glass`・`p.glassc`・`p.gwater`。限定の家具のかげは3だん・あみ少し（`TONE3`、持ち主がきめた）。
- 白いかべ・あざやかな屋根は、ふつうのかげだと灰色・にごった茶色に見える。場所ごとの色（`p.decal`・`p.flat`）でかげを入れ、段は6〜7だんにする。まるい物の角の数（`detail`）は96。
- 3Dからそのままドット絵にするときは、1マス64ドットで、ちぢめずに写す（`oblique3d.render_px`）。同じ面にそろえて組んだ材は、`grp` で同じグループにして線を引かない。ほかの材につきあてる材は、はしをその材のふちにそって切る（`prism`）。向きの絵は、1つの3Dを `Scene.turn` でまわして写す。動く部品は、軸のまわりに部品をまわして、コマごとに写す。奥行きだけに遠近をかけるときは `oblique3d.persp`。2×1などの物は、設計図に `SZ` を書く（書かないと1マス上にずれる）。布・砂のなだらかな物は `p.soft`、水は `'clear'`。木材は、どの部品も同じ色（`furn3d/items/common.py` の `WOOD`）。かげの色は、ベースの色の明るさ−35・あざやかさ+10、輪郭線は2ドット。金属は `sc.material('metal')`。木目などのテクスチャは、CC0の物（`tools/art/textures`）を `oblique3d.Tex` で部品ののびる向きにはり、明るさのちがいだけを3だんでつける（流れる向きになめらかにして、短い点を消す）。
- 絵を生成AIにたのんでうまくいかないときは、ゲームの形どおりの下絵をコードで描いて、清書をたのむ。
- 3Dモデルを作ってドット絵にするときは、スキル `.claude/skills/model3d-pixel/SKILL.md` の手順でする。
- まるい切り口とまわりの皮のように、ふちの点の奥行きが行ごとに入れかわる2つの部品は、さかいの線が手前の面へ2ドットとびこむ（横線に見える）。`sc.over(手前, うしろ)` で線をいつもうしろのがわに（`log` はそうしてある）。
- 木目・樹皮のすじ（`furntone` の `STREAK`）は、すじの向きで細長さをはかり、ななめにつづくドットも1本にする（外わくの四角ではかると、ななめの丸太のすじが消えた）。小さなアイコンで見えないときは、3つめにかえる段の数（木材のアイコンは2）。

## コワイノ・カゲドロボウ
- コワイノのやられ（さいごのコマ）は、横から見て、その場で下へグチャっとくずれる（布が重さでつぶれ、体が地面につき、持ち物は地面へ落ちる）。よこへ たおれこませない・上から見たような形にしない。
- カゲドロボウのふくろは、体とはなれた布のかたまり（色わけ `base` で、いちばん大きなかたまりでない所）を、べつの色（`sack`）にする。色わけ（`lab`）はかえない（ボーンは `lab` で見る）。
- コワイノの絵は、3Dから写したモーション（`kowaino_paint.py --sheets` → `kw_chips.py` でチップ `kg_<名前>:<動き>` に入れる）。攻撃4コマ・やられ5コマ。
- コワイノのモーションを直したら、毎回、コカゲもふくめた14体の絵を作りなおして、ゲームのチップにも入れなおし（`kw_chips.py`）、GIFのページ（https://claude.ai/artifact/AUCWnXd9HDwcKvArB7WhzC、`kw_gifpage.py` で作る）も公開しなおす（持ち主の指示）。

## リギング・モデル
- 3Dのモデルに骨を入れる・リギングを直すときは、Blender（bpy）でアーマチュアと自動の重みを使い、スキル `.claude/skills/rigging`・`rigging-basics` と、はこにわでの使い方 `.claude/skills/rigging/HAKONIWA.md` を読む（骨は、断面をはかって関節に置く・さこつ・重みはメッシュの上の道のり・部品の体は部品ごと・大きなポーズでのびをたしかめる）。
- Blender（bpy）で作業するときは、`.claude/skills/blender-core`（はじめに読む）・`blender-character-rigging`・`blender-animation`・`blender-stylized-npr` も読む。ぶつかったら `CLAUDE.md` と `rigging/HAKONIWA.md` が先。
- 持ち主が Blender で直すためにわたすモデルは、ボクセル・マーチングキューブで作らない（せいれいでそうして、形がひどく顔も目もなかった。持ち主：独自のやり方はだめ）。ふつうの作り方：正面・横の下絵を置き、ボックスモデリング（四角ポリゴン・ミラーとサブディビジョンは適用しない・関節にエッジループ）、体は1つのオブジェクト、顔・目も入れ、色わけはマテリアル（点の色にしない）。骨はふつうの人型のならびと自動の重み（`tools/art/spirit3d/model_blend.py`）。
- ボーンで動かすモデルは、べつに動く部品（こぶし・持ち物）と体・足が1つのつながった形だと、動かしたとき、つなぎの面がのびる。glb で切りはなす。腕の支点は、手ではなく、かたにする。
- もらった3Dモデルの形・色わけを直すときは、写すときの処理でごまかさない。モデルそのもの（glb）を直す：いらない所を消す・点をうごかす・部品を足す。色わけはマテリアルで持たせる。直した glb を持ち主にわたして、Blender で見てもらう。持ち主が直した glb のマテリアルは、そのまま色わけに使う（コワイノ：`kw_model.py`）。
- タップの案内の指（`#tutHand`）は、前のドットの絵（`tools/art/finger/old-*.webp`）から、白いつや（光）をなくした絵（持ち主がきめた。`finger3d.py` は使わない）。

## 御神木・カミサマ・せいれいの動きの絵
- せいれいの絵は、クォータービュー（`build.py --iso`）と、守り神と話すときの正面の絵（`build.py`。使うのは正面の行だけなので、正面だけ写して、横・うしろの行は同じ絵でうめる）。正面の絵の横・うしろは写さない（持ち主：むだなことをしない）。
- 動き（モーション）を持ち主に見せるときは、かならず GIF で送る（止まった絵をならべて送らない。持ち主がきめた）。
- せいれいの表情の目・ほっぺも3Dで写す（持ち主：絶対まもる）。2Dの絵をあとからかさねたり、ずらしたりしない。
- せいれいごとの色のずれ（`vr.h`・`vr.l`）は、ずきんの印の絵（`SPMQ`・`SPM` の `k`。ずきん・頭のかざり・芽・はねのドット）のドットだけに、そのドットの色の色相・明るさをずらしてかける（かげの帯は色がまざるので、色の表で入れかえない）。表情の層は色の表のまま。
- 道具の向きは手の骨のねじりできまる。IK のうでも、「たらす→横へひらく→前へふる」回転（`armswing`。前へふるのをあとにすると、水平をまたいでもねじれがとばない）でおき、いちばん小さい回転（`align`）にしない（手がねじれて柄が横を向く）。道具の向きは、動きの `t`（ねじり）・`k`（手首）できめ、GIFで見てたしかめる。
- 持ち主がわたしたモデルは、そのまま使う（持ち主：似たように作りなおさない）。せいれいは `tools/art/spirit3d/model/<属性>.fbx` の骨を、動きの数でそのまま3Dで動かし、そのメッシュをドット絵に写す（`fbx_motion.py`・`fbx_pixel.py`）。部品に切り分けて組みなおしたり、色をチップの絵から写したりしない。
- カミサマのマップの絵（チップ `god`）は、持ち主のモデル（`tools/art/models/god/saint_monk.glb`、トリポ。色なし）に、部品ごとの色をぬった `god_monk.glb`（`tools/art/god3d/monk_paint.py`。すその金色の帯は、服を高さで切ってわける）を、家具と同じ道具（`iso3d.py god`、設計図 `furn3d/items/god.py`）で写す。色は前のカミサマの絵の濃さ（モデルの色を白にまぜない `p.vivid`）・あみかけなし（`DITHER=0`）。会話の立ち絵は正面のまま。参考の絵は `god3d/ref.jpg`。
- 御神木の切り株・芽・若葉・若木・御神木（`story:stump`〜`story:tree`）は、トリポのモデル（`sacred_stump.glb`）から3Dのまま写す（`sacred_tripo.py`、`--chips`）。幹のまん中は4×4マスのまん中。光のつぶは絵に入れず、ゲームで動かす。温石だけは、もらったPNGから `tools/sacred-tree-art.py`。
  - 葉は、モデルの葉のかたまりの表面に小さな葉の部品をならべ（かたまりの中は線を引かない）、写したあと、葉の中の3ドットまでの点はまわりの色にする。
  - 木の皮は、モデルのテクスチャの明るさ（4だん）に、幹・根・枝ののびる向きにそったみぞとすじ、なめらかな色むら。ヌシの傷は、どの段階も同じ形・大きさ（画面の上での形）で、メッシュをえぐって作る。
- 横になった絵を作るのに、立った形の絵をゲームの中でまわさない（床で寝る絵でしていた。ベッドと同じく角度が合わない）。体を3Dでたおして（`lean`・`roll`、足もいっしょに `legbody`）写す。
- 横になる・ねころぶ絵を、立つ絵のカメラ（少し見おろす25度）で写さない（体の向きが、見おろしの家具・ベッドと合わない。持ち主：角度が合っていない）。家具と同じ見おろしで写す（動きに `isocam=1`。`fbx_pixel.ISOCAM`）。置き場所は、地面の点（マスのまん中から何マス）と高さできめて、画面の点へ写す（`standPt`）。せいれいを立てて描く絵の中のずれ（px・py に足す）で動かさない（画面の右・下へ動くだけで、ななめのマスにそわない）。ゲームの画面で写してたしかめる（`tools/art/spirit3d/sceneshot.cjs`）。
- せいれいのうでは短く、手を頭より上に上げると、ずきんにかくれて見えない。手を見せたい動きは、胸の前まで。
- せいれいはまっすぐ正面から写すので、うしろななめの絵では、前へ出した手・道具が画面で上がらず、体の横に出て見える（となりのマスは画面のななめ上）。となりのマスへ手をのばす動きは、うしろ向き（`face` 2）だけ手を高くし、ゲームの画面で写してたしかめる（GIF だけでは気づけない）。口のある道具（じょうろ）は、道具の `fwd` で口を体の正面へ向ける。
- 後ろ向きの腕は、全モーション共通で頭より先に描く（頭巾の表面へ手を重ねない）。
- クォータービューのせいれいは、立てる描き方のままだと、たてにつぶれるので、よこを `ISOSPX`（`IQSY/IQSX`）にして、もとの絵の比で描く（高さはそのまま）。
- せいれいの動きは、3Dから写した絵（`js/spirit-motions.js`。目・ほっぺ・まつげ・食べ物・水のつぶ・つり糸は、いまの描き方でかさねる）。作るのは `python3 tools/art/spirit3d/build.py [動きの名前...]`（`--iso` も）。動きを足す・かえるのは `motions.py`、道具は `props.py`。
  - せいれいを描くのは、この3Dの絵だけ（持ち主がきめた。パーツのドット絵を組む描き方・線と丸の描き方は、けした。もどさない・新しく作らない）。絵のない行動は立ち姿（`stand`）。新しい場面（すわる・ねる など）には、3Dの動きを足す（`spMotion`）。その動きの絵を読むあいだは、立ち姿（`spmPin`：はじめに読んで手ばなさない）で待つ。行動で使う動きは、歩いてむかうあいだに先に読む（`work-fx.js` の `workAnims`。動きを足したら、ここにも足す）。
  - 立ち姿になる動きをのこさない（持ち主：ぜんぶ差しかえる）。ゲームがわたす動きの名前（`anim`）には、かならず3Dの動きを作る。すわっているときは、すわった形の絵（`sit`・`sit_<動き>`：`motions.py` の `SITOF`）だけを出し、立った形の絵をいすの上に出さない。進みぐあいでコマをえらぶ動き（たたく・弓・場面の姿勢）は `P1` で作り、ゲームの `SPMPROG` に進みぐあいの出し方を書く。
  - パーツの絵（頭・体・うで・ずきん など）は、ゲームのチップにはない。光・闇の3Dの形を作る道具が使うので `tools/art/spirit3d/parts` にある（`core.chips`）。ゲームのチップは、目・まつげ・ほっぺ（`sp:face`・`sp:lash`・`sp:cheek`）だけ。
  - 形は、チップの正面の絵と横の絵の、両方の形の中にある所（高さごとの切り口はだ円）。止まっていれば、いまの絵と同じシルエット。うでは絵を軸のまわりに回す（細さがかわらない）。
  - 外がわのまわりに1ドットの輪郭線（となりの色より少しだけ暗い色、黒にしない。持ち主がえらんだ）。描くときにつける（べつの画面に描き、少し暗くした写しを上下左右に1ドットずらしてうしろにかさねる）。
  - 体と手足・頭のつなぎ目に線を引かない（持ち主の指示）。手前の手足がうしろにかさなる所だけ線。重なりは本当の奥行き。部品に奥行きの数を足して、ほかの部品との前後をかえない。顔は、ずきんにだけ勝つ。体より前に出たうで・手・道具は、頭（ずきん・顔・頭の上の物）にだけ勝つ（持ち主がえらんだ）。うしろ向きでは、3Dの奥行きのまま（持ち主の指示）。目はゲームでかさねるので、頭の上で手前にある、うで・手・道具の所は、もう1まい（絵の下に、正面・横・うしろの3行を、かさねる所の高さに切りつめて）にして、目の上にかさねる。
  - せいれいは、家具の見おろし（51度）ではなく、まっすぐ正面から写す（51度だと、横向きで手前と奥のうでが大きくずれる）。
  - 頭の色は、カメラに近い向き（前・横・うしろ）の、いまの絵の色をうつす（面の向きごとにまぜると、色がざらざらになる）。うしろ向きは、正面の形を裏から見る（持ち主がえらんだ）。
  - 道具は手に直角にくっついているので、ふる道具は、手首で柄の角度をうでとべつに動かす（トンカチ：打つときは柄がほぼ水平で頭の面が下）。
  - うでは、まっすぐ下にたらしたうでを、向きごとに、いまの絵と同じ角度だけ外へ開く。しっぽは、おしりから生えて、まっすぐ上からうしろへ64度、面を横に向けて30度ひねる（持ち主がえらんだ）。
  - 頭巾の先・しっぽは、体が大きく上下する動きでは、体の高さにばねでつながったように、おくれて行きすぎてもどる。横向きの奥の足は1段暗い色。歩いていて、よこ向きと正面・うしろ向きがかわるときは、すこしのあいだ、前の向きの体のまま首だけ先に向ける（画面の1コマごとに1だんずつ出す）。どれも Frostwind（MIT）の考え方。

- ゲームの3Dのせいれいの姿勢は、2Dと同じ `fbx_motion.pose` を焼いた骨の表（`tools/3d/bake-poses.py` → `assets/3d/pose-*.bin`）。モデル・`motions.py`・`props.py` をかえたら、`node tools/3d/bake-spirits.cjs` と `python3 tools/3d/bake-poses.py` の両方を動かす（骨の番号と場所を合わせている）。

## まとめ（細かい手順は道具のコードを見る）
- トリポのモデルを家具にそのまま使うとき（限定の家具）は、`gf_build.py` で作りなおし、できた `check.png` を毎回見てから出す。形はへらさない・色はデザインの絵を焼く・点の向きは面の大きさで重みをつける・オブジェクト（glb のノード）ごとにべつの部品にする。
- せいれいの3Dの動きの絵：外がわに1ドットの輪郭線（黒にしない）。体と手足・頭のつなぎ目に線を引かない（持ち主の指示）。重なりは本当の奥行き。体より前に出たうで・手・道具は頭にだけ勝つ。まっすぐ正面から写す（家具の見おろしにしない）。うしろ向きは3Dの奥行きのまま。
- コワイノは4つの向き（正面・うしろ・右・左。右と左はべつに写す、反転しない）。目は3Dのだ円で、写したあとに2Dでおさない。モーションの色は、はじめのコマできめて全コマで同じにする（ちらつく）。
- 洞窟のバケモノの骨の重みは、Blender のボーンヒートで作る（手作りの直しはかけない。10倍の大きさにして入れる）。
- 動きのデータ（`spirit-motions*.js`）の目の行 `e` は、ゲームが描く向きだけ書く（`build.py` の `EYEROWS`・`EYEROWS_ISO`。正面は0、クォータービューは0と2）。ほかの向きを描くようにするときは、そこに足して作りなおす（足さないと、その向きで落ちる）。
- Blender は `pip install bpy` で入る（`import bpy`。5.3）。植物のスキルの見なおしは `python3 .claude/skills/realistic-plant-3d/scripts/render_review_blender.py -- <1つの物の.glb> <出すフォルダ>`（クレイと材質を8つの向き。1株で約25秒）。
- 植物を3Dで作る前に、かならず本物の写真を見て、構造（株の形・葉のつき方・花のつき方・花の形と向き・色）を書き出してから作る。写真が見られないときは、つなぎ先を申請して見る（持ち主がきめた）。
- 3Dのゲーム（`js/3d/`）のせいれい：表情の目・ほっぺ・まつげは、顔の面に2Dと同じ式（`face_fit`）でチップをはる（3Dの目の形は作らない）。はねをたたむ形・手のまん中・道具の先は、`bake-poses.py` が焼く（モデル・motions.py・props.py をかえたら、`bake-spirits.cjs` と両方）。`bake-poses.py` で `FM.scene` が返す辞書は、属性をかえると中身がかわるので、あとで使う分は `dict(S)` でうつしておく。
