# プログラムの決まり・重さ

`CLAUDE.md` の決まりのつづき（この話題の作業をするときに読む）。ぶつかったら `CLAUDE.md` が先。数字（メモリ量・コマ数）はコードが本物。

## 絵と音のファイル・ブラウザ
- マップチップのアトラスは、使う物のページだけ読む（ぜんぶ読むと、ひろげて約360MBになり、iPhone で絵が作れない）。`tools/chips.py` の `pack` は、物の種類（`fam`）ごとにならべて、512のページにつめる（1024だと、1こ使うだけで4MBひろげていた）。切り出しおわったページは、20秒使わなければ手ばなし（`chaFree`）、つぎに使うときに読みなおす（`a.fr`。`chaReady`・`chipPend` は手ばなしたページを待たない）。アトラスをぜんぶ読む処理（ページの一覧をまわして `chipPage` をよぶ）を書かない。タイトルも、場面に出る物を1回ずつ描いて、そこで読みはじめたページだけを待つ（`index.html` の `ready`。#2220 で全ページを読んでいた）。読みこみ中のページの物は、`drawChip` が何も描かない（`chipPend`。仮の絵を一瞬出さない）。テストで描いた色をはかるときは、`chaReady()` を待ってから。
- クォータービューにする前の絵（正面・上から見た絵）を、読みこまない・待たない。同じアトラスのページにあるだけで、いっしょに読まれて重くなる。クォータービューの絵ができたら、アイコン・タイトル・うすい形も、その絵にかえて、古い絵は `tools/art/unused-chips.json` に書いてけす。読みこみ待ちのリスト（`GCH`・`WCH`）は、そのステージで描く物だけ。
- 画面に描くアイコン（`ICI`）・気持ちの絵（`EMOI`）・絵文字のかわりの絵（`EIMGI`）は、1まいのアトラス（`js/icon-atlas.js`）から切り出す（`icoaImg`。1まいずつ読むと、マップを開くのがおそくなった）。`ICONS`・`EMOS`・`EIMG` の絵をかえたら `python3 tools/art/icon_atlas.py` を動かす。メニューの `<img>` は1まいずつのファイル（`ICONS` の URL）のまま。
- 持ち物のように、`iconURL` で作るアイコンをたくさん出す画面は、開いたときにその場で作らない（アトラスのページは手ばなしているので、読みなおしを待って絵がおくれる）。ゲームの手があいているときに先に作っておく（`iconWarm`）。アイコン・説明の図を作るとちゅうで、読みこみ中のページの物があったら（`CHPN` がふえたら）、その絵はとっておかず、かりの空の絵にして、ページがとどいてから作る（`icWaitURL`・`icWaitDone`。しないと、コードの仮の絵のアイコンがのこる）。
- 絵と音は、JS の中に文字（base64）で入れない。ファイルにする：マップチップは、アトラス（`assets/chips/*.webp`）にまとめ、chips.js には場所だけ（`tools/chips.py`：`unpack` でほどいて JSON を直し、`pack` で作りなおす。pack は元の絵とドットまで同じかたしかめる）。プログラムの絵と音は `assets/g`、フォントは `assets/f`。ファイル名は中身から作る。絵は、画質を落とさない WebP（ロスレス、`exact`）。
- サービスワーカー（`sw.js`、公開したページだけ）が、名前に中身の番号がある物（`assets/`・`?v=` つきの .js）をスマホに保存し、2回めからネットを待たない。中身をかえたら、かならず名前（番号）もかわるようにする（同じ名前のまま中身をかえると、古い物が出つづける）。index.html はネットが先。
- 公開のとき（`pages.yml`）、`tools/minify.cjs` が、ファイルごとに注記と空白をとる（terser。名前はかえない・式も組みかえない・1つにまとめない：かわったファイルだけ読みなおすしくみをのこす）。リポジトリのコードは、そのまま。関数の文（`toString`）の空白や注記にたよる処理を書かない。
- `index.html` は、はじめにタイトルと同じ色の `#boot` を出し、タイトルのすぐあとで `#boot` をかくす（真っ白にしない）。開発用のメモのコメントは、ファイルのいちばん下。
- ブラウザでたしかめるときは、サーバーをとおして開く（file:// だと、toDataURL がつかえない）。テストのサーバーは、ほかの作業のサーバーとポートがかさならないようにする（`--directory` で自分のフォルダを出す）。

## 重さ
- キャンバスのタップの場所は、キャンバスの上の場所ではかる（`input.js`）。ページがスクロールしたままだと、画面の場所とずれる。ページがずれたら、もどす（`scrollTo(0,0)`）。
- Android の「戻る」でゲームのページから出ないように、さわったときに履歴に印を1つ足す。Chrome は、さわらずに足した履歴を戻るでとばすので、さわるたびにたしかめる。
- iPhone は、キャンバスのメモリの上限が小さく、こえるとページが落ちる。作業用のキャンバスは、使いおわったらすぐ手ばなす（`width=height=0`）。作っておく絵は、量がわかる形にする。
- マップ全体の大きさのキャンバスは作らない。地面は区画の絵（`iso-ground.js`）。区画は、画面に見えている所と、そのまわり1区画だけ作っておき（読みこみのときは見えている所だけ）、見えなくなってしばらくたって外になった区画は手ばなす。
  - マップを開くのは、絵（アイコン・そのほかの絵と、地面と水のチップ）が読みこめて、はじめの画面のまわりの区画を作り、はじめの画面を1回描いて、そこで読みはじめたアトラスのページがそろってから（`chaReady`）。それまでは「マップを読みこみ中… 〇%」でマップをかくし、ゲームの時間も止める。マップを作る仕事は、1こずつの一覧にして、1コマに少しずつすすめる（一度に作ると画面が止まって%が出ない）。ゲームがはじまってから、地面の絵などの読みこみに入らないようにする（アトラスのページだけは、はじめて出る物のときに読む）。
  - 読みこみで作る区画は、画面に見えている所だけ（まわりの1区画は、遊びはじめてから、時間があまったときに作る）。区画を作りはじめるときに、地面をぬいたはじめの画面を1回描き（`GRD.nob`）、そこに出る物のアトラスのページを先に読む。地面と水のチップのページは、アイコンより先に高い優先度（`chipPage(n,true)`）で読む。読みこみ中の区画のドットごとの計算は、ワーカーで同時にする。ワーカーは、もう読んだ `igPixels` の文から作る（ネットから読みなおすと、スマホではアトラスのうしろで待たされた）（計算は `iso-ground-px.js` の `igPixels` を、画面のスレッドと同じに使う。読みこみがおわったら手ばなす）。
  - ゲーム中に作るのは、物を置いて変わった区画と、画面を動かして近づいた区画（1コマ8msまで。見える区画を先に）。ちぢめたときは半分の細かさの区画、拡大が小さいときは、高い段の上の面を半分の細かさの1マスの絵にしてとっておく。どれも、しばらく使わなければ手ばなす。高い段の上の面は、区画の絵のそのマスにかかる所だけ写す。土のだんの上の面（`ICT`）は、マスごとに作っておき、毎コマは、その絵と、かたちを色でぬった絵をかさねるだけ。毎コマ、作業用のキャンバスで組みたてない。
  - チップの1コマずつの絵は、はじめて描くときに切り出す（全ステージの全コマを読みこみで切り出すと約86MBになる）。タイトルの絵は、タイトルをかくしているあいだ手ばなす。風のステージでヌシ様が出るときは、ヌシ様の絵（約19MB）も。せいれいの動きの絵は、色をかえたコマの数の上限と、60秒使わなければ手ばなす。HD-2D の仕上げの作業用のキャンバスは、画面の1/6と1/12の大きさ。メモリをふやす変更をしたら、はかって書きかえる。
- 区画ごとの絵を画面に拡大して描くときは、絵のまわりに、となりの中身を数ドット（のりしろ）よけいに描いておき、のりしろごと描いて、となりの区画とかさねる。iPhone の Safari は、拡大するとき、描く絵のはしを透明とまぜるので、ぴったりならべると区画のさかいめにうすい線が出る。Chrome では出ないので、Chrome でたしかめるときは `drawImage` を、切りとった所のまわりを透明にして描くものにおきかえて見る。
- 作っておく絵（地面の区画など）に、チップ（`drawChip`・`drawFloor`）を描くときは、読みこみ中のアトラスのページの物があったか（`CHPN` がふえたか）を見て、ページがとどいたら作りなおす（`igPendDone`）。しないと、その区画だけ仮の絵のままのこる。
- おわりの処理つきのカメラの動き（`camAnim.done`：鉱脈が目をさます・オオカゲの登場など）は、画面をさわっても止めない・`panTo` で上書きしない。止めると、おわりの処理がよばれず、`GIFT_ACTIVE` などがもどらなくて、ゲームが止まったままになる。ほかのカメラの動きに上書きされたときは、1コマの見はりが、おわりの処理だけをよぶ。演出のカメラの動きは、村を切りかえるときのかたづけで、自分の動きだけ消す。
- セーブスロットはなくした。セーブはオートセーブだけ。`performance.now()` の時刻（`bowT` など）はセーブに残ると、読みこんだあと、いまより先の時刻になる。くらべるときは「いまより前か」もたしかめる。
- ヘッドレスのブラウザは写す（screenshot）のがおそく、そのあいだにエフェクトがおわる。エフェクトを写すときは、`fx` の `life` を setInterval で止めて写す。タイマーの時刻のテストは、ゲームの中で時刻をはかる。重さをはかるときは、1コマごとに requestAnimationFrame で画面に出してからつぎを描く。
- スマホでも動くようにする。毎コマ・毎秒の処理に、むだな計算や一覧づくりのくりかえしを足さない。ただし、重さを理由に複雑な仕組みを入れない。単純で、数字が見てわかる形を優先する。
- 夜の明かりは、暗さを画面と同じ大きさの別の絵にぬり、明かりの所の暗さを光の絵（半径ごとに1まい）でけずって（destination-out）、かさねる。光の色をかぶせない（黄色いもやに見える）。明かりの一覧は `LITP`（`recount` で作る）。毎コマ、マスを1つずつ調べたり、ぼかしの絵を作ったりしない。
- 浅瀬は、砂の光（1まい）とマスごとの小石の絵を1回作っておき、ならべる。毎コマ描くのは、動くさざなみだけ。
- キャンバスの `filter`（`blur()`・`brightness()` など）を使わない（重い・古い Safari では効かない）。ぼかしは、小さくしてなめらかに大きくもどす。暗くするのは、絵の上に黒をうすく重ねる（`source-atop`）。
- 描いてから `getImageData` で読むだけの作業用のキャンバスは `getContext('2d',{willReadFrequently:true})`。ドットごとのくりかえしの中では、`S.ground`・`GT.d` などを先に手もとの変数にとり、0以上の数の切りすては `|0`、まとめてうつせる所は行ごとに `set` でうつす。

- 遅れて動く処理：ゲームと演出（S・フラグ・会話・fx・カメラ・世界の音・知らせ）は `later`（core.js の予約の係。メニュー・タイトル・マップえらび・かくしたタブのあいだは止まる）か、村をさわるなら `villageTimeout`。setTimeout は、画面の部品だけ・シートの中の動き（シートをひらいたまま動く物）・音の先読み・読みこみ待ちだけ。シートをとじる処理や、シートをひらいたまま進む処理を `later` にしない（止まったままになる）。テストで予約を進めるときは `clockStep(ms)`。

## 関数の名前・ファイル
- せいれいの名前の定数は、その子の名前のローマ字（`FUTABA='フタバ'`）。名前をかえたら、定数の名前もかえる。
- `pickFresh` に1つだけの一覧をわたすと、2回めから `undefined` をかえす（1つなら、そのまま使う）。
- ほかのファイルと同じ名前の `function` を書くと、あとで読みこむほうが黙って上書きする。`npm run lint`（`tools/lint.cjs`：ESLint で js/ をつないで調べる。PRごとに GitHub でも動く）で見つかる。わざと入れかえるとき（思い出帳の再生など）は `window.〇〇=` と書く。
- ゲームの js/ に、ほかのファイルの関数の、かわりの空の関数を置かない。一部のファイルだけを vm で読むテストのかわりの関数は `tools/tests/vm-stubs.js`。
- Python の行のおわりに `#` の注記を足すときは、その行に `;` のあとのつづきがないかたしかめる（つづきまで注記になって、処理が消える）。
- プログラムは `js/` に役目ごとに分けたふつうの script（`index.html` の読みこみの一覧 `U` の順に、あいだをあけずに動かす）。ファイルを足したら、その一覧に足す（大きさの表 `E` は、公開のときに `tools/sizes.cjs` が書く。手で書かない）。読みこむときにすぐ動く所（関数の外の処理）では、あとのファイルの関数・変数を使わない。

## ログ・テスト・見た目のたしかめ
- ログ（`js/log.js`）：エラーは、いつも記録（`lgErr`）。せいれいの行動（`lgStart`・`lgEnd`・通れない・止まった）・会話・目標と待つわけ（`lgTick`）は、設定の「くわしいログ」が入りのときだけ（`LOGV`）。さいごの3000行をためて、1500行を localStorage（`hakoniwa-log`）にのこす。不具合をしらべるときは、持ち主に書き出したログをもらう。新しく止まる・やめるわけを足したら `lgR` も入れる。量の多い所では `if(LOGV)` で、切りのときは何も計算しない。
- テスト・自動プレイ・夜の実験の道具と使い方は `tools/tests/README.md`。テストは、PRごとに `node tools/tests/run-all.cjs --changed`（サーバーも自分で立てる）。ぜんぶ動かすのは、持ち主がたのんだときだけ。しくみをかえたら、それをたしかめているテストと、自動プレイの進め方（`tools/sim/autoplay-bot.js`）も同じPRで直す。
- 夜のほかのバランスの数字をかえるときは、かえる前とあとに自動プレイ（`tools/sim/autoplay.cjs`）を動かして数字でくらべる。夜の実験の村（21日め）は、5日ごとの季節（`SEASONDAYS`）では春の夜になる（季節の効き目を見ないときは、PATCH で `seaMul` などを1にする）。
- 見た目のたしかめは、ブラウザで家をおいて、大きくしてスクリーンショットを見る。家の4つの角は、かならず見る。
- テストで物を置いて `recount` すると、スポットの場面（`spotScene`。そのあいだ `onTap` はタップをうけない）がはじまることがある。そのあとでタップをたしかめるときは `spotSceneReset()` でおえてから。タップをひろう所（`sacredTapHit` など）をしぼったら、テストのタップする場所も、その所（御神木は根もと `storyTreeX`・`storyTreeY`）にする。指の速さで決まるミニゲームのしっぱいは、テストでは時刻つきで `sacredPlayDown`・`sacredPlayMove`・`sacredPlayUp` をじかによぶ。
- 長い1行・短い名前（`S`・`W`・`fixm` など）の今のコードは、まとめて書きなおさない（持ち主がきめた）。新しく足す表・関数・項目は、いみのわかる名前にし、点数や重みの数は名前つきの表に書く（`PLAYSC`・`FWALK` など）。
- 段差の土のだんは、上の面の絵（`~top`）のページも、だんの絵と同時に読みはじめる（だんの絵がとどくまで上の面を読まないと、ロードのさいごの1コマで、見えるマスぜんぶの上の面を作りなおして重くなった）。段差のマスごとに1まいにまとめてとっておくやり方は、メモリが約2倍・ひいた画面で色がかわるので、やめた。1コマの段差の重さは、ほとんどが描く所で、マスごとの計算（`icBlkKey`・`igTileVer` など）は1割ほど。
