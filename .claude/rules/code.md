# プログラムの決まり・重さ

`CLAUDE.md` の決まりのつづき（この話題の作業をするときに読む）。ぶつかったら `CLAUDE.md` が先。

## 見た目
- 絵と音は、JS の中に文字（base64）で入れない。ファイルにする：マップチップは、アトラス（`assets/chips/*.webp`、2048×2048）にまとめ、chips.js には場所だけ（`tools/chips.py`：`unpack` でほどいて JSON を直し、`pack` で作りなおす。pack は元の絵とドットまで同じかたしかめる）。プログラムの絵と音は `assets/g`、フォントは `assets/f`。ファイル名は中身から作る（かえたら名前もかわるので、古いファイルが使われない）。絵は、画質を落とさない WebP（ロスレス、透明な所の色も保つ `exact`）。
- `index.html` は、はじめにタイトルと同じ色の `#boot` を出し、タイトルのすぐあとで `#boot` をかくす（大きなスタイルの読みこみのあいだ、真っ白にしない）。開発用のメモのコメントは、ファイルのいちばん下。
- ブラウザでたしかめるときは、サーバーをとおして開く（file:// で開くと、絵がよそのものあつかいになり、toDataURL がつかえない）。

## 重さ
- キャンバスのタップの場所は、キャンバスの上の場所ではかる（`input.js` の `cX`・`cY`・`cvRect`）。文字を打ったあとなどにページがスクロールしたままだと、画面の場所とずれる。ページがずれたら、もどす（`scrollTo(0,0)`）。
- Android の「戻る」でゲームのページから出ないように、さわったときに履歴に印を1つ足す（`backTrap`）。Chrome は、さわらずに足した履歴を戻るでとばすので、さわるたびにたしかめる。
- iPhone は、キャンバスのメモリの上限が小さく、こえるとページが落ちる。作業用のキャンバスは、使いおわったらすぐ手ばなす（`width=height=0`）。作っておく絵は、量がわかる形にする。
- マップ全体の大きさのキャンバスは作らない。地面は区画の絵（`iso-ground.js` の `IG`・`igBuild`）。ステージを開くときに、地面の区画をぜんぶ作って、すてない（`stageJob`・`igJobs`）。マップを開くのは、絵（マップチップのアトラス・アイコン・そのほかの絵）がぜんぶ読みこめて（`assetsOK`）、マップ全体を作りおわってから（`stageReady`）。それまでは「マップを読みこみ中… 〇%」でマップをかくし、ゲームの時間も止める（`paused`）。%は、絵の読みこみが30%・マップを作るのが70%（`loadPct`）。マップを作る仕事は、1こずつの一覧にして、1コマに少しずつすすめる（`stageJob`・`stageStep`。一度に作ると画面が止まって%が出ない）。ゲームがはじまってから読みこみに入らないようにする。ゲーム中に作るのは、物を置いて変わった区画だけ（`igDirty`。作りなおすまでは前の絵）。ちぢめたとき（画面の細かさ1.2より下）は半分の細かさの区画と、流れが1ドットうごくまで使いまわす水面の絵（`q.ws`）、拡大が `IGTZ`（0.6）より小さいときは、高い段の上の面を半分の細かさの1マスの絵にしてとっておく（`igTileLod`・`IG.tc`、いちばんちぢめた草原で約12MB）。どれも `igHalfFree` で、しばらく使わなければ手ばなす。高い段の上の面（`igTile0`）は、区画の絵のそのマスにかかる所だけ写す（区画ぜんぶを切りとって描くと重い）。チップの1コマずつの絵は、はじめて描くときに切り出す（`chipImgs`。読みこむときに全ステージの全コマを切り出すと約86MBになった。切り出すときの手直しは、チップの名前できめる `chipKey`）。タイトルの絵は、タイトルをかくしているあいだ手ばなす（`index.html` の `free`）。風のステージでヌシ様が出るときは、ヌシ様の絵（`WNSPR`、2048×2358 で約19MB）も。ほかに、せいれいの動きの絵：色をかえたコマが500コマまで（約17MB、`SPMCAP`）と、使っている動きの絵（1つ約0.5〜4MB、60秒使わなければ手ばなす）。HD-2D の仕上げの作業用のキャンバスは、画面の1/6と1/12の大きさで約0.5MB（2コマに1回だけ作りなおす `HDEVERY`）。ふやす変更をしたら、はかって書きかえる。
- 区画ごとの絵（地面の区画など）を画面に拡大して描くときは、絵のまわりに、となりの中身を数ドット（のりしろ、`GPAD`・`IGP`）よけいに描いておき、切りとらずに、のりしろごと描いて、となりの区画とかさねる。iPhone の Safari は、拡大するとき、描く絵（切りとった所）のはしを透明とまぜるので、ぴったりならべると区画のさかいめにうすい線が出る（のりしろの内がわだけを切りとって描いても出る）。Chrome では出ないので、Chrome でたしかめるときは `drawImage` を、切りとった所のまわりを透明にして描くものにおきかえて見る。
- おわりの処理つきのカメラの動き（`camAnim.done`：鉱脈が目をさます・オオカゲの登場など）は、画面をさわっても止めない・`panTo` で上書きしない。止めると、おわりの処理がよばれず、`GIFT_ACTIVE` などがもどらなくて、ゲームが止まったままになる。ほかのカメラの動きに上書きされたときは、1コマの見はり（`CAMW`）が、おわりの処理だけをよぶ。演出（鉱脈が目をさます）のカメラの動きは、村を切りかえるときのかたづけ（`oreWakeReset`）で、自分の動きだけ消す（のこすと、新しい村でカメラが旧い場所へ動き、そのあいだ新しい演出がはじまらない）。
- セーブスロット（`slots.js`）はなくした。セーブはオートセーブだけ。
- `performance.now()` の時刻（`bowT` など）はセーブに残ると、読みこんだあと、いまより先の時刻になる。くらべるときは「いまより前か」もたしかめる。
- ヘッドレスのブラウザは写す（screenshot）のがおそく、そのあいだにエフェクトがおわる。エフェクトを写すときは、`fx` の `life` を setInterval で止めて写す。タイマーの時刻のテストは、ゲームの中で時刻をはかる（テストとの往復の待ちを入れない）。
- 重さをはかるときは、1コマごとに requestAnimationFrame で画面に出してからつぎを描く（続けて描くと、ブラウザがためた描く仕事をときどきまとめて片づけて、大きく止まって見える）。
- スマホでも動くようにする。毎コマ・毎秒の処理に、むだな計算や一覧づくりのくりかえしを足さない。
- 夜の明かりは、暗さを画面と同じ大きさの別の絵（`DMK`）にぬり、明かりの所の暗さを光の絵（半径ごとに1まい `lightSpr`）でけずって（destination-out）、かさねる。光の色をかぶせない（黄色いもやに見える）。明かりの一覧は `LITP`（`recount` で作る）。毎コマ、マスを1つずつ調べたり、ぼかしの絵を作ったりしない。
- 浅瀬は、砂の光（1まい）とマスごとの小石の絵（`fordStones`）を1回作っておき、ならべる。毎コマ描くのは、動くさざなみだけ。
- キャンバスのぼかしに `filter='blur()'` を使わない（重い・iPhone の古い Safari では効かない）。小さくしてなめらかに大きくもどす。
- ただし、重さを理由に複雑な仕組みを入れない。単純で、数字が見てわかる形を優先する。

## 火山のそうび
- テストのサーバーは、ほかの作業のサーバーとポートがかさならないようにする（`--directory` で自分のフォルダを出す）。かさなると、ちがうフォルダのゲームをたしかめてしまう。

## なかよし
- `pickFresh` に1つだけの一覧をわたすと、2回めから `undefined` をかえす（`letterMore` は1つなら、そのまま使う）。
- ほかのファイルと同じ名前の `function` を書くと、あとで読みこむほうが黙って上書きする（おくりものの `giftGive` が手紙の `giftGive` をこわした）。`npm run lint`（`tools/lint.cjs`：ESLint で js/ をつないで調べる。PRごとに GitHub でも動く）で見つかるので、変更のあとに動かす。わざと入れかえるとき（思い出帳の再生など）は `window.〇〇=` と書く。
- ゲームの js/ に、ほかのファイルの関数の、かわりの空の関数を置かない（同じ名前を2回作ることになる）。一部のファイルだけを vm で読むテストのかわりの関数は `tools/tests/vm-stubs.js`。
