# プログラムの決まり・重さ

`CLAUDE.md` の決まりのつづき（この話題の作業をするときに読む）。ぶつかったら `CLAUDE.md` が先。

## 絵と音のファイル・ブラウザ
- マップチップのアトラスは、使う物のページだけ読む（ぜんぶ読むと、ひろげて約360MBになり、iPhone で絵が作れず前の仮の絵が出た）。`tools/chips.py` の `pack` は、物の種類（`fam`：id の `:` の前、`iso:` などは2つめまで。屋根は色ごと）ごとにならべて、1024のページにつめる。アトラスをぜんぶ読む処理（ページの一覧をまわして `chipPage` をよぶ）を書かない。読みこみ中のページの物は、`drawChip` が何も描かない（`chipPend`。仮の絵を一瞬出さない）。テストで描いた色をはかるときは、`chaReady()` を待ってから。
- 絵と音は、JS の中に文字（base64）で入れない。ファイルにする：マップチップは、アトラス（`assets/chips/*.webp`）にまとめ、chips.js には場所だけ（`tools/chips.py`：`unpack` でほどいて JSON を直し、`pack` で作りなおす。pack は元の絵とドットまで同じかたしかめる）。プログラムの絵と音は `assets/g`、フォントは `assets/f`。ファイル名は中身から作る（かえたら名前もかわるので、古いファイルが使われない）。絵は、画質を落とさない WebP（ロスレス、透明な所の色も保つ `exact`）。
- `index.html` は、はじめにタイトルと同じ色の `#boot` を出し、タイトルのすぐあとで `#boot` をかくす（大きなスタイルの読みこみのあいだ、真っ白にしない）。開発用のメモのコメントは、ファイルのいちばん下。
- ブラウザでたしかめるときは、サーバーをとおして開く（file:// で開くと、絵がよそのものあつかいになり、toDataURL がつかえない）。

## 重さ
- キャンバスのタップの場所は、キャンバスの上の場所ではかる（`input.js`）。文字を打ったあとなどにページがスクロールしたままだと、画面の場所とずれる。ページがずれたら、もどす（`scrollTo(0,0)`）。
- Android の「戻る」でゲームのページから出ないように、さわったときに履歴に印を1つ足す。Chrome は、さわらずに足した履歴を戻るでとばすので、さわるたびにたしかめる。
- iPhone は、キャンバスのメモリの上限が小さく、こえるとページが落ちる。作業用のキャンバスは、使いおわったらすぐ手ばなす（`width=height=0`）。作っておく絵は、量がわかる形にする。
- マップ全体の大きさのキャンバスは作らない。地面は区画の絵（`iso-ground.js`）。地面の区画は、画面に見えている所と、そのまわり1区画だけ作っておき、見えなくなって300コマたって、まわり1区画より外になった区画は手ばなす（ぜんぶ作ってすてないと、草原で約100MBになった。いまは拡大0.7で約30MB）。マップを開くのは、絵（アイコン・そのほかの絵と、地面と水のチップ）が読みこめて、はじめの画面のまわりの区画を作り、はじめの画面を1回描いて（読みこみ中の画面のうしろ）、そこで読みはじめたアトラスのページがそろってから（`chaReady`）。それまでは「マップを読みこみ中… 〇%」でマップをかくし、ゲームの時間も止める。%は、絵の読みこみが30%・マップを作るのが70%。マップを作る仕事は、1こずつの一覧にして、1コマに少しずつすすめる（一度に作ると画面が止まって%が出ない）。ゲームがはじまってから、地面の絵などの読みこみに入らないようにする（アトラスのページだけは、はじめて出る物のときに読む）。ゲーム中に作るのは、物を置いて変わった区画と、画面を動かして近づいた区画（1コマ8msまで。見える区画を先に、時間があまったら、まわりの区画）。ちぢめたとき（画面の細かさ1.2より下）は半分の細かさの区画と、流れが1ドットうごくまで使いまわす水面の絵、拡大が0.6より小さいときは、高い段の上の面を半分の細かさの1マスの絵にしてとっておく（いちばんちぢめた草原で約12MB）。どれも、しばらく使わなければ手ばなす。高い段の上の面は、区画の絵のそのマスにかかる所だけ写す（区画ぜんぶを切りとって描くと重い）。土のだんの上の面（かたちで切った地面）は、マスごとに作っておき（`ICT`、区画がかわったら作りなおす）、毎コマは、その絵と、かたちを色でぬった絵（時間の色・明るさ）をかさねるだけ。とっておくのは、60コマのうちに描いたマスだけで、拡大0.6より小さいときはゲームの点と同じ細かさ（草原で、拡大0.7で約11MB・0.35で約15MB）。毎コマ、作業用のキャンバスで組みたてない（マスの数だけ組みたてて、草原でえがく時間の7わりになっていた）。チップの1コマずつの絵は、はじめて描くときに切り出す（読みこむときに全ステージの全コマを切り出すと約86MBになった）。タイトルの絵は、タイトルをかくしているあいだ手ばなす。風のステージでヌシ様が出るときは、ヌシ様の絵（2048×2358 で約19MB）も。ほかに、せいれいの動きの絵：色をかえたコマが500コマまで（約17MB）と、使っている動きの絵（1つ約0.5〜4MB、60秒使わなければ手ばなす）。HD-2D の仕上げの作業用のキャンバスは、画面の1/6と1/12の大きさで約0.5MB（2コマに1回だけ作りなおす）。ふやす変更をしたら、はかって書きかえる。
- 区画ごとの絵（地面の区画など）を画面に拡大して描くときは、絵のまわりに、となりの中身を数ドット（のりしろ）よけいに描いておき、切りとらずに、のりしろごと描いて、となりの区画とかさねる。iPhone の Safari は、拡大するとき、描く絵（切りとった所）のはしを透明とまぜるので、ぴったりならべると区画のさかいめにうすい線が出る（のりしろの内がわだけを切りとって描いても出る）。Chrome では出ないので、Chrome でたしかめるときは `drawImage` を、切りとった所のまわりを透明にして描くものにおきかえて見る。
- 作っておく絵（地面の区画など）に、チップ（`drawChip`・`drawFloor`）を描くときは、読みこみ中のアトラスのページの物があったか（`CHPN` がふえたか）を見て、ページがとどいたら作りなおす（`igPendDone`）。しないと、その区画だけ仮の絵のままのこり、となりとのさかいに、たての線が出た。
- おわりの処理つきのカメラの動き（`camAnim.done`：鉱脈が目をさます・オオカゲの登場など）は、画面をさわっても止めない・`panTo` で上書きしない。止めると、おわりの処理がよばれず、`GIFT_ACTIVE` などがもどらなくて、ゲームが止まったままになる。ほかのカメラの動きに上書きされたときは、1コマの見はりが、おわりの処理だけをよぶ。演出のカメラの動きは、村を切りかえるときのかたづけで、自分の動きだけ消す（のこすと、新しい村でカメラが旧い場所へ動き、そのあいだ新しい演出がはじまらない）。
- セーブスロット（`slots.js`）はなくした。セーブはオートセーブだけ。
- `performance.now()` の時刻（`bowT` など）はセーブに残ると、読みこんだあと、いまより先の時刻になる。くらべるときは「いまより前か」もたしかめる。
- ヘッドレスのブラウザは写す（screenshot）のがおそく、そのあいだにエフェクトがおわる。エフェクトを写すときは、`fx` の `life` を setInterval で止めて写す。タイマーの時刻のテストは、ゲームの中で時刻をはかる（テストとの往復の待ちを入れない）。
- 重さをはかるときは、1コマごとに requestAnimationFrame で画面に出してからつぎを描く（続けて描くと、ブラウザがためた描く仕事をときどきまとめて片づけて、大きく止まって見える）。
- スマホでも動くようにする。毎コマ・毎秒の処理に、むだな計算や一覧づくりのくりかえしを足さない。
- 夜の明かりは、暗さを画面と同じ大きさの別の絵にぬり、明かりの所の暗さを光の絵（半径ごとに1まい）でけずって（destination-out）、かさねる。光の色をかぶせない（黄色いもやに見える）。明かりの一覧は `LITP`（`recount` で作る）。毎コマ、マスを1つずつ調べたり、ぼかしの絵を作ったりしない。
- 浅瀬は、砂の光（1まい）とマスごとの小石の絵を1回作っておき、ならべる。毎コマ描くのは、動くさざなみだけ。
- キャンバスのぼかしに `filter='blur()'` を使わない（重い・iPhone の古い Safari では効かない）。小さくしてなめらかに大きくもどす。
- 描いてから `getImageData` で読むだけの作業用のキャンバスは `getContext('2d',{willReadFrequently:true})`。ドットごとのくりかえしの中では、`S.ground`・`GT.d` などを先に手もとの変数にとり、0以上の数の切りすては `|0`、まとめてうつせる所は行ごとに `set` でうつす（地面の区画で、作る時間が約2わりへった）。
- ただし、重さを理由に複雑な仕組みを入れない。単純で、数字が見てわかる形を優先する。

## テストのサーバー
- テストのサーバーは、ほかの作業のサーバーとポートがかさならないようにする（`--directory` で自分のフォルダを出す）。かさなると、ちがうフォルダのゲームをたしかめてしまう。

## 関数の名前
- `pickFresh` に1つだけの一覧をわたすと、2回めから `undefined` をかえす（1つなら、そのまま使う）。
- ほかのファイルと同じ名前の `function` を書くと、あとで読みこむほうが黙って上書きする（おくりものの `giftGive` が手紙の `giftGive` をこわした）。`npm run lint`（`tools/lint.cjs`：ESLint で js/ をつないで調べる。PRごとに GitHub でも動く）で見つかる。わざと入れかえるとき（思い出帳の再生など）は `window.〇〇=` と書く。
- ゲームの js/ に、ほかのファイルの関数の、かわりの空の関数を置かない（同じ名前を2回作ることになる）。一部のファイルだけを vm で読むテストのかわりの関数は `tools/tests/vm-stubs.js`。
- Python の行のおわりに `#` の注記を足すときは、その行に `;` のあとのつづきがないかたしかめる（つづきまで注記になって、処理が消える。窓のあかりのPRで、壁にかける物のかげが消えかけた）。

## ログ・テスト・見た目のたしかめ（もとは CLAUDE.md）
- ログ（`js/log.js`）：エラーは、いつも記録（`lgErr`：どこで・ファイル名:行・そのときの目標・画面・会話中か）。せいれいの行動（`startAct` の `lgStart`・`endAct` の `lgEnd`・通れない・止まった）・会話（`dialog`）・目標と待つわけ（`lgTick`）は、設定の「くわしいログ」が入りのときだけ（`LOGV`）。さいごの3000行をためて、1500行を localStorage（`hakoniwa-log`）にのこす。不具合をしらべるときは、持ち主に書き出したログをもらう。新しく止まる・やめるわけを足したら `lgR` も入れる。量の多い所では `if(LOGV)` で、切りのときは何も計算しない。たしかめは `tools/tests/log.cjs`。
- テスト・自動プレイ・夜の実験の道具と使い方は `tools/tests/README.md`。テストは、PRごとに `node tools/tests/run-all.cjs --changed`（サーバーも自分で立てる）。ぜんぶ動かすのは、持ち主がたのんだときだけ。しくみをかえたら、それをたしかめているテストと、自動プレイの進め方（`tools/sim/autoplay-bot.js`）も同じPRで直す。
- 夜のほかのバランスの数字をかえるときは、かえる前とあとに自動プレイ（`tools/sim/autoplay.cjs`）を動かして数字でくらべる。夜の実験の村は、7日ごとの季節では冬の夜になる（季節の効き目を見ないときは、PATCH で `seaMul` などを1にする）。
- 見た目のたしかめは、ブラウザで家をおいて、大きくしてスクリーンショットを見る。家の4つの角は、かならず見る。
- テストで物を置いて `recount` すると、スポットの場面（`spotScene`。そのあいだ `onTap` はタップをうけない）がはじまることがある。そのあとでタップをたしかめるときは `spotSceneReset()` でおえてから。
- タップをひろう所（`sacredTapHit` など）をしぼったら、テストのタップする場所も、その所（御神木は根もと `storyTreeX`・`storyTreeY`）にする。
- 指の速さで決まるミニゲームのしっぱいは、テストでは時刻つきで `sacredPlayDown`・`sacredPlayMove`・`sacredPlayUp` をじかによぶ。
