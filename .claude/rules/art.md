# 絵・マップチップ・エフェクト

`CLAUDE.md` の決まりのつづき。ぶつかったら `CLAUDE.md` が先。

## 絵・エフェクト・マップチップのきほん
- 横向きの絵しかない物を上下へまっすぐ動かさない（すべって見える）。上下へ動く物には正面・うしろの絵も作る。
- 作業は、その物のほうを向く（北の物にはうしろ向き）。
- 壁の正面の帯・巾木・模様は、家の角やはしまで、すきまなくつなげる。
- 夜の明かりは、重なって明るくなりすぎないように。手前の背の高い物の上に窓の光をかぶせない。窓の光は、iso の窓の絵（`iso:win`）がとどいてから出す（いまは出さない）。
- ふきだしの絵（96×96）は、もらった絵（`tools/art/bubble/icons.png`）を `build.py` で BOX でちぢめて `assets/g` の1まいに（ドット絵にしない）。ゲームでは `pxBub` がかえす中のまん中に、なめらかにちぢめて描く（中では1.5倍、わくの内がわまで。せかいの大きさだと、はみ出す）。読みこむまで・表にない物はコードの絵。絵文字は `r.bubble` のキーとしてだけ使い、絵文字のフォントで描かない。表にない字は「？」の絵。新しい絵文字は、`BUBART` に絵、`BUBI` に字を足す。
- エフェクト（コマならび）は `tools/` のスクリプトでドット絵を作り `assets/g` に書き出す（例 `tools/fx-trap.py`）。スクリプトはのこす。
- エフェクトを作る・直すときは `.claude/skills/pixelfx/SKILL.md` も読み、`tools/pixelfx`（MIT）で、にた効果を書き出してお手本にする。ゲームの中で pixelfx のコードを動かさない。
- 自然・生き物・動き・天気・光をそれらしくするときは、`tools/frostwind`（MIT、`NOTICE.md`）の `PIXEL-ART.md`・`PROJECTION.md`・`src/` の考え方と数字をかりて、はこにわの作りで書きなおす。Frostwind のコードを動かさない。中の `CLAUDE.md`・`.claude/` は、はこにわの決まりではない。
- せいれいの攻撃のエフェクトは `tools/fx-attack-pfx.py`。守り神のわざ（まもりの光・こもれびのまもり・葉のかべ）は `tools/fx-guard-pfx.py`。どちらも夜の暗さ・コワイノより上に描く（下だと夜は見えない）。まもりの光の音は持ち主の音（`tools/sound/glight_tail.py`、もと `tools/sound/src/glight.mp3`）を、光が地面に当たるコマで鳴らす（画面のゆれ・光も、そのとき）。
- ドットでない物は新しく作らない（絵・UI・ミニゲーム・コードの絵も）。ただし、マップぜんたいの HD-2D の仕上げ（`js/hd2d.js`）は、ドットでなくてよい（持ち主がきめた）：
  - 明るい所のにじみ・時間の光の色・四すみを少し暗く・天気の光・空気の遠近。上下のぼかし（ピントの帯）はなくした（持ち主がきめた）。設定の「HD-2D」「にじみ」で入り・切り（はじめは入り）。ふきだし・文字・UI にはかけない（矢の数・ふきだしより前）。見せ場（なかまが来る・オオカゲの登場・御神木が育つ）はにじみを強く。fps などで自動で見た目をかえない（持ち主がきめた）。
  - かげは時間で向きと長さをかえる（朝は西・夕方は東へ、朝夕は長く。だ円のかげと落ち影は根もとからかたむけてのばす。持ち主がきめた。木の絵の光は左上のまま）。
- 家具・建物の絵（`chips.js`）は、もらった透過PNGの透過と色をそのまま小さくする（うすさで切りぬかない。ふちがガタガタになる）。動く絵は全コマを元の絵のそのコマから。
- チップの色は1つの物ごとに256色まで（うすさは数えない）。1つの物は、id の `:` と `#` の前が同じ物（`story:`・`crop:`・`tex:` は1つずつ。`iso:<id>:…`・`iso:win:<id>:…` は id ごと）。`tools/chips.py` の `cap_colors` が自動でへらす。
- もらった絵の部品に部品ごとの輪郭・明るさのちがいがあると、つなぎ目に線が出る：つなぐ辺は外の輪郭にせず、となりの列でうめ、明るさをならす（`tools/art/tlb/tlb_art.py`）。
- くりかえす絵（床・壁の正面・塀・柵・道）は、もらった絵のままだと、ほとんどつながらない：
  - 「1まいのタイル」ではなく、「規則正しいもようで、ふちも枠もない、大きな続きの面（床）・長い続きの帯（壁・塀・柵）」をたのむ。板・レンガ・石は同じ大きさ・同じ間かくでならべる、と書く。
  - もらったら、くりかえしの間かく（自己相関）を見つけて1つぶん切りとる。2×2（帯は横に3つ）ならべて、つなぎ目が見えないかかならずたしかめる。つながらない絵は使わず、理由を伝える。
  - 切るのは、丸太・板・石などの、もののさかい目で（途中で切ると半分の丸太が出る）。よけいに切りとらない。
- 絵のプロンプトに「ざらざらしたノイズを入れない」も書く（clean flat colors with soft shading; no noise, no grain, no speckles, no dithering, no gritty texture）。
- 塀・柵・壁は横もたても同じ作り：柱は角とはしだけ、あいだはその材でつなぐ。たての絵もたのむ絵にふくめる。見おろしなので、上の面（てっぺん）も見えるように描く。
- ドアの上の断面は、となりの壁の断面と同じ色（よこ置きは左の壁、なければ右。たて置きは上、なければ下。`<壁>.door:<mask>`・`<壁>.door#v0〜3` など）。
- 絵の大きさをかえるときは、ゲームの中で拡大・縮小しない（`c.scale` などをチップにかけない）。チップをその大きさで元の絵から作りなおす（ベッド・カーテン・窓も）。たのまれた大きさは w・h・ax・ay の数字で書く。
- 動く物（ドア・かまどの火など）は、動く部分だけコマごとに差しかえ、動かない所は全コマ1コマめとまったく同じにする（コマごとに本体がちがうと「うねうね」する）。作ったら、コマをかさねてちがいをたしかめる。もらった動く絵も、かさねてたしかめる。
- ノブなどの小さな部品を、色で見分けた所だけで切り出さない（形がくずれる）。大きくして元の絵と同じ形か見る。
- お手本（組み合わせた絵）とレイヤーの部品をもらったら、レイヤーをお手本にかさねて、部品ごとの大きさ・場所をはかる（部品ごとに大きさがちがうことがある）。ゲームはお手本と同じ大きさにし、できたらならべてくらべる。
- なめらかな絵をドット絵にするときの輪郭は2ドット：外がわは少し暗い色、内がわはまわりになじむ色（例 `tools/art/nature/nature_art.py`）。丸い物は、ちぢめてから少しぼかして切り、とがった1ドット・角を出さない。
- もらった絵の輪郭のむら・ぶつぶつは、あとで輪郭をぬりなおさない（はばが合わなくなる）。ちぢめるとき `tools/art/pixdown.py` を使い、のこった点は12倍で見て手でなおす（`FIX`。例 `tools/art/set10/set10_pix.py`）。
- もらった絵を小さくするときは BOX（`LANCZOS` などは、はしに明るい線が出て、つなぐとすきまに見える）。
- 「トリミングしてそのまま」は、切りとるだけで、細かさ（1マス64ドット）も大きさもかえない。
- 前の見え方の部品の描き方（`wallFront`・柵・塀のつなぎ方など）をかえたら、マップチップ工房の見本（工房の `index.html` の `comboDraw`・`openDraw`）も同じに直す。
- スキル：もらった絵をチップにするときは `chip-art`、ドット絵を描く・直す・仕上げるときは `pixel-craft`、新しく作る・評価する・「きれいにして」と言われたときは `pixel-manual`（どれも `.claude/skills/`）。いまあるチップを「ドット絵スキルで直して」「ルールに合わせて修正して」と言われたら `pixel-redraw` の順番どおり（`tools/art/chipcheck.py` → `tools/art/pixdraw.py` → めやすがぜんぶ通ってからチップへ → `tools/art/chipview.cjs`。お手本は食卓 `tools/art/table/table_art.py`）。描きなおすのは、たのまれたチップだけ。
- チップを作りなおしたら、`chips.js` の `CHIPA` が指す `assets/chips/*.webp` が、ぜんぶコミットに入っているか（`git ls-tree`）たしかめる（わすれると多くのチップが出ない）。
- マップチップ工房（https://claude.ai/artifact/TSGpjyVzS5fJvYkatcNaKv）：
  - チップの絵をかえたPRでは工房も新しくする。工房は `index.json` と `g/<ジャンル>.json` だけ読む。Artifact の read で `index.json` と、かわったチップの `g/*.json` をおとし、`python3 tools/chips.py kobo <フォルダ> [id...]`（id がなければ、さいごの replace の物）で、かわった物だけ書きかえて、出たファイルだけ公開しなおす（ぜんぶの unpack はしない。とても時間がかかる）。
  - 名前（`index.json` の `names`）は `BL` の名前。新しい物を足したら `names` にも足す（ないと id のまま、さがせない）。
  - 「さしかえ」の `replace.json` は `python3 tools/chips.py replace replace.json` で入れる（WebP は method 2。method 6 は1ページ25秒で小さくもならない）。大きさがかわると w・h もかわり、ax・ay はそのまま。工房で調整した物（`meta`）は ax・ay をかえ、大きさは元の絵から BOX で作りなおす。
  - 「ゲームの中で」の見本（`gv/<id>.webp`）は、ゲームで置いて写した絵（`tools/gameview_boot.cjs` で写し、`tools/gameview_grid.py` でマス目とわく。倍率と大きさは `info.json`）。つながる物は L 字、ドア・窓は壁・柵といっしょに。飼う生き物は `ani:<k>`（ファイル名 `ani-<k>`）。チップの絵・大きさ・置き方をかえたら、写しなおして公開しなおす。一覧を `chips.js` にそろえるときは `python3 tools/chips.py kobo-sync <フォルダ> [names.json]`（`g/*.json` をぜんぶおとしておく）。

## 壁・柵の部品の絵（前の見え方の絵。アイコン・工房の見本）
- 地図の壁・ドア・窓・塀・柵・生垣は、ひし形のつなぎ方（`js/iso-conn.js`）。この節は、前の見え方の部品の絵（アイコンと工房の見本、`drawConn`）の決まり。
- 部品は `<id>:H0/HL/HR/HLR`（横。H0は柱だけ）、`<id>:VU/VD/VUD`（たて。断面だけ）、`<id>:m5〜m15`（角・つなぎ目）。つながりは `connMask`（左1・右2・上4・下8）。
- 1マスの中：断面は y−9〜y、正面の板は y〜y+28、巾木は y+28〜y+32、その下4ドットがかげ（うすさ 96・64・38・16。下かななめ下が家の中の壁は 64・42・24・10 の `~in`）。柱とたての壁は x+5〜x+27。
- 正面の帯は `wallBand` で世界の座標でならべる（継ぎ目を出さない）。家の中から見える正面（下か、ななめ下が家の中）だけ中がわの見た目。角のマスは柱の外がわにも帯をつけて、はしまでつなげる。
- たての壁を手がきのマスごとの絵で描かない（さかいに線が出る）。部品の絵（`VUD` など）を使う。
- 正面は `wallFront` でかさねる：木の壁・丸太・しっくい・レンガは `<id>:ext`（もらった絵、世界の座標）と柱 `<id>:post`。よぞらの壁は、外は `yozorawall:ext`、柱は `yozorawall:post`、中から見える正面は `yozorawall:band` とダークチェリーの巾木（断面と形は `yozorawall:H0` など、木の壁の色をおきかえた部品）。
- 竹の壁（`bamboowall`、火山だけ `STAGEONLY`。火山の家の壁はこれ、木の壁は草原だけ）：もらった絵（どれも64でくりかえす）をつながりごとに組む（`tools/art/bamboowall/bamboowall_art.py`）。ドア・窓などの壁ごとの絵は、しっくいの壁の絵の木の所を竹の色に。`<壁>` だけの名前のチップは作らない（あると窓の壁で窓を描く所へ進まない）。
- 柵（`fence`、オーク）・丸太の塀（`logfence`）・竹の柵（`bamboofence`）・御簾垣（`misugaki`）・石の塀（`wall`）は、3Dで組んで写した絵（`tools/art/fence3d/fence3d.py`、かげは家具と同じ5色）。つなぎ方16とおり（`<id>:m0〜m15`）を、そのマスの中の物だけで組む（石の塀は、となりの石の塀のドアへのばす）。
  - 見え方は家具の38度ではなく、ゲームのマスと同じ（`oblique3d.game`）。そうしないと、たての柵がつながらない。
  - よこのつなぎ目は、横木・くい・石をマスの外までのばして組み、マスのはばで切る（もようは1マスでくりかえす）。たては、横木を上のマスへのばし、のばした所のまわりの線だけ消す。石の塀のたてのかさ石は、上のはしを1ドットあけて、つなぎ目の線を出す。
  - 柱はマスのまん中、たての柵は柱のまん中にそろえる。マスのさかいに石のつなぎ目を置かない（切ったはしの線が、かたほうにだけ出る）。
- 柵・塀のドアと門（`gate`・`logdoor`・`loggate`・`sdoor`・`stonegate`・`misugaki.gate`）も3Dから（`tools/art/fence3d/doors3d.py`）。開いたコマ（`#h1〜3`・`#v1〜3`）は、とびらを軸でじっさいにまわして写す（よこ置きは手前へ、たて置きは東へ）。よこ置きの柱はマスのさかいにまたがり、右どなりの柵・塀は柱にかかる所を描かない。たて置きの柱と御簾垣の戸の柱はマスの中（下のマスの柵が柱の上に描かれないように）。丸太の塀は、丸太の塀・そのドア・大門とだけつながる。
- 生垣（`hedge:0〜15`、g64）は、もらった絵（`tools/art/hedge/image.png`）から `tools/art/hedge/hedge_art.py` で。よこの帯とたての柱をつなぎ方ごとにかさね、まん中は1マス（64）でつながる形にして世界の座標でならべる。
- ダークチェリー（よぞらのベッドの木の色）：#522d1d・明るい所 #86552f・かげ #321f14。よぞらの家具・床・壁・ドア・窓はこの色。

## 絵の細かさ
- アイコン（`iconURL`）は2倍の細かさで描いて、144×144になめらかに入れる。ドットをとばす縮小・拡大（`imageSmoothingEnabled=false` で半ぱな倍率）は、がたがたになる。
- 地面・床・平らな物は、地面の下絵（1マス32ドット）にやきつける。g:64 の絵をそこに描くと荒く見えるので、くっきり見せたい物（ラグなど）は毎コマ画面の細かさで描く。
- 床のもようは1ドットの線で（下絵と壁ぎわの絵がそろう）。
- 床は、はしまで、すきま・線・段なしでつなげる：壁・ドアの下にのばす床は下絵に描く（毎コマの絵で重ねない）。上はしの「壁の下のかげ」も、のばした床につなげる（角で段にしない）。床や壁の見た目をかえたら、家の4つの角を6倍以上で見る。
- 壁の帯・巾木をマスごとにコードで描くときは、となりに0.5重ねる（ぴったりだと1.3倍・1.7倍などで、すきまの線が出る）。
- 見た目は6倍以上に加えて、ふだんの拡大率（1.3〜2.3倍）でも見る。

## 自然の物
- 岩（`rock`）の絵は、はば1.5マスくらい（持ち主のたのみ）。
- 自然物のチップ（木・森の木・りんごの木・枯れ木・ベリーの茂み・岩・大岩・きのこ・火山の木2つ）は、トリポのモデル（`tools/art/nature3d/nature_prep.py`）から3Dで写す（`furn3d/items/nat_*.py`、共通 `natcommon.py`）。お手本は前のチップの絵。
  - 葉は、葉の玉を小さな葉の部品でおおう。幹は CC0 の木の皮（Bark001）を、のびる向きにすじが通るようにはる（まっすぐは `axis='z'`、枝わかれは `'screen'`。そのままはるとノイズになる）。背の高い木は見おろし4度、太さ1.3倍。
  - 枯れ木・草原の木（`tree`・`ntree`・`fruit`）・火山の木（`tree~v`・`deadtree~v`）・ベリーの茂み・御神木（`story:*`）のかげ（持ち主がきめた）：左上の光（`LIGHT`）。色は5つ（かげ2・もと・ハイライト2）と輪郭。色のさかいめだけ、はばの小さい市松のあみかけ（`tone5` の `dw` 0.03、`rimhi` 0。家具と同じ）。木は幹と葉を色でわけて2回かける。葉はつぶつぶをのこし、かげは青みのある緑、葉の下の幹は暗く。御神木の傷・切り口・光のつぶの色はかえない。
  - 枯れ木（草原）は、同じ3Dを0・45・180度まわした3まい（`deadtree`・`#1`・`#2`）をマスごとにえらび、半分は左右反対。足もとにだ円のかげ。
  - りんごの木の実ったときは、3Dの絵を作らず、ふつうの木の絵にりんごのアイコンをのせる（持ち主がきめた）。
  - 岩・大岩は、お手本と同じ大きさ・形・ならびに、角ばった形で組む。
  - 草原の木（`tree`・`ntree`・`fruit`・`tree~aki`）は、クォータービューでも48度にせず、正面の見おろし4度のまま、まわさず・葉を上げずに写す（`iso3d.py` の `FRONT`。モデルは正面から見る形で、まるい物はクォータービューにしなくてよい。葉を上げると、葉が上にたまりすぎた。持ち主がきめた）。大きさ・置き方（`iso:1`）と落ち影はクォータービュー。
  - ほかの葉のある木は、クォータービュー（見おろし48度）では、葉の玉が幹をかくし、葉のはしが地面にとどいて、うまって見えるので、クォータービューの絵だけ、葉を上げて幹の根もとを見せる（`natcommon.lift`、`iso3d.py` が `natcommon.ISO` を入れる）。上げる高さは、葉のいちばん下が根もとより上に出るまで（写した絵の葉と幹の色で数える）。
- 秋は、草原の木を紅葉の絵（`tree~aki0` 赤・`tree~aki1` 黄、マスごと。`nat_tree_aki.py`、落ち影も）。草原の木の絵をかえたら、こちらも作りなおす。
- 自然の物の光は太陽1つ（`natcommon.SUN`：高さ30度・正面から左へ8度。持ち主がきめた）。モデルをまわした絵でも光はまわさない。
- 落ち影（`tools/art/furn3d/castshadow.py`、`<絵>:sh`・反対は `:shf`）：根もとの高さの平面に太陽から影を落とし、同じカメラで写す（けずる・切る・ずらして合わせない）。ぼかして2色、さかいめだけ市松のあみかけ。ゲームは、その行の段差のあと・物より先に描く。自然の物の絵をかえたら影も作りなおす。
- 生き物の足もとのかげは、ドットのだ円（時間で向きと長さ）。はばは、そのコマの絵の下から30%の行のはし。小さな生き物は、高くとぶほど小さく・うすく。
- 3Dのモデルに、ポーズの前の場所で色をつけるときは `Part.paint`（`blueprint.build`）。`decal` だと、かたむけたコマで柄がずれる。
- 生き物のモデル（`tools/art/animals/animal_prep.py`）：目は左右同じ大きさのたいらな玉にかえ、2つとも `EYE` にする（部品の番号で目をほっぺにすると片目がピンクになる）。

## 時間の色
- 昼と夜の色は `js/daycolor.js` の `DAYC` 1か所（時刻ごとの、暗さ・地面・水・雲の海・屋根・窓のあかり・時間の光）。色をかえるときは、この表の数字だけを書きかえ、ほかに夜の色を書かない。
- 地面の層は物より先に画面ぜんたいにかけ算、物・がけの正面は夜の暗さだけ。水は水面を流すとき、雲の海は `q.k` の所だけ。屋根は形ぜんぶを1つにして1回だけかける（2回かけない）。高い段の上の面は `dcTop`。あかりは暗さをけずる（2つめの層）。
- 物ごと（チップごと）の色わけはしない（持ち主がきめた。スマホで重い）。

## 日ざしと月明かり
- 光の帯（ゴッドレイ、`light-rays.js`）：晴れた朝・夕方と、月のある夜（満月は強く・新月はなし）だけ。昼は出さない（持ち主がきめた）。ドットの絵を1回作ってならべる。

## 畑と作物の絵
- 花・木・作物・木の実が育つのは朝6時。植えた花・木の芽は、つぎの朝6時まで（`S.bud` と `isBud` は `callDay`。`dayNo` は夜中の0時でかわるので使わない）。
- 畑の土（`farm:0〜15`・ぬれた土 `farmw:0〜15`）は上下左右の16とおり。「大きな畑3×3・よこ1×3・たて3×1・1マス」をたのめば、そろう。
- 1マスに畝1本、畝のまん中がマスのまん中。土の絵に草・芽を入れない（同じ場所に草がならぶ）。たのむときもそう書く。
- 花・木の芽は `bud`、ハスは土のない `bud~w`。芽・土のもりあがり・作物は、土の下はしを畝のてっぺんにそろえる（ぬれた畑は `<key>w`）。芽は育ちはじめたら描かない。
- クォータービューの土のもりあがり・芽・作物（`farm.mound`・`farm.sprout`・`crop:<作物><だん>`、ぬれた畑は `w`）は、3Dから写した `iso:1` の絵（`furn3d/items/crop.py`、`iso3d.py crop`）。もりあがりはマスのまん中の丘、作物はトリポのモデル（`tools/art/crop3d/crop_prep.py` で色わけ）を、その上に根もとを少しうめて立てる。畑の土（`farm:<m>`）は地面にねかせたまま。
- つやつやの作物：まいた印があって、朝に育ちきる前にかわいた印がない畑は、収穫+1・とれごろに光のつぶ。収穫の数を出す所・見る所にも `tsuyaOf` を入れる。たしかめは `tools/tests/tsuya.cjs`。

## クォータービューの地面（`js/iso-ground.js`）
- 高さ（持ち主がきめた）：1だんはマスの1辺の0.8（`IQL` 36・写す道具の `ISOH`）。光の向きは、ほんとうのカメラの角度（`ISOLIGHT`）。家の壁は2だん（`IQWALLH`・`iso_conn.py` の `WH`、まん中の行をくりかえす `frow`）、家のドアは1.4だん（`iso_door.py` の `LZ`）。ベッド・木箱・本棚・キャビネット・かざり棚・まき棚・流し台・調理台・作業台は、はば1マスぴったり。ベッドのほかは、うしろの面をマスのうしろのふちにつける（作業台の上 `wbwork` も合わせる）。
- 地面は画面の向きの四角の区画（1ドット＝ゲームの1点、ひし形は64×48）。
- 草地とあれ地・水と岸のさかいは、デュアルグリッドのオートタイル（角ごとに16とおり）。1ドットずつぼかす・ノイズでゆらす・色むらをかさねる作り方は、もうしない。
- ひし形の絵がとどくまでは、上から見た絵をドットのまん中の点で写す（まわして描かない）。地面の絵は、まうえから見たつながる面でたのむ（`tools/art/iso/ground-prompt.md`）。
- つながる物と屋根（`js/iso-conn.js`）：壁・ドア・窓・石の塀・柵・生垣は「まん中の柱＋となりへの腕」（左1・右2・上4・下8）。チップ `iso:<id>:<m>`（ドアは `h`・`v` と `#1〜3`、ひくい壁は `~low`、壁にかける物は `iso:win:<id>:<h|v>`。ax・ay はマスのまん中の地面の点）。
- 屋根は、屋根のタイルセット（`tools/art/iso/iso_roof.py`。クロスゲーブル。3Dで組んで、マスごとの完成したチップに写す。屋根の色ごと）。ゲームはチップをえらんで列ごとに奥から置くだけ（コードで屋根を描かない・ドットごとにかさねたり色をかけたりしない。持ち主がきめた）。部品の決め方は、道具の `cells`・`pick` とゲームの `iqRoofCells`・`iqRPick` が同じ（かえるときは両方）。屋根をはずした家は、手前の南・東の壁をひくい壁に。高い壁がひくい壁にかわる所（東・南のはし）は、切り口の断面の板 `iso:<壁>:cut-e`・`cut-s`（`iso_conn.py --cut`、色はその壁の絵の色から）をかさねる（ないと、壁の中が空いて見える）。屋根の雪は雪だけのチップ（`iso:roofsn:<部品>-a`・`-f`）をかさねる。のき・けらばの下のかげは、壁・妻の面の上の板として3Dで入れる（屋根をはずすとかげも出ない）。のきの出にかくれる深さは坂の向きでちがう（カメラへ下りるけらばは約0.23だん深い）ので、ならべた絵で帯のはばを数えてそろえる。かげの板は屋根の部品といっしょに写して、屋根にかくれない所だけをのこす（谷で、ほかのうでの屋根の上にのった）。
- 土のブロックのだんは、角の形ごとのタイルセット（`tools/art/iso/iso_block.py`、`iso:blk-<だん>:<nsew>[-<ななめ>]`）。外に出ている角だけまるい箱（rounded box）で、横の面はがけの絵の暗い所ほどへこませる。ゲーム（`icBlock`）は下のだんからチップを置き、上の面は、その所の地面を `~top` のかたちで切って描く（上の面を1マスずつ焼くと、地面のもようがマスごとに切れて線が出た）。
  - 1マスの中だけの箱で写し、奥から順にかさねる（となりにつづく向きは、まるめない平らなふたの面。手前のマスがかくす）。`iso_conn.py` のように、となりへのばしてマスで切ると、へこませた面がとなりのマスに入り、つなぎ目にすきまが出た。内がわの角（ななめのマスがうまっている所）は、角の手前でへこみをなくす（うしろのマスの角がのぞいて、明るい線に見えた）。
  - まわりに輪郭線を引かない（だん・マスのつなぎ目に線が出る）。下のだんの岩の絵は、上下がつながる形（`midtex`）。
- 家具・建物・自然の物（`js/iso-obj.js`）：3Dの絵は、いまのチップと同じ名前で入れかえ `iso:1` をつける（反転しないので、向きは4つとも写す。ax・ay は置いたマスのまん中の地面の点）。
- `iso:1` の絵は、描くときに画面の向きをかけなおすので、その前の `translate`・`rotate`・`scale` はきかない。`isoLocal({rot,sx,sy},…)` で足もとのまわりにかける。写すのは `python3 tools/art/iso/iso3d.py <出力> [設計図...] [--chips]`（`--from` で写しなおさずにチップへ）。御神木は切り株の n×n のまん中から。大きさは `BL` の `sz`。絵より置く所が大きい物（作業台など）は、向きごとのずれをつける。
- 向き（`js/iso-face.js`）：せかいの向きはいままでのまま。`isoFace` で、前ななめ（南＝左下）・うしろななめ（北＝右上）と左右の反転にする（東は前ななめの反転・西はうしろななめの反転。よこの絵は使わない）。向きを見る描き方を足したら `isoFace`・`isoVw` を通す。写すのは、せいれい `build.py --iso`（`js/spirit-motions-iso.js`。洞窟はいままでの絵）・飼う生き物 `ANIISO=1 ani_build.py`・小さな生き物 `CRITISO=1 crit_build.py`・コワイノ `KWISO=1 kowaino_paint.py --sheets`。せいれいの目・ほっぺは、左右べつにコマごとの場所を出し（`rig.py`）、ゲームはそのとおりにかさねる。
- 夜の窓のあかり（`iqWinLit`、`iso:win:window:lit:<h|v>`）：灯りのある家の、外を向いた窓（よこは南の面・たては東の面）だけを暗さの上にかさねる（面のかげはつけない）。手前の物にかさなる窓は描かない（`iqWinHid`）。
- 家のドアのわく（柱・かもい）は、となりの壁の絵（`iso_door.py` の `FRAMEW`・`FRAMEX`）。ほかの壁にも置くドアは、壁ごとの絵 `iso:<壁>.<ドア>:…` を作る（ゲームの `iqGateId` が、となりの壁の絵をさがす。ないと木の壁のわくが出て、壁の上のふちが切れる）。
- ドア・門・壁にかける物（`tools/art/iso/iso_door.py`、`iso:win:wreath:d` など）：とびらは、おく（北・西）へひらく（手前へ出すと手前の物にかくれる）。ひらいたとびらは、マスの外へ出ても切らない。柵のドアの柱の所だけ、となりの柵の腕を描きこむ（ないと横木が切れて、すきまが出る）。マスの東・南のはしちょうどの面は、そのマスの物。はみ出す物もマスの中におさめる。
- エフェクト・夜・霧（`js/iso-fx.js`）：地面にはりつく物（水たまり・わく・かげ・霧）は地面の描き方のまま、段は `isoGroundLv`（y から `liftOf` をひかない）。立つ物・うかぶ物は足もとで立てる。足もとは、うまれたときの地面の点：地面より上に出す物を足すときは地面の y を書く（`gy`・`fxSpr` の6つめ・`addFloatG`・矢の `gy1`・`gy2`）。字・数・札は `isoUITf` で、のばさずに。

## 草地のふち
- 種類のちがう道どうしがとなり合うときは、両方のふちに草のふちを出す。
- 草地とあれ地のさかいは、あつ森より（持ち主がきめた）：まるくやわらかい形のデュアルグリッド。水・高さのちがうマスは見ない。水のマスから草をはみ出させない・水の下に草をしかない。
- 草地とあれ地のさかいのふちは、あぜ道・砂利道の草のふちと同じ（持ち主がきめた）：まるい形はそのままで、こい緑のふち・あれ地がわのかげはつけず、ふくらみととがった草の葉を、あれ地のほうへはみ出させる（`igGrassTiles`）。

## 水面
- 水のふちに、となりの地面を鏡うつしにしない。水の下のすきまは、となりの陸の地面を、そのがわの半マスにしきつめる。あぜ道・砂利道は水につなげない（ふつうの道のはしと同じに丸く切り、草のふちも出す。水の下に道のもようを入れない）。
- 水面は、水のテクスチャを毎コマゆっくりスクロール（`igShimmer`）。白いキラキラや、もようをゆらして重ねる方法は使わない。
- 池・川のふちはデュアルグリッドで丸める。水面は岸より一段ひくく見せる（すぐ上が陸なら、岸の断面とかげ）。火山の水と雲の海はべつ。
- 水のテクスチャ（`tex:water`）は、もとの絵 `tools/art/ground/src/water.png` から `water_tex.py` で（明るいもようだけ中央値の色へ近づける。白とびしない）。チップをじかに直さない。
- 雨の輪・水たまり・こおった水たまり（`iso:rip#0〜3`・`iso:pud:<大きさ>#<形>`・`iso:pudi:…`）は、3Dで地面の上の平らな形を写した絵（`furn3d/items/fx_water.py`、`iso3d.py fx_water`）。ゲームは `feelIso` で、地面の点に画面の向きのまま置く（地面の描き方で絵をかたむけない。かたむくと、ひし形にそってななめになる）。うすさはゲームでかける（すける `clear` は、下に何もないと写らない）。
- ハスは、葉のまん中をマスのまん中に置き、池のはしのマスでは水のほうへずらす（`lotusFoot`。デュアルグリッドで水の形が丸くけずれる）。

## 道・床の絵
- 草原のあれ地（`tex:dry`）・草地（`tex:grass`）は、もらった絵（`tools/art/ground/src`）を `ground_tex.py` で224×224の、つながる絵に。あれ地は、区画の列・行ごとに、ばらばらに反転してしきつめる（90度まわすとひびが切れるので、まわさない）。
- あぜ道・砂利道（`path#0〜3`・`gravel#0〜3`）は、まわりの帯を4しゅるい同じにして、まん中だけかえる（どうならべてもつながる）。ふちを少しまるく切る。
- 石畳・レンガ道（`stone#0〜3`・`brick#0〜3`）は2×2マスでつながる1まい。石の床（`stonefloor#0〜15`）は4×4マス。石・レンガは目地で切り、ずれた行のはしは同じ石の続きを使う。石畳・レンガ道は1マスぴったり（へりはマスのふちまで）。
- 道のへり（`stone:0〜14`・`brick:0〜14`、入隅 `:c0〜3`）：はば5ドットの帯（上下の帯を90度まわして左右にも使う）、道がわにうすいかげ2ドット。入隅は2つの帯をL字につなぐ9×9（外がわの2×2はあける）。石畳のへりは、みかげ石（`tex:granite`）の色ともよう。レンガ道のへりのレンガは16ドット。
- じゅうたんのふち（`carpet:U/D/L/R`）は、マスのいちばん外がわに、はしからはしまで（32ドット）。となりもじゅうたんなら描かない。
- チップの未使用の判定は、動的な名前（向き・接続・成長・開閉・表情）とフリーモード・古いセーブの読みかえも見る。読みこみのたしかめにだけのこる古い部品を消すときは、たしかめの方も、いまのチップに合わせる。消した一覧と理由は `tools/art/unused-chips.json`。

## 歩きながらの動きの絵
- 歩いているあいだは、よろこぶ・拍手・会話中でも、歩く向き・歩く動きのまま（`walking` のときは `clap`・`wv`・`facePlayer` にしない。場面の姿勢ものこさない）。

## コードで描く絵
- コードで描く絵（そうびのアイコン・鉱脈など）はドット絵：16×16 などのマス目を整数の fillRect で。まるい線・なめらかな線・グラデーションは使わない。のばすときは imageSmoothingEnabled=false。色は明るくやわらかく、輪郭は中より少し暗い色（黒にしない）。

## ドットのアイコン
- 新しいドットのアイコンは、形（マスク）から2ドットのふちを作る（形をけずって引く）。
- 32×32のアイコン（そうび・料理・食べ物・宝・鉱石など）は `tools/art/icons32`（`game.py` で3倍の96×96を `ICONS` へ）。輪郭はまわり1ドット（となりの色を少し暗く）、色は1こ16色まで（`cap_colors` は広い所をくずすので使わない）。細長い物（矢）は45度ななめにしてからちぢめる。くずれる物は `hand.py` で手で描く。`ICONS` に絵があれば、コードの仮の絵より先に使う。
