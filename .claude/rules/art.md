# 絵・マップチップ・エフェクト

`CLAUDE.md` の決まりのつづき（この話題の作業をするときに読む）。ぶつかったら `CLAUDE.md` が先。

## 見た目
- 横向きの絵しかない生き物・物を、上下へまっすぐ動かさない（横を向いたまま、すべって見える）。上下へ動く物には、正面・うしろの絵も作る。
- 作業（`WORKFACE`）は、その物のほうを向く。上（北）の物には、うしろ向き（`workFace`・`objAbove`）。
- 壁の正面の帯・巾木・模様は、家の角やはしまで、すきまなくつなげる。壁や床の見た目をかえたときは、かならず家の4つの角を大きくして見て、はしまで行っているかたしかめる。
- 夜の明かりは、重なって明るくなりすぎないようにする。手前にある背の高い物の上に、窓の光などをかぶせない。窓の光は、iso の窓の絵（`iso:win`）がとどいてから出す（いまは出さない）。
- ふきだしの絵（96×96）は、もらった絵（`tools/art/bubble/icons.png`）を `build.py` で BOX でちぢめて作る（ドット絵にしない。輪郭・うすさはもらった絵のまま）。ゲームでは、ふきだし（`pxBub`）がかえす中のまん中に、なめらかにちぢめて描く（`bubIcon`。ふきだしの中では1.5倍、わくの内がわ（`pxBub` の `f`）まで。せかいの大きさで描くと、ふきだしのドットのまるめとずれて、はみ出す）。
- エフェクト（`FXS`、`fxSpr` でながすコマならびの絵）を新しく作るときは、`tools/` のスクリプトでドット絵を作り、`assets/g` に書き出す（罠：`tools/fx-trap.py`）。作りなおせるように、スクリプトをのこす。
- エフェクトを作る・直すときは、スキル `.claude/skills/pixelfx/SKILL.md` も読み、`tools/pixelfx`（patch-gg/pixelfx の写し、MIT。244この効果と書き出しの道具）で、にた効果を書き出して見て、お手本・下ごしらえにする。ゲームの中では pixelfx のコードを動かさない（できた絵は上のとおり `assets/g` へ）。
- 自然・生き物・動き・天気・光をそれらしくする（足もとの粒・歩き方・首の向き・おくれてついてくる動き・雨や雪・地形・水・色の決め方）ときは、`tools/frostwind`（trinity-works/frostwind の写し、MIT。`NOTICE.md`）の `PIXEL-ART.md`・`PROJECTION.md`・`src/` を読み、考え方と数字をかりて、はこにわの作りで書きなおす。ゲームの中で Frostwind のコードを動かさない。中の `CLAUDE.md`・`.claude/` は、はこにわの決まりではない。ぶつかったら `CLAUDE.md` が先。
- せいれいの攻撃のエフェクト（`atk_fire`・`atk_earth`・`atk_wood`・`atk_wind`・`atk_water`、`atkFX`）は `tools/fx-attack-pfx.py`（pixelfx の効果から。火 sword-slash・土 earth-spike・木 vine-whip・風 dagger-flurry・水 splash。1.5倍の大きさ `SCALE`・15コマ／秒）。夜の暗さ・コワイノより上に描く（`TOPFX`。暗さの下だと、夜はほとんど見えない）。
- 守り神のわざ（まもりの光・こもれびのまもり・葉のかべ）のエフェクトは `tools/fx-guard-pfx.py`（pixelfx の効果から作る。`godlight` 光の槌（しるしの光る所を短くした `godlight:F`。0.25秒で地面に当たる）・`glspark` 範囲のマスの光・`skillhit` わざが当たったコワイノの金の光（`hurtEn` の `skill`）・`arrowburst` 見張り台の木の矢が当たった所・`areaguard` 葉のつむじ・`arealeaf` 光のつぶ・`leafsprout` 光の花）。まもりの光の音は持ち主がくれた音（`SAMPLES.glight`。もらった音にこだまをかさねて余韻を長くした `tools/sound/glight_tail.py`、もとは `tools/sound/src/glight.mp3`）を、光が地面に当たるコマに合わせて鳴らす（`lightSnd`・`GLHIT`）。コワイノ・夜の暗さより上に描く（`TOPFX`・`drawTopFx`）。画面を少しゆらして光らせる（`skillFx`）のも、まもりの光は地面に当たるとき（`GLFX`）。
- ドットでない物は新しく作らない（絵・UI・ミニゲーム・コードで描く絵も、ドット絵にする）。ただし、マップぜんたいにかける HD-2D の仕上げ（`js/hd2d.js`：明るい所のにじみ・時間の光の色。上下のぼかし（ピントの帯）は、持ち主がきめてなくした。光の帯は `light-rays.js` だけで、昼には出さない。設定の「HD-2D」で入り・切り、はじめは入り）は、ドットでなくてよい（持ち主がきめた）。ふきだし・文字・UI にはかけない（`render` の `hdPost` は、矢の数・ふきだしより前）。画面の四すみを少し暗く（`HDVIG`）。天気の光・空気の遠近もここ。見せ場（なかまが来る・オオカゲの登場・御神木が育つ）は `hdBig` でにじみを強く。にじみは設定の「にじみ」で入り・切り（`HDGLOW`）。fps などで自動で見た目をかえない（持ち主がきめた）。かげは時間で向きと長さをかえる（`sunLean`：朝は西・夕方は東へ、`sunLen`：朝・夕方は長く。足もとのだ円のかげ `shadow` と、落ち影は根もとからかたむけてのばす `hdCastStretch`。持ち主がきめた。木の絵の光は左上のまま）。
- 家具・建物の絵（`chips.js`）は、もらった透過PNGの透過（うすさ）と色をそのまま小さくして作る。うすさで切りぬかない（ふちがガタガタになる）。動く絵は、全部のコマを元の絵のそのコマから作る。
- マップチップの色は、1つの物ごとに256色まで（うすさは数えない・かえない）。1つの物は、id の `:` と `#` の前が同じ物（向き・コマ・開け閉め・つなぎの部品をまとめる。`story:`・`crop:`・`tex:` は1つずつ、`SOLO`。クォータービューの `iso:<id>:…`・`iso:win:<id>:…` は、その id ごと）。`tools/chips.py` の `pack_imgs` が、こえた物を自動でへらす（`cap_colors`：メディアンカット＋k-means、ディザなし。1つの色が RGB で24より大きくずれないように、はなれた色はそのまま入れる `OUTL`）。
- もらった絵の部品に、部品ごとの輪郭や明るさのちがいがあると、つなぎ目に線が出る：つなぐ辺は外の輪郭にせず、手すりなどは、となりの列でうめ、明るさをならす（`tools/art/tlb/tlb_art.py`）。
- くりかえして使う絵（床・壁の正面・塀・柵・道）は、もらった絵のままだと、ほとんどつながらない（生成した絵は、端と端が合わない）。
  - たのむときは「1まいのタイル」ではなく、「規則正しいもようで、ふちも枠もない、大きな続きの面（床）・長い続きの帯（壁・塀・柵）」をたのむ。板・レンガ・石などは同じ大きさ・同じ間かくでならべる、とはっきり書く。
  - もらったら、もようのくりかえしの間かく（自己相関）を見つけて、ちょうど1つぶんを切りとる。使う前に、2×2（帯なら横に3つ）ならべて、つなぎ目が見えないかをかならずたしかめる。つながらない絵は使わず、理由を伝える。
- 絵のプロンプトには「ざらざらしたノイズを入れない」も書く（clean flat colors with soft shading; no noise, no grain, no speckles, no dithering, no gritty texture）。
- 塀・柵・壁は、横もたても同じ作り：柱は角とはしだけ。そのあいだは、その材（横木・板・石）でつなぐ。たての絵（手前から奥へのびる向き）も、横と同じく、たのむ絵にふくめる。
- 見おろしの絵なので、塀や壁は、正面だけでなく上の面（てっぺん）も見えるように描く。
- ドアの上の断面（たて置きのドアは断面の絵）は、となりの壁の断面と同じ色にする：よこ置きは左の壁、なければ右。たて置きは上の壁、なければ下（`<壁>.door:<mask>`・`<壁>.door#v0〜3` など、壁ごとの絵）。
- 絵の大きさをかえるときは、ゲームの中で拡大・縮小しない（`c.scale` などをチップにかけない）。チップそのものを、その大きさで作りなおす（元の絵から作る）。ベッド・カーテン・窓も同じ。たのまれた大きさは、チップの w・h・ax・ay の数字で書く。
- 動く物（ドアの開け閉め・かまどの火など）は、動く部分だけをコマごとに差しかえる。動かない所（枠・本体）は、全部のコマで1コマめとまったく同じ絵にする。作ったら、コマどうしをかさねて、動く部分いがいにちがいがないかをかならずたしかめる。
- ノブなどの小さな部品を絵から切り出すときは、色で見分けた所だけにしない（暗いふち・かげが落ちて形がくずれる）。切り出した部品を大きくして、元の絵と同じ形かをかならず見る。
- 動く絵で、コマごとに本体の形が少しずつちがうと、動かしたとき「うねうね」して見える。動かない所（本体）は1コマめの絵にそろえ、動く所（明かり・炎など）だけを、それぞれのコマの元の絵から使う。もらった動く絵は、コマをかさねて、どこがちがうかをかならずたしかめる。
- もらった絵のくりかえしを切るときは、丸太・板・石などの、もののさかい目で切る（途中で切ると、はしに半分の丸太が出ておかしい）。もらった絵は、なるべくそのまま使い、よけいに切りとらない。
- お手本（組み合わせた絵）とレイヤーの部品をもらったら、まずレイヤーをお手本にかさねて、部品ごとにのばした大きさ・置いた場所をはかる。部品ごとに大きさがちがうことがある（たてに長くのばした柱など）。ゲームは、お手本と同じ大きさにする。できたら、お手本と同じ大きさにそろえてならべ、くらべる。
- なめらかな絵をドット絵にするときの輪郭は2ドット：外がわはその色より少し暗い色、内がわはまわりの色になじむ色（うすく・やわらかく。例 `tools/art/nature/nature_art.py`）。丸い物は、形をちぢめてから少しぼかして切り、とがった1ドット・角を出さない。
- もらった絵の輪郭線のむら・色のぶつぶつは、あとから処理で輪郭をぬりなおさない（ドットのはばが合わなくなる）。ちぢめるときに `tools/art/pixdown.py`（セルの色の多いほう・中の線と外の輪郭を1ドット。ドットのますめにそろう）を使い、のこった点やぬけは、12倍で見て、その物のドットを手でなおす（設定の `FIX`。例 `tools/art/set10/set10_pix.py`）。
- もらった絵を小さくするときは、面積の平均（PILの `BOX`）を使う。`LANCZOS` などは、帯や部品のはしに明るい線（にじみ）が出て、つなぐとすきまの線に見える。
- 「トリミングしてそのまま」は、もらった絵を切りとるだけで、細かさ（1マス64ドット）も大きさもかえずにチップにする。
- 前の見え方の部品のかさね方・描き方（`wallFront`・柵・塀のつなぎ方 `MCONN` など）をかえたら、マップチップ工房の「つなげたとき」「ドア・窓（門）といっしょに」の見本（工房の `index.html` の `comboDraw`・`openDraw`。前の見え方の部品の見本。地図のつなぎ方は「ゲームの中で」の写し）も同じ描き方に直す。見本だけ古いままだと、まちがった絵に見える。
- もらった絵をマップチップにするときは、スキル `.claude/skills/chip-art/SKILL.md`（`tools/art/pixdown.py` でちぢめる）の手順でする。
- ドット絵を描く・直す・仕上げるときは、スキル `.claude/skills/pixel-craft/SKILL.md`（丸みのならび・色の差・色数・中間色・線と影・顔と目・直す順番）を読む。
- いまあるチップを「ドット絵スキルで直して」「ルールに合わせて修正して」と言われたときは、スキル `.claude/skills/pixel-redraw/SKILL.md` の順番どおりにする（`tools/art/chipcheck.py` で数字をしらべる → `tools/art/pixdraw.py` で描く → めやすがぜんぶ通ってからチップに入れる → `tools/art/chipview.cjs` でゲームの中で見る。お手本は食卓 `tools/art/table/table_art.py`）。描きなおすのは、たのまれたチップだけ。
- ドット絵をあたらしくつくる・評価する・「きれいにして」などの直しを言われたときは、スキル `.claude/skills/pixel-manual/SKILL.md`（設計・手順・質感・視点・統一・チェックリスト）も読む。ぶつかったら `CLAUDE.md` が先。
- マップチップを作りなおしたら、`chips.js` の `CHIPA` が指す `assets/chips/*.webp` が、ぜんぶコミットに入っているか（`git ls-tree`）たしかめる。入れわすれると、多くのチップが出なくなる（#1661 でおきた）。
- マップチップの絵をかえたPRでは、マップチップ工房（https://claude.ai/artifact/TSGpjyVzS5fJvYkatcNaKv）も新しくする。工房は `index.json` と `g/<ジャンル>.json` だけを読む。Artifact の read で `index.json` と、かわったチップのある `g/*.json` をおとし、`python3 tools/chips.py kobo <そのフォルダ> [id...]`（id がなければ、さいごの replace でかえた物）で、かわったチップだけを書きかえて、出てきたファイルだけを公開しなおす（ぜんぶの unpack はしない。とても時間がかかる）。
- マップチップ工房の名前（`index.json` の `names`）は、ゲームの `BL` の名前。ないと id のまま出て、名前でさがせない。新しい物の絵を工房に足したら、`names` にも足す。
- マップチップ工房の「さしかえ」でもらった `replace.json` は、`python3 tools/chips.py replace replace.json` で入れる（数秒。アトラスの WebP は method 2。method 6 は1ページ25秒かかり、小さくもならない）（絵の大きさがかわると w・h もかわる。ax・ay はそのまま。工房で位置・大きさを調整した物（`meta`）は、ax・ay をかえ、大きさは元の絵から BOX で作りなおす）。
- マップチップ工房の「ゲームの中で」の見本（`gv/<id>.webp`）は、ゲームそのもの（クォータービュー）で置いて写した絵（`tools/gameview_boot.cjs` で写し、`tools/gameview_grid.py` でひし形のマス目と置くマスのわくをつける。写すときの倍率と大きさは `info.json`）。つながる物は角を置くマスにした L 字、ドア・窓は壁・柵といっしょに置いて写す。飼う生き物は `ani:<k>`（`S.ani` に1ぴき、立つ絵 #0。見本のファイル名は `ani-<k>`、工房は `#` の前の id を先にさがす）。チップの絵・大きさ・置き方をかえたら、写しなおして工房も公開しなおす。工房のチップの一覧を、いまの `chips.js` にそろえる（ないチップを足し、なくなったチップをけす）ときは `python3 tools/chips.py kobo-sync <フォルダ> [names.json]`（工房の `g/*.json` をぜんぶおとしておく）。

## 壁・柵の部品の絵（前の見え方の絵。アイコン・工房の見本）
- 地図の壁・ドア・窓・塀・柵・生垣は、ひし形のつなぎ方（`js/iso-conn.js`、「クォータービューの地面」の節）。この節は、前の見え方で作った部品の絵（アイコンと工房の見本で使う。`drawConn`）の決まり。
- 部品の絵（`chips.js`）は `drawConn` でつなげて描く。部品は `<id>:H0/HL/HR/HLR`（横の壁。H0は柱だけ）、`<id>:VU/VD/VUD`（たての壁。上から見た断面だけ）、`<id>:m5〜m15`（角・つなぎ目）。つながりは `connMask`（左1・右2・上4・下8）。
- 1マスの中の場所：断面（てっぺん）は y−9〜y、正面の板は y〜y+28、巾木は y+28〜y+32、その下4ドットがかげ（1ドットごとに下ほどうすく：うすさ 96・64・38・16。角の部品 `m5〜m7` も同じ。下かななめ下が家の中の壁は、もっとうすい 64・42・24・10 の絵 `~in` を使う）。柱とたての壁は x+5〜x+27。
- 正面の帯（板・巾木・模様）は `wallBand` で、世界の座標でならべる（マスのさかいめに継ぎ目を出さない）。
- 家の中から見える正面（下か、ななめ下のマスが家の中）だけ、中がわの見た目にする。角のマスは、柱の外がわ（x〜x+5・x+27〜x+32）にも帯をつけて、はしまでつなげる。
- たての壁を手がきの絵（`drawSection` などのマスごとの絵）で描くと、マスのさかいに線が出て、すきまに見える。部品の絵（`VUD` など）を使う。
- よぞらの壁：断面と形は、ダークチェリーの部品 `yozorawall:H0` など（木の壁の部品の色をおきかえた絵）。正面は `wallFront` でかさねる：外から見える正面はもらった絵 `yozorawall:ext`（世界の座標でならべる）、柱の正面は `yozorawall:post`、家の中から見える正面は夜空の帯 `yozorawall:band` とダークチェリーの巾木。
- 竹の壁（`bamboowall`、火山だけ `STAGEONLY`。火山の家の壁はこれ。木の壁は草原だけ）：部品の絵は、もらった絵（上の面・正面・柱・たての帯、どれも64でくりかえす、1マス64ドット）を、つながりごとに組んで作る（`tools/art/bamboowall/bamboowall_art.py`。正面は竹だけの行をくりかえして56→64）。ドア・窓などの壁ごとの絵は、しっくいの壁の絵の木の所（よぞらの壁の絵とちがう所）を竹の色にした絵。`<壁>` のチップ（id だけの名前）は作らない（あると窓の壁で窓を描く所へ進まない）。
- 木の壁・丸太・しっくい・レンガの壁も、正面は `wallFront` でかさねる：正面 `<id>:ext`（もらった絵。世界の座標でならべる）と柱 `<id>:post`。断面と形は部品の絵のまま。
- 柵（板の柵 `fence`、オークの色）・丸太の塀（`logfence`）・竹の柵（`bamboofence`）・御簾垣（`misugaki`）・石の塀（石垣 `wall`）は、3Dで組んで写した絵（`tools/art/fence3d/fence3d.py`。かげは家具と同じ5色 `furntone`）。つなぎ方16とおり（`<id>:m0〜m15`）を、それぞれ、そのマスの中の物だけで組み、ゲームはその1まいを描くだけ（`drawConn` の `MCONN`。石の塀は、となりの石の塀のドアへのばす）。見え方は家具の38度ではなく、ゲームのマスと同じ（`oblique3d.game`）：そうしないと、たての柵がマスごとにつながらない。よこのつなぎ目は、横木・くい・石をマスの外までのばして組み、マスのはばで切る（木目・石のもようは1マスでくりかえす `Tex` span 1・`sc.txo`）。たてのつなぎ目は、横木を上のマスへのばして組み、のばした所とそのまわりの線だけ消す（はしに線が出ない）。石の塀のたてのかさ石は、マスの上のはしを1ドットあけて、つなぎ目の線を出す。柱はマスのまん中、たての柵は柱のまん中にそろえる。マスのさかいに石のつなぎ目を置かない（切ったはしの線が、かたほうのマスにだけ出る）。
- 柵・塀のドアと門（柵のドア `gate`・丸太の塀のドア `logdoor`・丸太の大門 `loggate`・石の塀のドア `sdoor`・石の大門 `stonegate`・御簾垣の戸 `misugaki.gate`）も3Dから（`tools/art/fence3d/doors3d.py`）。開いたコマ（`#h1〜3`・`#v1〜3`）は、とびらをちょうつがいのたての軸でじっさいにまわして写す（0・30・60・85度。よこ置きは手前へ、たて置きは東へ）。よこ置きの柱はマスのさかいにまたがって立ち、右どなりの柵・塀は柱にかかる所を描かない（`GLX`＝柱のはばの半分。石の塀も）。たて置きの柱は、マスの中に立つ（下のマスの柵が、あとから柱の上に描かれないように）。御簾垣の戸の柱はマスの中。丸太の塀は、丸太の塀・そのドア・大門とだけつながり、ほかの柵・塀のとなりでは、はしの柱で終わる（`LOGF`）。
- 生垣（`hedge:0〜15`、g64）は、もらった絵（`tools/art/hedge/image.png`、3Dのお手本どおりのならび）から `tools/art/hedge/hedge_art.py` で作る：よこの帯（横の生垣のはし・まん中）と、たての柱（たての生垣の上のはし・まん中・下のはし）を、つなぎ方ごとにかさねる。くりかえしのまん中は、はしをまぜて1マス（64）でちょうどつながる形にし、世界の座標でならべる（となりのマスとつながる）。たての生垣のはばは x 5.5〜58.5、上の面の上のはしは y −11。
- ダークチェリーの色（よぞらのベッドの木の色）：もと #522d1d・明るい所 #86552f・かげ #321f14。よぞらの家具・床・壁・ドア・窓は、この色にそろえる。

## 絵の細かさ
- アイコン（`iconURL`）は、2倍の細かさで描いて、144×144になめらかに入れる（画面では72などにちぢめて出す）。ドットをとばす縮小・拡大（`imageSmoothingEnabled=false` で半はんぱな倍率）にすると、がたがたになる。
- 地面・床・平らな物は、地面の下絵（1マス32ドット）にやきつける。1マス64ドットの絵（`g:64`）をそこに描くと、半分の細かさになって荒く見える。くっきり見せたい物（ラグなど）は、毎コマ、画面の細かさで描く。
- 床のもようは、1ドットの線でかく（下絵と、壁ぎわの毎コマの絵とで、見た目がそろう）。
- 床は、はしまで、すきま・線・段なしでつなげる。
  - 壁・ドアの下にのばす床（家の中がわ、`wallMarg`）は、地面の下絵に描く。毎コマの絵で重ねない（下絵と細かさがちがい、マスのさかいに線が出る）。
  - 床の上はしの「壁の下のかげ」は、壁の下にのばした床にもつなげる（`shU`）。家の角で、かげが段にならないようにする。
  - 床や壁の見た目をかえたら、家の4つの角を6倍以上に大きくして、すきま・線・段がないか見る。
- 壁の正面の帯・巾木を、マスごとにコードで描く（`wallBand` など）ときは、となりの壁に0.5だけ重ねて描く。ぴったりのはばで描くと、ふだんの拡大率（1.3倍・1.7倍など、きりのよくない倍率）で、マスのさかいめにすきまの線が出る。
- 見た目のたしかめは、6倍以上の拡大に加えて、ふだんの拡大率（1.3〜2.3倍）でも見る。

## 自然の物
- 岩（`rock`）の絵は、はば1.5マスくらい（持ち主のたのみで、前の1マス以下の絵の1.5倍）。
- 自然物のチップ（木・森の木・りんごの木・枯れ木・ベリーの茂み・岩・大岩・きのこ・火山の木2つ）は、トリポのモデル（`tools/art/nature3d/nature_prep.py`）から3Dで写す（`furn3d/items/nat_*.py`、共通は `natcommon.py`）。お手本は、前のチップの絵（色・形・ならび）。
  - 葉は、葉の玉を小さな葉の部品でおおう（`leafballs`、御神木と同じ）。幹は CC0 の木の皮（Bark001）を、のびる向きにすじが通るようにはる（`barktexdecal`：まっすぐな幹は `axis='z'`、枝わかれは `'screen'`。テクスチャをそのままはると、ドットのノイズになる）。かげは、うすいトゥーン（`GRAD=False`・`SHADE` 半分）。背の高い木は見おろし4度（`ELEV`）、高さはそのまま太さ1.3倍（`wide`）。
  - 枯れ木（`deadtree`）・草原の木（`tree`・`ntree`・`fruit`）・火山のとんがりの木（`tree~v`・`deadtree~v`）・ベリーの茂み・御神木（`story:*`）のかげ（持ち主がきめた）：左上の光（設計図の `LIGHT`）。色は5つだけ（かげ2色・もとの色・ハイライト2色）と輪郭。色のさかいめだけ、はばの小さい市松もようのあみかけ（`tone5` の `dw` 0.03。あみかけは最小限・輪郭の左上を明るくしない `rimhi` 0。家具と同じ。持ち主がきめた）。皮のすじは少しだけ（`natcommon.tone5`：写したときの奥行き `LAST_ZB` から面の向きを出して、なめらかな明るさを5だんにわける）。木は幹と葉を色でわけて2回かける（`mask`）。葉は、写した絵の明るさをまぜて（`mix`）つぶつぶの形をのこし、かげは青みのある緑（`pal`）。葉の下の幹は暗く（`under`）。御神木は、ヌシの傷を目じるしの色でもう1回写して場所をしらべ、傷の色はそのままのこす（`sacred_tripo.shot`）。切り口・光のつぶ（うすい色）もかえない。
  - 枯れ木（草原）は、同じ3Dを0・45・180度まわした3まい（`deadtree`・`#1`・`#2`。設計図の `VIEWS` の3つめが角度）を、マスごとにえらび、半分は左右反対（`plantChip`・`DTV`）。足もとにドットのだ円のかげ（`dtShadow`）。
  - りんごの木の実ったときは、3Dの絵を作らず、ふつうの木の絵にりんごのアイコンをのせる（`appleOn`。持ち主のきめ）。
  - 岩・大岩は、お手本と同じ大きさ・形・ならびに、点をつつむ角ばった形で組む（`hullrock`、面ごとにお手本の5だんの色）。
- 秋（`seasonNow()===2`）は、草原の木（`AKITREE`：tree・ntree・fruit）を紅葉の絵（`tree~aki0` 赤・`tree~aki1` 黄、マスごと）にする。絵は `nat_tree_aki.py`（`nat_tree` と同じ3Dで、葉の5色と輪郭だけ秋の色）。落ち影も作る。草原の木の絵をかえたら、こちらも作りなおす。
- 自然の物の光は太陽1つ（`natcommon.SUN`：高さ30度・正面から左へ8度。持ち主がきめた）。木・茂みのかげ（`tone5` の `light=sunscreen(ELEV)`）・岩・きのこ（`LIGHT=SUN`）・落ち影、どれもこの光。モデルをまわした絵でも、光はまわさない。
- 落ち影（`tools/art/furn3d/castshadow.py`、チップ `<絵>:sh`・左右反対は `:shf`）：根もとの高さに見えない平面を置き、太陽から影を落として、その絵と同じカメラで写す（高い所をけずる・切る・ずらして合わせない）。ぼかして2色（こい・うすい）。さかいめだけ、はばの小さい市松のあみかけ（`BANDS`）。ゲームは、その行の段差のあと・その行の物より先に描く（`castShadowChip`、`CASTSH`）。自然の物の絵をかえたら、影も作りなおす。
- 生き物（飼う生き物・小さな生き物）の足もとのかげは、ドットのだ円（`dotShadow`：まわり1ドットはうすく・中はこく `DSHA`、時間で向きと長さ）。はばは、そのコマの絵の下から30%の行のはし（`chipFoot`、チップごとに1回しらべる）。小さな生き物は、高くとぶほど小さく・うすく（`CRITSHZ`）。
- 3Dのモデルの面に、ポーズの前の場所で色をつけるときは `Part.paint`（`blueprint.build`。みつばちのしま `crit_rig` の `stripes`・`BEEBANDS`）。ポーズのあとの場所（`decal`）でつけると、からだをかたむけたコマで柄がずれる。
- 生き物のモデル（家畜・小動物、`tools/art/animals/animal_prep.py`）：目は左右とも同じ大きさのたいらな玉にかえる（もとの目は左右で形がちがう）。部品の番号で目をほっぺにすると片目がピンクになるので、目は2つとも `EYE` にする。

## 時間の色
- 昼と夜の色は、`js/daycolor.js` の表 `DAYC` 1か所（時刻ごとに、夜の暗さの色 `dk`・地面 `g`・水 `w`・雲の海 `s`・屋根 `r`・窓のあかりの強さ `win`・時間の光 `glow`）。時刻のあいだはなめらかにつなぐ（`dcNow`）。色をかえるときは、この表の数字だけを書きかえ、ほかの所に夜の色を書かない。
- 地面の層は、物より先に画面ぜんたいにかけ算（`dcGround`）。物・がけの正面は、夜の暗さ（`DMK`）だけ。水は、水面を流すときに表の `w` をかける（`igShimmer`）。雲の海・屋根の層（表の `s`・`r`）と、高い段の上の面（`isoTile`）には、まだかけていない（ひし形にしたあと、まだ）。あかりは、いままでどおり暗さをけずる（2つめの層）。
- 物ごと（チップごと）の色わけはしない（持ち主がきめた。描くたびに目印の絵がいって、スマホで重い）。

## 日ざしと月明かり
- 光の帯（ゴッドレイ、`light-rays.js`）：晴れた朝・夕方と、月のある夜（満月は強く・新月はなし）だけ。昼は出さない（持ち主がきめた）。帯は `RAYP` のドットの絵を1回だけ作ってならべる。夜は帯の所の暗さを少しけずる（`rayCutDark`）。帯の中の花粉の粒は、ドットできらっと光る（`rayInside`）。

## 畑と作物の絵
- 花・木・作物・木の実が育つのは朝6時（`morning`）。植えた花・木の芽は、つぎの朝6時まで（`S.bud` と `isBud` は `callDay`。`dayNo` は夜中の0時でかわるので使わない）。
- 畑の土（`farm:0〜15`・ぬれた土 `farmw:0〜15`）は、上下左右のつながり16とおり。絵は「大きな畑3×3・よこ1×3・たて3×1・1マス」をたのめば、16とおりがそろう。
- 1マスに畝が1本で、畝のまん中がマスのまん中。土の絵に草・芽を入れない（同じ絵をくりかえすので、草が同じ場所にならぶ）。たのむときも、そう書く。
- 花・木の芽は `bud`（土のもりあがりつき）。ハスは水の上なので、土のない芽 `bud~w`。
- 芽・土のもりあがり・作物は、土のもりあがりごとの絵（ぬれた畑は `<key>w`）。どれも、土の下はしを同じ高さ（畝のてっぺん）にそろえる。芽は、育ちはじめたら描かない。
- つやつやの作物（`tsuyaOf`・`TSUYA`）：たねをまいたとき（`sowFarm`）に `d.ts`、朝（`morning`）に育ちきる前の畑がかわいていたら `d.dry`。`d.ts` があって `d.dry` のない畑は、収穫+1・とれごろに光のつぶ（`tsuyaDots`）・収穫のとき光（`juiceGlowAt`）。収穫の数を出す所・見る所（`hYield`・畑の画面・`harvest` の空き）にも `tsuyaOf` を入れる。たしかめは `tools/tests/tsuya.cjs`。

## クォータービューの地面（`js/iso-ground.js`）
- 地面は、画面の向きの四角の区画（`IGW`×`IGH`、1ドット＝ゲームの1点、1マスのひし形は64×48）に作り、ステージを開くときにぜんぶ作って、すてない（`igJobs`。いま草原で約80MB＋水面の形 約8MB。かわった所は `igDirty`）。
- 草地とあれ地・水と岸のさかいは、デュアルグリッドのオートタイル（マスの角ごとに、となり4マスの16とおり。`igTiles`・`IGWT`）。1ドットずつぼかす・ノイズでゆらす・色むらをかさねる作り方は、もうしない。
- ひし形の絵がとどくまでは、いままでの上から見た絵を、ドットのまん中の点で写す（まわして描かない）。地面の絵は、まうえから見たつながる面でたのむ（`tools/art/iso/ground-prompt.md`）。
- 水は岸より一段ひくい：画面で水のすぐ上が陸なら岸の断面（`WBANKC`）。水面は毎コマ流す（`igShimmer`）。高い段の上の面は `igTile`。
- 段差（`js/iso-cliff.js`）：高い段は上の面を段の高さだけ上に、手前のとなり（y+1・x+1）が低い所だけ1だんずつ壁のタイル（`icFace`、とっておく `ICK`）。坂・階段・ハシゴは3Dの点を画面へ写した形（`icShape`、ふちはぼかさず切る）。描く順は x+y（階段は `icStairDD`）。
- つながる物と屋根（`js/iso-conn.js`）：壁・ドア・窓・石の塀・柵・生垣は、マスごとの「まん中の柱＋となりへのびる腕」（`iqMask`：左1・右2・上4・下8）。3Dの絵はチップ `iso:<id>:<m>`（ドアは向き `h`・`v` と `#1〜3`、ひくい壁は `~low`、壁にかける物は `iso:win:<id>:<h|v>`。ax・ay はマスのまん中の地面の点）。屋根は家の列ごとの切妻（棟は東西）をコードで組む。屋根をはずした家は、手前の南・東の壁をひくい壁にする（`iqFront`）。
- 家具・建物・自然の物（`js/iso-obj.js`）：クォータービューの3Dの絵は、いまのチップと同じ名前で入れかえ、チップに `iso:1` をつける（`drawChip` が `isoChipAt` で画面の向きに描く。ax・ay は置いたマスのまん中の地面の点から。反転しないので、向きは4つとも写す）。
- クォータービューの絵（`iso:1`）は、描くときに画面の向きをかけなおす（`isoScreenTf`）ので、その前の `translate`・`rotate`・`scale`（ゆれ・育つときののびちぢみなど）はきかない。かけるときは `isoLocal({rot,sx,sy},…)` で、足もとの点のまわりにかける。写すのは `python3 tools/art/iso/iso3d.py <出力> [設計図...] [--chips]`（`--from` で写しなおさずにチップへ）。御神木の絵は、切り株の n×n のまん中から描く（`isoChipAt` の `story:`）。大きさはゲームの BL の `sz`（`bl_sizes`）。絵より置く所が大きい物（作業台・その上の形）は、向きごとのずれ `FOOTOFF`。材料置き場は、そのマスのまん中から（`isoChipAt` の `matyard`）。
- せいれい・生き物・コワイノの向き（`js/iso-face.js`）：せかいの向き（正面＝南など）は、いままでのまま。描くときに `isoFace` で、前ななめ（南を向いて写した絵＝左下）・うしろななめ（北＝右上）の2つの絵と左右の反転にする（東は前ななめの反転・西はうしろななめの反転）。絵は、いまの正面の絵の名前を前ななめ、うしろの絵の名前をうしろななめに入れかえる（よこの絵は使わない）。向きを見る描き方を足したら、`isoFace`・`isoVw` を通す。写すのは、せいれい `build.py --iso`（`js/spirit-motions-iso.js` の `SPMQ`。洞窟はいままでの `SPM`。3Dの絵のない立ち姿は `stand`）・飼う生き物 `ANIISO=1 ani_build.py`・小さな生き物 `CRITISO=1 crit_build.py`・コワイノ `KWISO=1 kowaino_paint.py --sheets`。せいれいの目・ほっぺは、左右べつに顔の3Dの面の上の場所とちぢみ方をコマごとに出し（`rig.py` の `eyeq`・`ISOEYEUV`）、ゲームはそのとおりにかさねる。見える・見えないは、その向きのコマの多いほうにそろえる。
- ドア・門・壁にかける物（`tools/art/iso/iso_door.py`、チップ `iso:<id>:<h|v>`・`#1〜3`・家のドアの `~low`・`iso:win:<id>:<h|v>`・ドアのリース `iso:win:wreath:d`・`d#1〜3`）：とびらは、おく（北・西）へひらく（手前へ出すと、あとで描く手前のマスの物にかくれる）。ひらいたとびらは、マスの外へ出ても切らない（`own_mask` の `free`）。柵のドアの柱はマスの中（`doors3d.INPOST`。2マスの門は `BIGIN`）で、柱のはばの所だけ、となりの柵の腕を描きこむ（ないと、柵の横木がマスのさかいで切れて、柱とのあいだにすきまが出る）。マスの東・南のはしちょうどの面は、そのマスの物（`EDGE`。ないと柱の東の面が切れる）。かさ石など、はみ出す物もマスの中におさめる。
- エフェクト・夜・霧（`js/iso-fx.js`）：地面にはりつく物（水たまり・わく・かげ・霧）は地面の描き方のまま、段は `isoGroundLv` でつける（せかいの y から `liftOf` をひかない）。立つ物・うかぶ物（粒・輪・落とし物・場面の光）は足もとで立てる（`isoStand`・`isoCell`・`isoAt`）。粒・エフェクト・字の足もとは、うまれたときの地面の点：頭の上など地面より上に出す物を足すときは、地面の y を書く（fx の `gy`・`fxSpr` の6つめ・`addFloatG`・矢の `gy1`・`gy2`）。字・数・札は `isoUITf` で、のばさずに描く。霧・雲は `IQFOGH` だんのあつみ（`isoFogDraw`）。夜のあかりは物のまわりの地面の円（`isoLitPool`）。

## 草地のふち
- 種類のちがう道どうしがとなり合うときは、両方の道のふちに草のふちを出す（`drawFloorChip` の `tr`）。
- 草地とあれ地のさかいは、あつ森より（持ち主がきめた）：まるくやわらかい形で、デュアルグリッドのオートタイル（`iso-ground.js` の `igTiles`）。水・高さのちがうマスは見ない。水のマスから草をはみ出させない・水の下に草をしかない。

## 水面
- 水のふちに、となりの地面を鏡うつしにしない（水のうつしこみはいらない）。水のマスの下（ふちのすきま）は、となりの陸の地面（草地・乾いた地面）を、そのがわの半マスに同じもようでしきつめる。あぜ道・砂利道は、水につなげない（水のがわも、ふつうの道のはしと同じに丸く切り、草のふち（そのマスの地面が草地なら `fringeg`）も、ほかのはしと同じに出す。水の下に道のもようを入れない）。
- 水面は、水のテクスチャそのものをゆっくりスクロールさせる（`igShimmer`）。白いキラキラ（点めつ）や、もようをゆらして重ねる方法は使わない。
- 池・川のふちは丸める：水と岸のさかいは、デュアルグリッドのオートタイル（`IGWT`：まっすぐな岸は水のマスの7ドット内がわ）。
- 池・川の水面は、岸より一段ひくく見せる（`WBANK`）：画面で水のすぐ上が陸なら、岸の断面（`WBANKC`）とそのかげ。火山の水と雲の海はべつ。

## 道・床の絵
- 草原のあれ地（`tex:dry`）・草地（`tex:grass`）は、もらった絵（`tools/art/ground/src`）を `ground_tex.py` で224×224にちぢめた、つながる絵（`DRTEX`）。あれ地は、224ドットの区画の列ごとに左右、行ごとに上下を、ばらばらに反転してしきつめる（`dryTex`）。かがみうつしでつながるので、さかいは出ない。90度まわすと、さかいでひびが切れるので、まわさない。
- あぜ道・砂利道（`path#0〜3`・`gravel#0〜3`）は、もようにくりかえしがないので、まわりの帯を4しゅるいで同じにして（半分ずらしてつなげた絵）、まん中だけをかえている。どうならべてもつながる。
- 石畳・レンガ道（`stone#0〜3`・`brick#0〜3`）は、2×2マスでつながる1まい。石畳は、もらった石組みのテクスチャ（128×128）を半分にして4まいに分けた絵。レンガ道は、もらった絵をそのままの細かさで使う。石の床（`stonefloor#0〜15`）は、石畳とはべつの、4×4マスでつながる絵。石・レンガの色はばらばらなので、目地で切り、ずれた行のはしの石は、同じ石の続きを使う。
- 石畳・レンガ道は1マスぴったりのはば（へりはマスのふちまで、切らない）。あぜ道・砂利道は、ふちを少しまるく切る。
- 道のへり（`stone:0〜14`・`brick:0〜14`、内がわの角 `:c0〜3`）は、もらった四角の絵のへりの石から作った7ドットの帯と角の石。石畳のへりは、帯の明るさ（目地・ハイライト・かげ）はそのままに、色ともようをみかげ石（`tex:granite`）にかえた絵。へりのある道（石畳・レンガ道）は、どれも同じ作り：へりは、はば5ドットの帯（上下の帯を90度まわして左右に使う。たてとよこで同じはば・同じ形）。帯と道のさかい（道がわ）には、うすいかげ2ドット。内がわの角（入隅）`:c0〜3` は、となりの2つの帯をL字につなぐ9×9（外がわの2×2はあける）。レンガ道のへりのレンガは16ドット。
- じゅうたんのふち（`carpet:U/D/L/R`）は、マスのいちばん外がわに、はしからはしまで（32ドット）。となりもじゅうたんなら描かない。
- チップの未使用判定は、動的な名前（向き・接続・成長・開閉・表情）とフリーモード・旧セーブ移行も確認する。読み込み確認だけに残る旧部品を消すときは、確認側も現在の描画用チップに合わせる。削除済みの一覧と理由は `tools/art/unused-chips.json`。

## 手ざわり・まとまり・間（ポリッシュ）
- 歩いているあいだは、よろこぶ・拍手・会話中でも、歩く向き・歩く動きのまま描く（`walking` のときは `clap`・`wv`・`facePlayer` にしない）。こっちを向いたまま、すべらせない。場面の姿勢（`sacredPose`：会話で聞く姿勢 `dlgListen` など）がのこっていても、歩いているあいだは使わない（`drawRes0` の `storyPose`）。

## 火山のそうび
- コードで描く絵（そうびのアイコン・鉱脈など）は、ドット絵にする：小さなマス目（16×16 など）を整数のドットの fillRect でかき、まるい線・なめらかな線・グラデーションは使わない。のばすときは imageSmoothingEnabled=false。色はゲームに合わせた明るくやわらかい色、輪郭は中の色より少しだけ暗い色（黒にしない）。

## なかよし
- 新しいドットのアイコンは、形（マスク）から2ドットのふちを作る（`ui2` のときの作り方：形をけずって引く）。
- 32×32のアイコン（そうび・料理・食べ物・宝・鉱石など）は `tools/art/icons32`（`game.py` でゲームに入れる：3倍の96×96を `ICONS` へ）。輪郭はまわり1ドット（となりの色を少し暗く）、色は1こ16色まで（`quant`。`chips.py` の `cap_colors` は、はなれた色をのこすかわりに白いうつわのかげなど広い所をくずすので使わない）。細長い物（矢）は45度ななめにしてからちぢめる。くずれる物は `hand.py` で手で描く。コードの仮の絵の所は、`ICONS` に絵があればそちらを使う。
- ふきだしの絵は、もらった96×96の絵30こ（`assets/g` の1まい、`BUBSPR`・`BUBS`。元は `tools/art/bubble/`、`build.py` で作る）を描く。ふきだしは40.5×38.25（話したそうなふきだしは45×42）。読みこむまで・表にない物は、11×11のコードの絵（`BUBART`・`BUBI`）。絵文字の字は `r.bubble` のキーとしてだけ使い、絵文字のフォントでは描かない。表にない字は「？」の絵（`bubIcon`）。新しい絵文字をふきだしに使うときは、`BUBART` に絵を、`BUBI` に字を足す。
