# 絵・マップチップ・エフェクト

`CLAUDE.md` の決まりのつづき。ぶつかったら `CLAUDE.md` が先。数字・道具の場所はコードとスクリプトが本物（`tools/art/` の物の名前で探す）。

## きほん
- 物とせいれいの前後は、深さの順のレイヤで重ねる（手前の物が上）。せいれいや物の絵を切って（clip・cut）前後を見せない。台のむこうで顔がうまるときは、立つ位置で直す（持ち主がきめた）。
- かげは、明度でなく彩度でつける（かげほどあざやか・明るさはかえない。持ち主がきめた。3Dから写す絵も、手で描く絵も）。
- 横向きの絵しかない物を上下へまっすぐ動かさない（すべって見える）。上下へ動く物には正面・うしろの絵も作る。作業は、その物のほうを向く（北の物にはうしろ向き）。
- 壁の正面の帯・巾木・模様は、家の角やはしまで、すきまなくつなげる。
- 夜の明かりは、重なって明るくなりすぎないように。手前の背の高い物の上に窓の光をかぶせない。
- ふきだしの絵（96×96）は、もらった絵（`tools/art/bubble/icons.png`）を `build.py` で BOX でちぢめて `assets/g` に（ドット絵にしない）。ゲームでは `pxBub` の中のまん中に、なめらかにちぢめて描く。表にない物はコードの絵。絵文字は `r.bubble` のキーとしてだけ使い、絵文字のフォントで描かない。新しい絵文字は、`BUBART` に絵、`BUBI` に字を足す。
- エフェクト（コマならび）は `tools/` のスクリプトでドット絵を作り `assets/g` に書き出す。スクリプトはのこす。作る・直すときは `.claude/skills/pixelfx/SKILL.md` も読み、`tools/pixelfx`（MIT）で、にた効果を書き出してお手本にする。ゲームの中で pixelfx のコードを動かさない。
- 自然・生き物・動き・天気・光をそれらしくするときは、`tools/frostwind`（MIT）の `PIXEL-ART.md`・`PROJECTION.md`・`src/` の考え方と数字をかりて、はこにわの作りで書きなおす。Frostwind のコードを動かさない。中の `CLAUDE.md`・`.claude/` は、はこにわの決まりではない。
- せいれいの攻撃のエフェクト（`tools/fx-attack-pfx.py`）・守り神のわざ（`tools/fx-guard-pfx.py`）は、夜の暗さ・コワイノより上に描く（下だと夜は見えない）。まもりの光の音は、光が地面に当たるコマで鳴らす（画面のゆれ・光も、そのとき）。
- ドットでない物は新しく作らない（絵・UI・ミニゲーム・コードの絵も）。ただし、マップぜんたいの HD-2D の仕上げ（`js/hd2d.js`）は、ドットでなくてよい（持ち主がきめた）：
  - 明るい所のにじみ・時間の光の色・四すみを少し暗く・天気の光・空気の遠近。上下のぼかし（ピントの帯）はなくした。設定の「HD-2D」「にじみ」で入り・切り。ふきだし・文字・UI にはかけない。見せ場はにじみを強く。fps などで自動で見た目をかえない（持ち主がきめた）。
  - かげは時間で向きと長さをかえる（朝は西・夕方は東へ、朝夕は長く。持ち主がきめた。木の絵の光は左上のまま）。

## チップ・もらった絵
- 家具・建物の絵は、もらった透過PNGの透過と色をそのまま小さくする（うすさで切りぬかない。ふちがガタガタになる）。動く絵は全コマを元の絵のそのコマから。
- チップの色は1つの物ごとに256色まで（うすさは数えない）。1つの物は、id の `:` と `#` の前が同じ物（`story:`・`crop:`・`tex:` は1つずつ。`iso:<id>:…`・`iso:win:<id>:…` は id ごと）。`tools/chips.py` の `cap_colors` が自動でへらす。
- もらった絵の部品に輪郭・明るさのちがいがあると、つなぎ目に線が出る：つなぐ辺は外の輪郭にせず、となりの列でうめ、明るさをならす。
- くりかえす絵（床・壁の正面・塀・柵・道）は、もらった絵のままだと、ほとんどつながらない：
  - 「1まいのタイル」ではなく、「規則正しいもようで、ふちも枠もない、大きな続きの面（床）・長い続きの帯（壁・塀・柵）」をたのむ。板・レンガ・石は同じ大きさ・同じ間かくでならべる、と書く。
  - もらったら、くりかえしの間かく（自己相関）を見つけて1つぶん切りとり、2×2（帯は横に3つ）ならべて、つなぎ目が見えないかかならずたしかめる。つながらない絵は使わず、理由を伝える。切るのは、丸太・板・石などのさかい目で。
- 塀・柵・壁は横もたても同じ作り：柱は角とはしだけ、あいだはその材でつなぐ。たての絵もたのむ絵にふくめる。見おろしなので、上の面も見えるように描く。
- ドアの上の断面は、となりの壁の断面と同じ色（よこ置きは左の壁、なければ右。たて置きは上、なければ下）。
- 絵の大きさをかえるときは、ゲームの中で拡大・縮小しない（`c.scale` などをチップにかけない）。チップをその大きさで元の絵から作りなおす。たのまれた大きさは w・h・ax・ay の数字で書く。
- 動く物は、動く部分だけコマごとに差しかえ、動かない所は全コマ1コマめとまったく同じにする（コマごとに本体がちがうと「うねうね」する）。作ったら、コマをかさねてちがいをたしかめる。もらった動く絵も同じ。
- ノブなどの小さな部品を、色で見分けた所だけで切り出さない（形がくずれる）。
- お手本（組み合わせた絵）とレイヤーの部品をもらったら、レイヤーをお手本にかさねて、部品ごとの大きさ・場所をはかる。ゲームはお手本と同じ大きさにし、できたらならべてくらべる。
- なめらかな絵をドット絵にするときの輪郭は2ドット：外がわは少し暗い色、内がわはまわりになじむ色。丸い物は、ちぢめてから少しぼかして切り、とがった1ドット・角を出さない。
- もらった絵の輪郭のむらは、あとで輪郭をぬりなおさない（はばが合わなくなる）。ちぢめるとき `tools/art/pixdown.py` を使い、のこった点は12倍で見て手でなおす（`FIX`）。ちぢめるのは BOX（`LANCZOS` などは、はしに明るい線が出て、つなぐとすきまに見える）。「トリミングしてそのまま」は、切りとるだけで、細かさ（1マス64ドット）も大きさもかえない。
- スキル：もらった絵をチップにするときは `chip-art`、ドット絵を描く・直す・仕上げるときは `pixel-craft`、新しく作る・評価する・「きれいにして」と言われたときは `pixel-manual`。いまあるチップを「ドット絵スキルで直して」と言われたら `pixel-redraw` の順番どおり。描きなおすのは、たのまれたチップだけ。
- チップを作りなおしたら、`chips.js` の `CHIPA` が指す `assets/chips/*.webp` が、ぜんぶコミットに入っているか（`git ls-tree`）たしかめる（わすれると多くのチップが出ない）。
- チップをけすだけのときは `python3 tools/chips.py remove <idの一覧.json>`（unpack・pack をしない。約30秒）。`pack` のページづくりは同時にする。
- チップの未使用の判定は、動的な名前（向き・接続・成長・開閉・表情）とフリーモード・古いセーブの読みかえも見る。消した一覧と理由は `tools/art/unused-chips.json`。
  - チップの絵をかえたPRでは工房も新しくする。工房は `index.json` と `g/<ジャンル>.json` だけ読む。Artifact の read で `index.json` と、かわったチップの `g/*.json` をおとし、`python3 tools/chips.py kobo <フォルダ> [id...]` で、かわった物だけ書きかえて、出たファイルだけ公開しなおす（ぜんぶの unpack はしない。とても時間がかかる）。
  - 名前（`index.json` の `names`）は `BL` の名前。新しい物を足したら `names` にも足す。
  - 「さしかえ」の `replace.json` は `python3 tools/chips.py replace replace.json` で入れる（WebP は method 2）。大きさがかわると w・h もかわり、ax・ay はそのまま。工房で調整した物（`meta`）は ax・ay をかえ、大きさは元の絵から BOX で作りなおす。
  - 「ゲームの中で」の見本（`gv/<id>.webp`）は、ゲームで置いて写した絵（`tools/gameview_boot.cjs`・`gameview_grid.py`）。チップの絵・大きさ・置き方をかえたら、写しなおして公開しなおす。一覧を `chips.js` にそろえるときは `python3 tools/chips.py kobo-sync <フォルダ> [names.json]`。

## 壁・柵の絵
- 壁・ドア・窓・塀・柵・生垣は、地図もアイコン・タイトル・設計図・足場のうすい形も、クォータービューの絵（`js/iso-conn.js` の `iqConnDraw`・`iqIconDraw`・`iqGhostDraw`）。前の正面の部品の絵（`<id>:H0`・`m5`・`~in`・`.window` など）はけした（`tools/art/unused-chips.json`）。新しく作らない・読みこまない。
- ダークチェリー（よぞらのベッドの木の色）：#522d1d・明るい所 #86552f・かげ #321f14。よぞらの家具・床・壁・ドア・窓はこの色。

## 絵の細かさ
- アイコン（`iconURL`）は2倍の細かさで描いて、144×144になめらかに入れる。ドットをとばす縮小・拡大（`imageSmoothingEnabled=false` で半ぱな倍率）は、がたがたになる。
- 地面・床・平らな物は、地面の下絵（1マス32ドット）にやきつける。g:64 の絵をそこに描くと荒く見えるので、くっきり見せたい物（ラグなど）は毎コマ画面の細かさで描く。床のもようは1ドットの線で。
- 床は、はしまで、すきま・線・段なしでつなげる：壁・ドアの下にのばす床は下絵に描く。上はしの「壁の下のかげ」も、のばした床につなげる（角で段にしない）。床や壁の見た目をかえたら、家の4つの角を6倍以上で見る。
- 壁の帯・巾木をマスごとにコードで描くときは、となりに0.5重ねる（ぴったりだと1.3倍・1.7倍などで、すきまの線が出る）。
- 見た目は6倍以上に加えて、ふだんの拡大率（1.3〜2.3倍）でも見る。

## 自然の物
- 岩（`rock`）の絵は、はば1.5マスくらい（持ち主のたのみ）。
- 自然物のチップ（木・森の木・りんごの木・枯れ木・ベリーの茂み・岩・大岩・きのこ・火山の木）は、トリポのモデル（`tools/art/nature3d/nature_prep.py`）から3Dで写す（`furn3d/items/nat_*.py`、共通 `natcommon.py`）。お手本は前のチップの絵。
  - 葉は、葉の玉を小さな葉の部品でおおう。幹は CC0 の木の皮（Bark001）を、のびる向きにすじが通るようにはる（まっすぐは `axis='z'`、枝わかれは `'screen'`。そのままはるとノイズになる）。
  - 枯れ木・草原の木・火山の木・ベリーの茂み・御神木のかげ（持ち主がきめた）：左上の光（`LIGHT`）。色は5つ（かげ2・もと・ハイライト2）と輪郭。色のさかいめだけ、はばの小さい市松のあみかけ（`tone5`、家具と同じ）。木は幹と葉を色でわけて2回かける。葉はつぶつぶをのこし、かげは青みのある緑、葉の下の幹は暗く。御神木の傷・切り口・光のつぶの色はかえない。
  - 枯れ木（草原）は、同じ3Dを0・45・180度まわした3まいをマスごとにえらび、半分は左右反対。
  - りんごの木の実ったときは、3Dの絵を作らず、ふつうの木の絵にりんごのアイコンをのせる（持ち主がきめた）。
  - 岩（`rock`・`rock#1〜#4`）は5とおりをマスごとにえらぶ（`chipOf`）：トリポの岩に、小さな岩を、よこの少しおくに置いて、手前の岩で1/4〜1/3かくす物が2つ（お手本：あつ森の岩）・前の形の岩だけが3つ。たてにちぢめない。大岩は、お手本と同じ大きさ・形に組む。
  - 草原の木（`tree`・`ntree`・`fruit`・`tree~aki`）は、クォータービューでも48度にせず、正面の見おろし4度のまま、まわさず・葉を上げずに写す（`iso3d.py` の `FRONT`。持ち主がきめた）。大きさ・置き方（`iso:1`）と落ち影はクォータービュー。
  - ほかの葉のある木は、クォータービュー（見おろし48度）では、葉の玉が幹をかくし、葉のはしが地面にとどいてうまって見えるので、クォータービューの絵だけ、葉を上げて幹の根もとを見せる（`natcommon.lift`）。
- 自然の物の光は太陽1つ（`natcommon.SUN`。持ち主がきめた）。モデルをまわした絵でも光はまわさない。
- 生き物の足もとのかげは、ドットのだ円（時間で向きと長さ）。はばは、そのコマの絵の下から30%の行のはし。小さな生き物は、高くとぶほど小さく・うすく。
- 3Dのモデルに、ポーズの前の場所で色をつけるときは `Part.paint`。`decal` だと、かたむけたコマで柄がずれる。
- 生き物のモデル（`animal_prep.py`）：目は左右同じ大きさのたいらな玉にかえ、2つとも `EYE` にする（部品の番号で目をほっぺにすると片目がピンクになる）。

## 時間の色・光
- 昼と夜の色は `js/daycolor.js` の `DAYC` 1か所。色をかえるときは、この表の数字だけを書きかえ、ほかに夜の色を書かない。
- 地面の層は物より先に画面ぜんたいにかけ算、物・がけの正面は夜の暗さだけ。屋根は形ぜんぶを1つにして1回だけかける（2回かけない）。高い段の上の面は `dcTop`。あかりは暗さをけずる（2つめの層）。
- 物ごと（チップごと）の色わけはしない（持ち主がきめた。スマホで重い）。
- 光の帯（`light-rays.js`）：晴れた朝・夕方と、月のある夜だけ。昼は出さない（持ち主がきめた）。

## 畑と作物の絵
- 花・木・作物・木の実が育つのは朝6時。植えた花・木の芽は、つぎの朝6時まで（`S.bud` と `isBud` は `callDay`。`dayNo` は夜中の0時でかわるので使わない）。
- 畑の土（`farm:0〜15`・ぬれた土 `farmw:0〜15`）は上下左右の16とおり。「大きな畑3×3・よこ1×3・たて3×1・1マス」をたのめば、そろう。1マスに畝1本、畝のまん中がマスのまん中。土の絵に草・芽を入れない（たのむときもそう書く）。
- 花・木の芽は `bud`、ハスは土のない `bud~w`。芽・土のもりあがり・作物は、土の下はしを畝のてっぺんにそろえる。芽は育ちはじめたら描かない。
- つやつやの作物：まいた印があって、朝に育ちきる前にかわいた印がない畑は、収穫+1・とれごろに光のつぶ。収穫の数を出す所・見る所にも `tsuyaOf` を入れる。

## クォータービューの地面（`js/iso-ground.js`）
- 高さ（持ち主がきめた）：1だんはマスの1辺の0.8（`IQL`・写す道具の `ISOH`）。光の向きは、ほんとうのカメラの角度（`ISOLIGHT`）。家の壁は2だん（`IQWALLH`・`iso_conn.py` の `WH`）、家のドアは1.4だん。ベッドは、はばも長さも1マスぴったり（かけぶとんのたれた所まで）。木箱・本棚・キャビネット・かざり棚・まき棚・流し台・調理台・作業台は、はば1マスぴったりで、うしろの面をマスのうしろのふちにつける。
- 地面は画面の向きの四角の区画（1ドット＝ゲームの1点、ひし形は64×48）。草地とあれ地・水と岸のさかいは、デュアルグリッドのオートタイル（角ごとに16とおり）。1ドットずつぼかす・ノイズでゆらす・色むらをかさねる作り方は、もうしない。
- ひし形の絵がとどくまでは、上から見た絵をドットのまん中の点で写す（まわして描かない）。地面の絵は、まうえから見たつながる面でたのむ（`tools/art/iso/ground-prompt.md`）。
- つながる物と屋根（`js/iso-conn.js`）：壁・ドア・窓・石の塀・柵・生垣は「まん中の柱＋となりへの腕」（左1・右2・上4・下8）。チップ `iso:<id>:<m>`（ドアは `h`・`v` と `#1〜3`、ひくい壁は `~low`、壁にかける物は `iso:win:<id>:<h|v>`。ax・ay はマスのまん中の地面の点）。
  - 1マスの中だけの箱で写し、奥から順にかさねる（となりにつづく向きは、まるめない平らなふたの面）。となりへのばしてマスで切ると、へこませた面がとなりのマスに入り、つなぎ目にすきまが出る。内がわの角は、角の手前でへこみをなくす。
  - まわりに輪郭線を引かない。下のだんの岩の絵は、上下がつながる形（`midtex`）。
  - まるみの半径は、出隅も入隅も0.2マス（持ち主がきめた）。入隅（L字の内がわの角）は、ひくいマスが、自分の列のあとに、そのだんの高さへ1まいの絵 `iso:blkf-<だん>:<角>-<A><B><C>` をかさねる（`build_fillet`・`icFils`。持ち主がえらんだ。4マスに分けると、となりの高さごとに絵がいり、チップが数千こになる）。まるいふちは、まわりのマスの角の上にもかかるが、上にだんがつづくマスの所へは出さない。
  - 南東の出隅は、岩の絵の列を、まわりの長さにそって南の面から東の面へつなぐ。ふちの地面の色の明るさは、向きでまぜて段にする（`rimk`。きりかえると、角にたての色の線・入隅に明るいかたまりが出た）。
  - てっぺんのふちは、まっすぐにしない：岩の絵の上の帯の明るさ（`toprof`）で、地面の色のさかいを上下させ、手前（南・東）のまるいふちを、われめで下げる。うしろ（北・西）のふちは下げない。
- 家具・建物・自然の物（`js/iso-obj.js`）：3Dの絵は、いまのチップと同じ名前で入れかえ `iso:1` をつける（反転しないので、向きは4つとも写す。ax・ay は置いたマスのまん中の地面の点）。

## 草地のふち・水面
- 種類のちがう道どうしがとなり合うときは、両方のふちに草のふちを出す。
- 草地とあれ地のさかいは、あつ森より（持ち主がきめた）：まるくやわらかい形のデュアルグリッド。水・高さのちがうマスは見ない。水のマスから草をはみ出させない・水の下に草をしかない。ふちはあぜ道・砂利道の草のふちと同じ（持ち主がきめた）：こい緑のふち・あれ地がわのかげはつけず、ふくらみととがった草の葉を、あれ地のほうへはみ出させる（`igGrassTiles`）。
- 水のふちに、となりの地面を鏡うつしにしない。水の下のすきまは、となりの陸の地面を、そのがわの半マスにしきつめる。あぜ道・砂利道は水につなげない（ふつうの道のはしと同じに丸く切り、草のふちも出す）。
- 水面は、水のテクスチャを毎コマゆっくりスクロール（`igShimmer`）。白いキラキラや、もようをゆらして重ねる方法は使わない。
- 池・川のふちはデュアルグリッドで丸める。水面は岸より一段ひくく見せる（すぐ上が陸なら、岸の断面）。岸の断面は、がけの絵（`cliff:block`）で、上のふちは岩の絵の上の帯の明るさに合わせて、われめに地面をたらす。岩は水の中へつづけ、水面の形（`q.w`）のうすさで水をすかして見せる。火山の水と雲の海はべつ。

## 道・床の絵

## 歩き・コードの絵・アイコン
- 歩く絵（`motions.py` の `walk`）はふつうの歩き方：足をついたすぐあとに体がいちばん下がり、すれちがうときに上がる。ついている足は地面をまっすぐうしろへ、うかせるのは前へふる足。体の上下は絵の中だけで、コードで絵ぜんたいを上下させない（2重になり、足とずれる）。コマは時計でなく歩いた道のりで進める（`WALKPT`。足ぶみの速さは持ち主がえらんだ数で、足が少しすべるのはそのまま。`WSTEP` は足の長さで無理のない所まで）。足ぶみは歩く速さの倍（床・にげる・レベル）でそのまま速くなるので、数をきめるときは、いちばん速い床でもたしかめる。
- 歩いているあいだは、よろこぶ・拍手・会話中でも、歩く向き・歩く動きのまま（`walking` のときは `clap`・`wv`・`facePlayer` にしない。場面の姿勢ものこさない）。
- コードで描く絵（そうびのアイコン・鉱脈など）はドット絵：16×16 などのマス目を整数の fillRect で。まるい線・なめらかな線・グラデーションは使わない。のばすときは imageSmoothingEnabled=false。色は明るくやわらかく、輪郭は中より少し暗い色（黒にしない）。
- 新しいドットのアイコンは、形（マスク）から2ドットのふちを作る（形をけずって引く）。
- 32×32のアイコン（そうび・料理・食べ物・宝・鉱石など）は `tools/art/icons32`（`game.py` で3倍の96×96を `ICONS` へ）。輪郭はまわり1ドット、色は1こ16色まで（`cap_colors` は広い所をくずすので使わない）。細長い物（矢）は45度ななめにしてからちぢめる。くずれる物は `hand.py` で手で描く。`ICONS` に絵があれば、コードの仮の絵より先に使う。

## 絵をたのむプロンプト
- もらった絵を使ってみて、うまく使えなかったときは、なにがだめだったかと、新しいプロンプトを作って報告する（毎回）。
- 絵をたのむためのプロンプトは、1つにまとめて書く。分けるときは、共通の事項（絵のかき方・背景・向きなど）をそれぞれに書いて、1つだけで使えるようにする。
- 3Dのモデリングとテクスチャ（家具・建物・生き物・コワイノ・せいれい・柵・塀・ドア）も、ドット絵に写すのも、Claude がする（持ち主がきめた。GPT にはたのまない）。`handoff/`・`AGENTS.md` は前のやりとりとしてのこしてある。作る物の一覧・大きさ・名前・置き方は、そこを見てよい。
- 3Dモデル（トリポ）をたのむプロンプトも、いつも1つにまとめる（何こあっても1つのモデルにならべてたのみ、`tripo_split.py` で切りわける。持ち主がきめた）。1こずつは短く書く。
- お手本のキューブ（`tools/art/ref/view-cube.png`）をいっしょにわたし、`view-cube-prompt.md` の文を入れて、見おろしの角度と高さの比（1マスの高さ＝正面0.8マス）をそろえる。高さのない平らな物（地面・草地・床・道のテクスチャなど）には、キューブも、その文もつけない（マス目やキューブを描きこまれる）。
- ななめになってはいけない物（灯籠・ランプ・柱・家具など）は「まっすぐ立てる・かたむけない」をはっきり書く（upright, perfectly vertical, not tilted など）。
- できあがりのドット数（「〇×〇 pixels」など）を書かない。大きくかいてもらい、こちらで BOX でちぢめる。
- どれにもかならず「輪郭線はうすく・細く」を書く（例：no thick or dark outlines; if an outline is used, it is a thin 1-pixel line only slightly darker than the color next to it, never black or near-black）。「ざらざらしたノイズを入れない」も書く（clean flat colors with soft shading; no noise, no grain, no speckles, no dithering, no gritty texture）。
- 色は明るくやわらかく。窓ガラスなどは濃くなりやすいので、うすい色をはっきり書く（pale, light, soft colors; no dark or heavily saturated colors など）。

## 手順のまとめ（細かい作り方は道具のコードを見る）
- マップチップ工房：チップの絵をかえたPRでは、工房も新しくする（`python3 tools/chips.py kobo <フォルダ> [id...]`・`replace`・`kobo-sync`。かわった物だけ。ぜんぶの unpack はしない）。新しい物は `index.json` の `names` にも足す。
- 屋根は3Dで組んだタイルセットのチップをえらんで置くだけ（コードで屋根を描かない・ドットごとにかさねたり色をかけたりしない。持ち主がきめた）。部品の決め方は道具（`iso_roof.py` の `cells`・`pick`）とゲーム（`iqRoofCells`・`iqRPick`）で同じにする。
- 土のブロックのだんは角の形ごとのタイルセット（`iso_block.py`）。1マスの中だけの箱で写し、まわりに輪郭線を引かない。
- マスごとにかさねる絵（土のだんの上の面など）：地面は、ひし形より少しひろく写して、かたちで切る（ぴったりで切ると、ふちがうすくなり筋）。上にかさねる色（明るさ・時間の色）は、ひし形の中だけ（片がわのふちだけふくむ）にする（となりとかさなると、さかいめだけ2回ぬられて筋）。
- 高い段のマスの描く順（`icBlkDD`）は、うしろのマスの物・せいれいより後、そのマスの上の物より先。高い段のマスの上に足す物の奥行きは、`icBlkDD` からはかる（`x+y` の数をじかに書かない）。
- 柵・塀・ドア・門・生垣は3Dで写す（`tools/art/fence3d/`）。見え方は家具の38度でなくゲームのマスと同じ（`oblique3d.game`）。つなぎ方16とおりを、そのマスの中の物だけで組む。竹の壁は火山だけ（`STAGEONLY`）。
- `iso:1` の絵は、`translate`・`rotate`・`scale` がきかない（`isoLocal` を使う）。向きは `isoFace` を通す。写す道具は `tools/art/iso/iso3d.py`。
- 草原の木（`tree`・`ntree`・`fruit`）は、クォータービューでも正面の見おろし4度のまま、まわさず・葉を上げずに写す（`FRONT`。持ち主がきめた）。ほかの葉のある木だけ、葉を上げて幹の根もとを見せる（`natcommon.lift`）。
- 落ち影（`castshadow.py`）は、根もとの高さの平面に太陽から影を落とし、同じカメラで写す（けずる・切る・ずらして合わせない）。自然の物の絵をかえたら影も作りなおす。
- 水面・道・床のテクスチャは、もとの絵（`tools/art/ground/src`）から道具で作る（チップをじかに直さない）。水は毎コマゆっくりスクロール。白いキラキラは使わない。
