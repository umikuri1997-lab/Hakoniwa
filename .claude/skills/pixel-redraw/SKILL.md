# チップを、ドット絵の決まりに合わせて描きなおす

考え方は `pixel-manual`・`pixel-craft`、ゲームの決まりは `CLAUDE.md`（ぶつかったら `CLAUDE.md`）。ここは **やる順番と、合格のめやす** だけ。順番をとばさない。目で見る前に、かならず数字で見る。

お手本は2つ。新しく描くときは、形のにているほうをまねて書く（1から自分で組み立てない）。
- 四角い物（板・箱・台）：食卓 `tools/art/table/table_art.py`（`board` の1行）
- いくつかをまとめて（向きの絵・丸い台と足・板をならべた箱）：`tools/art/wood1/wood1_art.py`（ローテーブル・ベンチ・まるいサイドテーブル・木箱）
- 丸い物（丸い座面・丸い台・たる）：スツール `tools/art/examples/round_stool.py`（絵を書き出すだけのお手本）

## 0. はじめる前に
- **この手順が向いている物**：形のかんたんな物（板・箱・台・丸い座面・脚のある家具）。食卓・スツールくらいの細かさの物は、だれが描いても同じ品質になる（Sonnet でためした）。
- **向いていない物**：部品やもようの多い物（たる＝ふたのふち・板のさかい・鉄の輪、食べ物ののった台、木・花・せいれい・コワイノ）。コードで描きなおすと、数字のめやすは通っても、前の絵より細かさがへって、さびしい絵になる（Sonnet で たるをためして、そうなった）。こういう物をたのまれたら、描きはじめる前に、えらべるボタンで聞く（「かんたんな絵になるが、描きなおす」「もとの絵から `chip-art`・`pixdown` で作りなおす」「やめる」）。
- 描きなおすのは、**持ち主にたのまれたチップだけ**。もらった絵から作ったチップは、`CLAUDE.md` に「もらった絵の透過と色をそのまま・色の数をへらさない」とある。たのまれていないチップを、かってに描きなおさない。
- どのチップか、名前が2つ以上考えられるときは、えらべるボタンで聞く。
- **大きさ（w・h）と置き方（ax・ay）は、かえない。** 絵のある所（x・y のはんい）も、前の絵と同じにする。
- 向きの絵（`id>1` など）・コマ（`#0〜`）・部品があるチップは、ぜんぶ同じ色・同じ輪郭で描く。動く絵は、動かない所をぜんぶのコマで同じ絵にする。

## 進め方（持ち主に見せながら）
- 家具は、にた物を4つくらいずつまとめて描く（1つのスクリプトに `run({id: 描く関数, …})`。向きの絵 `id>1` も入れる）。
- **チップに入れる前に、前とあとをならべた絵（5倍）を持ち主に送って、えらべるボタンで聞く**（「このまま入れる」「〇〇を直してから入れる」「まだ直す」）。直す所を言われたら、そこだけ直して、もう一度見せる。「入れる」と言われるまで、チップに入れない。
- 持ち主から、これまでに言われた直し（つぎからは、はじめからこうする）：
  - 板の台（ベンチ・ローテーブル）は、上の面の手前の左右の角と、正面の下の角を丸くする（`board` の `fcorner=(3, 2, 1)`・`bottom=(3, 2, 1)`）。角ばったままにしない。
  - 丸い天板の下の台・足は、台形や、とがった角にしない。前の絵と同じ部品（丸い棒の足・丸くすぼまる台）にする。
  - 部品を、こい線の四角でかこまない（木箱のかど金）。前の絵で、まわりになじんでいた部品は、なじむ色で。
  - すじかい・棒の太さは、前の絵と同じに（細くしない）。

## 1. いまの絵を、数字でしらべる
```
python3 tools/art/chipcheck.py <id> <となりに置かれる物の id...> --out <作業フォルダ>/before
```
- `<id>.png`（前の絵。あとで見くらべに使う）と `<id>_x8.png`（8倍）が出る。8倍の絵を Read で見る。
- 出た数字を、そのまま報告の「前」に使う（色の数・半透明・輪郭が2ドット以上の所・孤立ドット・にた色）。
- 「絵のある所 x・y」は、うすさが半分より上のドットのはんい。前の絵のふちが半透明でも、この数字に合わせる。
- 「色の一覧」は、多い順の12色。描きなおす色は、ここからえらぶ（いちばん多い色が、いちばん広い面の基本の色）。
- 「形（行ごとの左はし・右はし）」を読む。例 `6 4 3x2 2x31 3 4 6x15 7` は、上から、左はしが 6、4、3が2行、2が31行…という意味。**前の絵の形（どの行からどの行までが、何の部分か）を、ここから書き出す。**

## 2. 設計を、文で書く（描く前に）
つぎの5つを、スクリプトのコメントに書く。書けないうちは描かない。
1. **部分**：大きな形を、四角・板・脚などに分ける。それぞれの x・y のはんい（前の絵の数字から）。
2. **光**：左上から。上を向く面がいちばん明るい → 正面 → かげ。
3. **色**：素材1つにつき、**基本・かげ・光の3色**と、輪郭1色、輪郭の内がわのなじむ色1色。ぜんぶで16色まで（素材が1つなら12色まで）。色は、前の絵のいちばん多い色からとる（新しい色を思いつきで作らない）。役目のちがう所でも、にた色（差が10より小さい）は、同じ色を使いまわす。
4. **輪郭**：外がわ1ドット（その面より少し暗い色。黒にしない）。上の面は、その内がわに、なじむ色を1ドット（`inner`）。
5. **質感**：木目は板の長いほうの向きの短い線を2〜3本。石は割れ目を1〜2本。点（1ドット）を置かない。

きまった数字：
- **丸い物は、角の段ではなく、だ円で描く。行ごとの左はしの表を、自分の手で書かない（八角形になる）。**
  - 丸い板（上の面＋厚み）：`p.round_top(x0,y0,x1,y1, thick, top, side, line_top, line_side, lip, side_shade)`。x0〜y1 は上の面のだ円、thick は厚みのドット。
  - 丸いだけの形：`p.oval(x0,y0,x1,y1, fill, line)`。
  - 前の絵の形（`rows_from`）は、丸い物には使わない（前の絵のがたがたまで写る）。だ円の x0・x1・y0 は、1 の「絵のある所」と「形」の数字からきめる。
- 重なる部品は、**うしろの物から先に描く**（スツール：脚 → 座面）。上の物が落とすかげは `p.drop_shadow(上の物の輪郭の色, (下の物の色…), かげの色, n=2)`。
- となり合う部品の輪郭は、同じ色にする（色がちがうと、さかいが2ドットの線になる）。上の面と正面が同じ色のときは、上の面の輪郭を暗いほうの色にして、さかいを見せる。
- 食卓の色にない素材（鉄・布・石）は、1 の「色の一覧」からその素材の色を1つとり、基本にする。かげは、その色の明るさを0.85倍、光は1.12倍にした色（色あいはかえない）。
- 同じ木の家具は、食卓と同じ8色を使いまわす：`from pixdraw import OT, OD, TB, TS, TI, LIP, AB, AS, LL`（色の表を、自分で書かない）。
- 角の段：大きな板・箱の上の角は、上の行から **4・2・1・1** ドットのへこみ。下の角は **2・1**。小さい部品（はば12より小さい）は 1 だけ。
- 脚・柱：`p.leg(x0,y0,x1,y1, base, light, shade, line)`。はばは前の絵と同じ（7〜10）。左2ドットが光、右2ドットがかげ、上2行が、上の物の落とすかげ。下のはしは輪郭1ドット。ななめの脚は、まっすぐの脚にしてよい。
- 上の面と正面のさかい：上の面のいちばん手前の行を、光の色1行にする。
- 物の下に、地面のかげは描かない。

## 3. 描く（`tools/art/pixdraw.py`）
`tools/art/<id>/<id>_art.py` を作る（食卓をまねる）。使う物は、これだけ：
- `Pix(w, h)`・`slab(x0,y0,x1,y1, fill, line, top=(4,2,1,1), bottom=(2,1), line_rows={行:色})`（角が段々の板と輪郭）
- `rect`・`hl`（よこ線）・`vl`（たて線）・`dot`・`clear`
- `board(x0,y0,x1,y1, front, legs, leg_w, leg_bottom, grain / vgrain, bottom, fcorner)`（木の板の台：上の面・正面・脚・木目・輪郭の内がわまで、1行で）
- `round_top(...)`（丸い板）・`leg(...)`（脚）・`drop_shadow(...)`（落ちるかげ）
- `oval(x0,y0,x1,y1, fill, line)`（だ円）・`shape(rows, fill, line)`（行ごとの左はし・右はしの表 `{y:(x0,x1)}` の形）・`oval_rows(...)`・`rows_from(png, y0, y1)`（絵の形から表をとる）
- `inner(base, line, c, sides='ULR')`（輪郭のとなりのドットを、なじむ色に。丸い形でも、とぎれない帯になる）
- `run({id: 描く関数})`（スクリプトのおわりに書く。引数にフォルダがあれば `<id>.png` を書き出すだけ、なければ、まとめてチップに入れる。アトラスの作りなおしは1回）・`save(png)`・`put(id)`
- **4 が通って、持ち主が「入れる」と言うまでは、かならず出力のフォルダ（`put` を使うスクリプトは png のパス）をわたして動かす。**

描く順番（コードも、この順に書く）：**1 シルエット → 2 大きな面 → 3 かげと光 → 4 質感 → 5 小さな部品**。

## 4. できた絵を、数字でしらべる（チップに入れる前）
```
python3 tools/art/<id>/<id>_art.py <作業フォルダ>/new.png
python3 tools/art/chipcheck.py --png <作業フォルダ>/new.png
python3 tools/art/chipcheck.py --cmp <作業フォルダ>/before/<id>.png <作業フォルダ>/new.png <作業フォルダ>/cmp.png <となりの物の id...>
```
**合格のめやす（ぜんぶ通るまで、3 にもどる）：**
| しらべる物 | めやす |
|---|---|
| 色の数 | 16色まで |
| 半透明 | 0 |
| にた色 | 0組 |
| 輪郭が2ドット以上の所 | 0（NG のときは、出た x,y の所を直す） |
| 孤立ドット | 0。NG が孤立ドットだけで、ぜんぶがわざと置いた点（びょう・目・光）なら合格。その点の x,y を報告に書く |
| 形 | 絵のある所の x・y が、前の絵と同じ。1つの部分の中で、左右のはしの数字が、行ったり来たりしない（丸い物は、へって、ふえるの1回だけ） |
| 形の重なり（`--cmp` の出力の「形の重なり」） | 90%より上。90〜95%のときは、どこを・なぜかえたか（ななめの脚をまっすぐに、など）を報告に書く |

そのあと `cmp.png` を Read で見て（数字を直したあとの、さいごの絵を、かならず見る）、つぎを **1つずつ、はい・いいえで** 答える。いいえが1つでもあれば、3 にもどる。
1. 前の絵と同じ物に見えるか（形・大きさ・色あい）。丸い物が、角ばって見えないか。脚・柱の太さが、前の絵と同じか。
2. 下にならべた、となりの物（2倍）とくらべて、明るさ・輪郭のこさ・細かさがそろっているか。
3. 上の面・正面・脚の3つの明るさが、見分けられるか。
4. 木目・もようが、ひっかききず・よごれに見えないか（見えたら、本数をへらす・色の差を小さくする）。
5. 前の絵にあった部品（ふち・板のさかい・金具・取っ手など）が、ぜんぶのこっているか。へった部品があるなら、チップに入れずに、なにがへったかを持ち主に見せて聞く。

## 5. チップに入れて、ゲームの中で見る
```
python3 tools/art/<id>/<id>_art.py            # チップに入れる
rm -rf tools/__pycache__ tools/art/__pycache__ tools/art/<id>/__pycache__
wc -c chips.js                                # index.html の E のはじめの数字を、この数に書きかえる
node tools/art/chipview.cjs <作業フォルダ>/cv <id> <となりの物の id...>
```
- `view_3.png`・`view_2.png`・`view_1.3.png` を Read で見る。「エラーなし」と出ること。
- 見ること：マスからはみ出していないか・となりの物とそろっているか・1.3倍でも何か分かるか。

## 6. マップチップ工房・PR
1. `js/main.js` の `APP_VER` を、つぎのPRの番号に。`for f in js/*.js chips.js; do node --check "$f" || echo "$f"; done`。
2. 工房（`CLAUDE.md` の工房の決まり）：Artifact の read で `index.json` と、そのチップのある `g/*.json` と `index.html` をおとす → `python3 tools/chips.py kobo <おとしたフォルダ> <id>` → `python3 tools/gameview_grid.py <作業フォルダ>/cv/gv <作業フォルダ>/gvout <作業フォルダ>/cv/gameinfo.json` → `index.json`・かわった `g/*.json`・`gv/<id>.webp` を公開しなおす。
3. 最新の `main` からのブランチで、PRを作ってマージする。

## 7. 報告（この形で）
- 直した所の表：輪郭・形・色の数・半透明・質感の「前 → あと」（1 と 4 の数字）。
- たしかめたこと：`node --check`・ゲームで写した倍率・エラーのあるなし・工房。
- たしかめていないこと：スマホの実機など。
- うまくいかなかった所があれば、なにがだめだったか。

## やってはいけないこと
- 絵をぼかす・なめらかにちぢめる・色を自動でへらす処理で直す（ドットのますめがくずれる）。1ドットずつ、役目のある色を置く。
- 数字のめやすが通らないまま、チップに入れる。
- 8倍の絵だけで決める（ゲームの中の 1.3倍・2倍も見る）。
- 大きさ・置き方・ゲームのコードを、たのまれていないのにかえる。
