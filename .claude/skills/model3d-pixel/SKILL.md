# 3Dモデル → ドット絵

ゲームの決まりは `CLAUDE.md`（ぶつかったら `CLAUDE.md` が先）。ドット絵の考え方は `pixel-manual`・`pixel-craft`。
3Dを「AIに絵をたのむためのお手本」にするやり方は `chip-art` の「3Dのお手本から絵をたのむ」。ここは、**3Dをそのままドット絵に写す** やり方。

家具は、家具ごとの設計図 `tools/art/furn3d/items/<id>.py` と、共通の写す道具 `tools/art/furn3d/furn3d.py` で作る。新しい家具は、にた形のお手本をまねて書く（1から組み立てない）。
- 箱・わく・すじかい・ふたの開く絵：木箱 `tools/art/crate3d/`（ふたのような動く部品があるので、べつのスクリプト）
- 脚と座面・背もたれ・4つの向き・せいれいの手前にかさねる絵（`.front`）：いす `items/chair.py`
- 天板と脚・幕板：食卓 `items/table.py`
- 2×2マスの家具・板をならべた天板：大きな食卓 `items/dtable.py`
- 小物をお手本の絵と同じならびで置く・モデルの色をかえる（`p.recol`）・ねかせた本：かざり棚 `items/shelf2.py`。とびら（わく・鏡板・つまみ）：キャビネット `items/cabinet.py`。まき（`logy`：皮の色と切り口 `LOGEND`）：まき棚 `items/makidana.py`。壁にかける物：かべ棚 `items/wshelf.py`
- 布でつつんだ物（角も上下のふちも4分の1の円で丸める `common.soft`・背もたれを反らせる `lean`）：ひとりがけソファ `items/sofa1.py`・ひじかけいす `items/achair.py`。いまの絵と同じ大きさにするときは、いまの絵の大きさ（ドット）から寸法をきめる（たて1マス≒61ドット・おく1マス≒55ドット）。
- ふとん・まくら（高さの面）：ベッド `items/bed.py`。なだらかな砂：砂場 `items/sandbox.py`。すける水：水おけ `items/tub.py`。
- まるい座面（`cyl`、`plainwall`）：スツール `items/stool.py`。2×1マス・4つの向き：ベンチ `items/bench.py`
- 棚と中の小物（本）・3つの向き（前・右・左）：本棚 `items/shelf1.py`
- 丸い物（ふくらんだ板・鉄の輪・丸いふた）：たる `items/taru.py`（`EXTRA(sc)` で三角形を組む）
- 色は `items/common.py`（明るい木の色・鉄・本の色）。

```bash
python3 tools/art/furn3d/furn3d.py <id> <出力フォルダ>            # 絵・設計図・いまのチップとならべた絵（cmp_x4.png）を書き出す
python3 tools/art/furn3d/furn3d.py <id> <出力フォルダ> --chips    # ゲームのチップにも入れる
python3 tools/art/crate3d/crate3d.py <出力フォルダ> [--chips]       # 木箱
```

設計図（`items/<id>.py`）に書く物：`ID`・`PARTS()`（部品の表。木目をはらない部品は `notex(p)`）・`EXTRA(sc)`（表で書けない形）・`VIEWS`（チップの名前と、まわす数 k：0前・1右・2後ろ・3左）・`BOTTOM`（絵の下のはし。いまのチップの `ay+h` に合わせる）・`FRONT`（せいれいの手前にかさねる絵の名前と、その部品の名前を見る関数）。

## 0b. 作りなおすときの進め方（持ち主にきまったこと）
- 見え方は、どの家具も同じ：見おろし42度・左右は平行で奥行きだけ遠近（画角10度・1マスぶん）。`furn3d.py` の `ELEV・FOV・FRAME`。
- 大きさは、いまのチップの大きさ（w・h）に近くなるように、寸法を直す（はじめの寸法は大きくなりがち。上の面が深く見えるので、おくゆきは小さめに）。
- **にた家具を4つずつ作り、いまの絵とならべた絵（`cmp_x4.png`、4つをたてにならべる）を送って、えらべるボタンで聞く**（「入れる」「〇〇を直して」）。「入れる」と言われるまで `--chips` しない。
- 向きの絵は、いまのチップにある名前（`ROTS`）に合わせる。`ROTS` の 3（前・右・左）の左は、反転でなく `id>2` に写す（`chipOf` は `id>向き` があればそれを使う）。いまある `.front`（せいれいの手前にかさねる絵）も、同じ名前で作る。
- 形が自由な物（植物・布・ぬいぐるみ・像・炎）は、作る前にえらべるボタンで聞く。

## 0. はじめる前に
- **向いている物**：材を組んでできた物（箱・台・棚・柵・小屋・はしご・すじかいのある物）。木目などのテクスチャがはれる物。
- **向いていない物**：形が自由な物（木・花・岩・せいれい・コワイノ・布）。こういう物をたのまれたら、えらべるボタンで聞く（「3Dで、かんたんな形で作る」「`chip-art` で絵をたのむ」「やめる」）。
- いまある物を作りなおすときは、いまのチップの大きさ・置き方・絵のある所をはかってから組む（`python3 tools/art/chipcheck.py <id> --out <フォルダ>`）。はば・高さ・おくゆきを、いまの絵に合わせる。
- ゲームのチップに入れるのは、持ち主が「入れる」と言ってから。入れる手順は `chip-art`・`pixel-redraw`（大きさ・置き方をかえない、工房も新しくする）。

## 1. 設計図を書く（部品の表）
`tools/art/<物>3d/<物>_parts.py` に、`blueprint.Part` で部品の表を書く。数字はマス（x=東・y=南・z=上、置くマスの左上が(0,0)）。

- **どの3Dも、まず、じっさいに作れる設計図を考えてから組む**。部品ごとの形・寸法・何にのるか・どこでとめるかを、設計図のファイルのはじめに短く書いてから、その数字で `PARTS()` を書く（例 `items/dtable.py`）。同じ物がならぶ所（天板の板・本棚の段など）は、同じ寸法にする（はしの板だけすきまの分ちがう、などにしない）。
- **ほんとうに作れる組み方にする**。部品ごとに、何にのる・何にとめるか（`on=`）と、とめ方（`note=`）を書く。`check(L)` が空（まちがいなし）になるまで直す。
- 実物の作り方をまねる。木箱なら：底板 → 四すみの柱 → 柱のあいだに側板 → 側板の外に横桟（わく）→ わくの中にすじかい → ふた板 → ふたの桟。
- **交わる材**：1本は通し、もう1本は2つに分けて、はしを通しの材のふちにそって切り、つきあてる（`prism`：正面の形の多角形を、おくゆきへのばした板）。ふつうの板（`box`・`plate`）は直角にしか切れないので、交わる所で、うしろの材の面が三角にはみ出す。
- **同じ面にそろえた材**（すじかいの3本など）は、おくゆきもぴったりそろえ、`grp='名前'` で同じグループにする（そのあいだに輪郭線を引かない）。ゆるい角度のつき目の線は、ドット絵では、とびとびの点になる。
- **部品の面をぴったり同じ所にかさねない**（どちらが手前かがきまらず、ざらざらになる）。うしろにする部品は 0.002〜0.003 マスさげる。
- 角の面取り（`bevel`）は0にする（ドット絵では、面取りのかげが1ドットずつのこって、孤立ドットになる）。
- 材が面から出る長さは、上の面が1ドット（1/64マス）くらいになるように。すじかいは 0.017 マスくらい。2ドット以上だと、ななめの材の上の面と輪郭線がかさなって、ごちゃっと見える。
- 色は、ゲームのほかの絵に合わせた明るくやわらかい色。**木材は、どの部品も同じ色（`common.py` の `WOOD`）**（持ち主がきめた。わく・脚・背板・中の板などで木の色をかえない）。板の見分けは、テクスチャと輪郭線・かげでつける。

## 2. 3Dに組んで、ドット絵に写す
```python
import oblique3d as O
from blueprint import build, blueprint, check
sc = O.Scene(); sc.texture(O.Tex('tools/art/textures/wood049.png')); build(sc, L)
O.S = 64; im = O.render_px(sc, O.game, ext, O.VIEW, k=0.72)   # 1マス64ドット、ちぢめない
```
- **1マス64ドットで、ちぢめずに写す**（`render_px`）。大きく写して `pixdown.py` でちぢめると、輪郭線がにじんだり、かたがわだけになったりする。
- `ext` は、置く範囲のまわりに2ドット（2/64マス）あける（外の輪郭が入るように）。
- 輪郭線は `render_px` が引く：部品のさかいの、うしろがわのドットに1ドット。まわりは外がわに1ドット。色はそのドットの色×k（0.72。黒にしない）。線を引かない部品は `sc.outline(0)` のあとに足す（中の暗い所など）。
- **裏面法の輪郭線（`render` の `out`）は、ドット絵には使わない**（線の太さがそろわず、交わる所がよごれる）。
- 3Dのたしかめに、1マス512ドットでも写す（`O.S=512`）。交わる所・つきあて・かくれる面が、ほんとうの物と同じかを、大きな絵で見る。

## 2b. 向き・動く絵
- 向きのある家具（`ROTS` の 4：前・右・後ろ・左、チップ `id`・`id>1`・`id>2`・`id>3`）は、**1つの3Dを `sc.turn(k, 床の範囲)` で90度ずつまわして写す**（向きごとに組みなおさない・反転でごまかさない）。光はどの向きでも同じ左上から。
- 4つの面を、ほんとうの物と同じに作る（前だけ作りこむと、うしろ・横の向きで板だけになる）。横の面の材は `prism(..., 'x')`。
- 動く部品（ふた・とびら）は、部品の pid を覚えておき、軸のまわりに頂点をまわして、角度ごとに写す（お手本：木箱のふた `LIDANG`）。コマは `<id>#o1` のようなべつのチップにして、ゲームで状態に合わせてえらぶ（`crateLid`）。開くと絵の大きさがかわるので、ay は地面（置くマスの手前のはし）の行でそろえる。
- 開けると見える中は、うすい暗い板（`中のかげ`、輪郭線なし）をはって、箱の中らしく暗くする。
- ゲームに入れるのは、写すスクリプトの `--chips`（`chips.load_imgs`・`pack_imgs`、`.chips_changed` に id を書く）。そのあと `chip-art` のとおり、マップチップ工房も新しくする。

## 2c. 見おろしの角度・奥行きの遠近
- `O.persp(elev, fov, frame)` で、見おろしの角度（ゲームのほかの絵は51.34度）と、奥行きだけの遠近（左右は平行のまま。frame は画角に入れる上下の範囲（マス）、None で遠近なし）をえらべる。`render_px(sc, proj, ext, depth)` にそのままわたす。
- 遠近の写し方は、ドットごとに、見える面の場所を式でとく（`proj.ray`）。三角形を細かく分けて写すやり方は、とても重いので使わない。
- ほかの絵とならべるとちぢみ方がちがうので、ゲームに入れる前に、えらべるボタンで聞く。

## 3. 木目などのテクスチャ
- テクスチャは CC0 の物だけ。`tools/art/textures/` に入れ、出どころ・ライセンス・とってきた所を `README.md` に書く。いまあるのは `wood049.png`（ambientCG、横むきの木目）。
- 新しく取ってくるとき：ambientcg.com・polyhaven は、ネットの制限で直接とれない。GitHub の写しを、`raw.githubusercontent.com` で取る（さがすのは `gh api -X GET search/code -f q='ambientCG <名前> CC0'`）。
  - 中身が `version https://git-lfs...` の目じるしだけなら、`media.githubusercontent.com/media/<owner>/<repo>/<branch>/<path>` から取り、sha256 が目じるしの oid と同じかたしかめる。
  - 色・明るさに手が加わった写し（LICENSE に「saturation reduced」などとある物）は使わない。
- `O.Tex(path, span=2.0, flow=10, minrun=4)`：部品ののびる向き（いちばん長い向き）にそって、明るさのちがいだけを3だんでつける。色は部品の色のまま。
  - そのままはると、ドット絵では、すじでなく、点のぶつぶつになる。木の流れる向きになめらかにし（`flow`）、短い点を消す（`minrun`）。
  - 輪郭線の色は、木目をつける前の色から作る（木目ごとに線の色がわかれない）。
- 部品ごとに木目の場所をずらすので、板ごとにちがう木目になる。

## 4. 数字でたしかめる
```bash
python3 tools/art/chipcheck.py --png <出力>/<物>.png
```
- めやす：色の数16まで・半透明0・にた色0組・輪郭が2ドット以上の所0。`render_px` は、さいごに、にた色（差12より小さい）を多いほうの色にまとめる（`merge`）。
- 孤立ドットは、すじかいの交わる所・柱のふちに、のこりやすい。数と場所を持ち主に伝える（チップにするなら、`pixel-redraw` の手順で手で直す）。
- 10倍の絵（`<物>_x10.png`）で、交わる所・つき目・木目が、すじに見えるかを見る。

## 5. 持ち主に見せる
- いまのチップとならべた絵（4〜5倍）・10倍の絵・設計図を送る（`SendUserFile`）。
- 返事には、組み方・数字の結果（色・孤立ドットなど）・のこっている所・ゲームに置いて見ていないこと、を書く。
- ゲームに入れるかは、えらべるボタンで聞く（「このまま入れる」「〇〇を直してから入れる」「まだ直す」）。

## よくある失敗（木箱・たるでおきたこと）
- 部品と部品のあいだに、3ドットより細いすきま（三日月の形など）があると、2ドットの輪郭線が何本も入って、くずれて見える（たるの、上のふちと鉄の輪のあいだ）。部品の場所をずらして、細いすきまを作らない（たるの上の輪は、口のすぐ下）。
- 2ドットの輪郭線は、さかい目から3ドットより細い部品（いすの柱など）には、2ドットめを引かない（`render_px` が自動で1ドットにする）。細い部品に2ドット引くと、部品の半分が線になって、たてじまにくずれる。
- つづいている1まいの板の、べつの部品どうし（たるのふちとたる板）は、`sc.tag`・`join` で線を引かない。
- まるい天板・座面（`cyl`）は、天板の上の面とまわりのかべのさかいに線を引くと、ぎざぎざの歯のようになる → `grp` を同じにして線を引かない。まわりのかべに木目をはると、たてのぶつぶつのすじになる → `plainwall=True`（木目は上の面だけ）。かどの数（`detail`）は64。
- まるいテーブルは、見おろし42度では、上の面がほとんど丸に見え、まん中の柱・足が天板にかくれる（持ち主はなくすことにした）。足は天板より外までひらかないと見えない。
- 大きな天板（2×2の食卓）を1まいの板にすると、木目がななめに流れて見える → よこにのびる板を何まいかならべる（そとの角だけ丸める）。
- 見おろしの角度では、上の棚板が、下の段の小物をかくす。小物を見せる棚は、棚板をあさく（おく0.28）、段のあいだを広く（0.43）する。
- お手本の絵にある小物（つぼの色・ならび・本のつみ方）や、ささえなどの見える部品は、お手本と同じにする（下から見えないささえは、見おろしでは見えない：お手本で見えている所に、見える形で作る）。
- 2×1 の物（ベンチ・砂場）をたてにした向きは、ゲームでは置いたマスから下へのびる。設計図に `SZ=(2,1)` を書く（`furn3d.py` が、たての向きを1マス下へずらす）。書かないと、たての絵が1マス上にずれる（ベンチでおきた）。
- なだらかな面（砂・まくら）は、ふつうの3だんのかげでは、ほとんど光の色だけになる。`p.soft`（`material('soft')`：さかい目の向きを光に近くする）、まくらのように、かげをごくうすくしたい物は、場所ごとの色でかげを入れて `material('flat')`。
- 水は `material('clear')`：ほかをぜんぶ描いてから、`CLEARA` のこさでかさねる（底やかべがすけて見える）。光のすじ（白い線）は絵として入れない（持ち主がだめと言った）。つやはマテリアルで：水面に小さなさざなみ（高さの面）を作ると、光と目のあいだを向く山が白く光る（`CLEARSPEC`）。おくのほうを空の色に近くして、うつりこみにする。
- 高さの面（`common.hfield`）：なだらかな砂・まくら・たれるかけぶとんを、高さの式で組む（上と下の面、まわりはふちでとじる。色は場所ごとにもできる）。
- ふとんは、ほんものの重なりで組む：マットレス（しきシーツ）→ うわシーツ → かけぶとん（うすく、マットレスのふちで丸くまがって、左右と足もとへ少しはみ出してたれる。角は両がわへたれるので下までさがる）→ うわシーツを、かけぶとんの頭のはしで折り返す（うすく）。あつすぎ・大きすぎにしない。
（木箱でおきたこと）
- 大きく写して `pixdown.py` でちぢめた → 輪郭線がにじみ、かたがわだけ・色が124色。→ 64ドットで直接写す。
- 裏面法の輪郭線 → ななめの材の下に太い線が出て、かげのように見えた。→ `render_px`。
- すじかいの交わる所を、直角に切った板でかさねた → うしろのすじかいの上の面が三角にはみ出した。→ `prism` でふちにそって切る。
- つき目に線を引いた → ゆるい角度の線が、とびとびの点になった。→ `grp` で線を引かない。
- 木目をそのままはった → 点のぶつぶつ・40色。→ `Tex` の `flow`・`minrun`、線は木目の前の色、板の色をそろえる → 14色。
- テクスチャを取ってきたら、Git LFS の目じるしだけだった → `media.githubusercontent.com` から取り、sha256 をたしかめる。
