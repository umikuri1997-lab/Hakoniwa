# リアルな植物3Dモデル生成

## 目的

実在の植物の特徴を再現した、立体として自然な3Dモデルを制作する。正面だけ似せるのではなく、全方向から観察しても成立する構造にする。単にプリミティブを組み合わせた記号的な植物、左右対称な作り物のような植物、同じ葉を機械的に並べた植物で完成としない。

## 必須の追加資料（制作開始時に読む）

- [references/production-quality.md](references/production-quality.md)：調査・形態設計・実装・品質評価と再修正の詳細工程。以下の基本指示と合わせて遵守。
- [references/visual-library.md](references/visual-library.md)：実物写真・植物画の参照先と、同梱の技術画像の索引。画像を実際に開いて確認する。
- `assets/geometry_samples.png` と `assets/structure_guide.png`：葉・枝・葉序の技術参考画像。最終品質の上限ではない。
- `scripts/plant_geometry.py`：曲面葉、テーパー枝、葉序、GLB出力の再利用可能な実装（numpy/trimesh）。`scripts/demo_shapes.py` は実行例。対象種の固有構造を追加して使用し、汎用見本だけで完成させない。
- `examples/spec-template.json`：制作ごとの形態仕様記録。
- [references/implementation-notes.md](references/implementation-notes.md)：同梱コードの使い方と検査範囲。

**絶対条件：植物の名前が変わっても同じ形の葉・樹冠を使い回すだけの生成は禁止。参考画像の特徴から対象種専用のパラメータ・構造を設計する。実行環境がある限り、生成したモデルのレンダーと参照を比較し、欠点を修正してから納品する。**

## V3：花・草花の品質改善（必須）

- [references/flower-quality.md](references/flower-quality.md) を花・草花制作時に必ず読む。`assets/review_failure_example.jpg` はユーザー提供の改善対象画像であり、品質目標ではない。
- 花弁と葉の滑らかな曲面、薄い縁、種ごとの花序、自然な開花度と花柄の方向を必須とする。`scripts/flower_geometry.py` と `assets/flower_primitives.glb` は曲面実装の技術見本。
- 複数種を依頼された場合は代表1株で生成・比較・修正・再レンダーを行い、その品質を確立してから各種を個別設計。全種を同じテンプレートに流し込まない。
- 花弁の角張り、厚い樹脂のような縁、折り紙状の葉、球体の花序、硬い星形の花、同心円の花弁、機械的な高さや向きの反復は、実物参照で妥当と確認できない限り修正対象。形態と質感を別に調整する。
- 実物写真との比較、クレイ表示、ゲーム内想定距離の表示、修正前後の確認を行う。見ていない画像を確認済みにしない。実行環境がなければ未検証として明記。

## 1. 入力と仕様

- 植物名、学名（判明している場合）、品種、参考画像、成長段階、サイズ、季節、用途、希望形式、表現スタイルを把握する。
- 既存の指定を優先し、同じ質問を繰り返さない。植物名だけでも、対象が明確なら作業を進める。寸法・ポリゴン数など未指定の制作上の設定は暫定値として明記する。
- 同じ和名が複数種を指し、同定の違いが形状に大きく影響する場合は確認する。画像だけから品種・学名を断定しない。架空植物はユーザーの設定を優先する。
- デフォルトはリアルな形態と自然な質感。ゲーム向け、トゥーン、ローポリ、テクスチャなし等は指示がある場合に適用する。形状のリアルさとレンダリングのリアルさは別々に管理する。
- Blenderで編集可能なモデルを基本とする。出力形式に指定がなければ .blend と再生成用 .py を目標にし、ゲーム等への組み込み用途では .glb も出力する。BlenderがなくてもPythonとnumpy/trimeshでGLB生成できる場合は実際のGLBを納品する。いずれも実行できない場合は実行可能な .py を納品する。

## 2. 植物の構造を先に調べる

ウェブ検索や資料参照が可能なら植物園、大学、植物誌、標本データベースなどから対象の形態を確認する。写真を参照できる場合は全体像、枝の分岐、葉の表裏・葉序、花・実・幹など複数の角度を確認する。検索が使えない場合は確実な知識と提供資料の範囲にとどめ、不明点を明記する。出典を捏造しない。

モデルを作る前に以下の内部仕様を決め、対象の形態をコードに反映する。

- 全体：樹形、草姿、成長方向、高さと幅の比率、重心、密度、シルエット。
- 骨格：主幹の有無、枝の分岐方式、節、節間、枝の次数、根元、先細り、重力の影響。
- 葉：互生・対生・輪生・根生等の葉序、単葉・複葉、葉柄、葉身、葉縁、葉脈、反り、厚さ、表裏、成長段階。
- 花・実：花序、花弁・萼・雄しべ等の構造、花や実の付く場所、季節、成熟度。
- 質感：樹皮、茎、葉表と葉裏、色と粗さ、透過性。不要なノイズを足さない。

植物の種類別設計は [references/botanical-modeling.md](references/botanical-modeling.md) を参照する。

## 3. モデリング原則

### 3.1 骨格を先に作る

1. 主幹・茎・根元から、実際の成長方向に沿った曲線または連続メッシュを生成する。
2. 枝や葉柄を親の節・枝の表面と連結する。枝は先端へ細くなり、分岐部に自然な太さと角度があること。
3. 茎の接線から局所座標系を作り、その座標系で葉や花を取り付ける。ワールド座標の固定方向に並べない。
4. 自然な曲がり、重力、光の方向を必要に応じて反映する。ランダムなジグザグや無意味な分岐を避ける。

### 3.2 葉を一枚ずつ成立させる

- 葉の付け根から先端への中心線を作り、葉幅プロファイルに沿って左右の頂点を配置する。頂点数は葉縁や曲面が表現できる数にする。
- 葉柄が葉身の付け根につながること。葉を中央で茎に突き刺さない。ただし盾状葉など、その種特有の付着位置は正しく表現する。
- 葉の種類に応じて長さ、幅、先端、基部、葉縁、主脈、側脈、反り、ねじれ、断面を設計する。単葉を単純な楕円板に統一しない。
- 互生・対生・輪生などの実際の葉序を守る。137.5度の螺旋配置は適切な種類の近似に限り使う。すべての植物に適用しない。
- 対生の植物でも葉の長さ・角度・曲がり・展開度に自然な個体差をつける。全体を左右鏡像にしない。ただし植物固有の規則的な構造は崩さない。
- 複数の葉形状を用意するか、パラメトリックに変形する。若葉、成熟葉、下葉を必要に応じて区別する。
- 葉が浮く、茎を貫通する、すべて同方向を向く、等間隔すぎる、同形の葉が放射状に機械的に並ぶ状態を避ける。

### 3.3 花・果実・樹冠

- 花は種に合った花弁数・配置・花序・花柄・萼等で作る。花弁の曲面・厚み・重なりを表現する。
- 果実は枝や花柄から成長した位置・向きに置く。未指定の植物に装飾として花や果実を勝手に追加しない。
- 樹冠は枝の成長構造と葉群で形成する。球体を数個置くだけで完成としない。遠景用の簡略LODだけは例外として扱う。
- シルエットと葉群内部の空間を両立させる。局所的な密度差、空隙、枝の見える部分を作り、均一な塊にしない。

### 3.4 自然なばらつき

再現可能なシード付き乱数を使う。ばらつきは対象の生育形態に従って制御する。全体の樹形、節の間隔、枝角度、葉の大きさ、展開度、色、曲がりを独立に無秩序化するのではなく、枝の位置や成長段階と関連付ける。花弁数等の種固有の特徴を乱数で壊さない。

## 4. 実装・出力

[references/blender-workflow.md](references/blender-workflow.md) の実装・検証手順に従う。

- Blender Python (`bpy`, `mathutils`) で自己完結した生成スクリプトを作る。必要なら Geometry Nodes、メッシュインスタンス、テクスチャを使う。
- 実行環境を確認する。Blender実行やMCP接続が可能なら生成、保存、レンダリング、検証まで行う。Blenderが利用できない場合は、numpy/trimeshによるGLB生成・再読み込み検査が可能か確認する。どちらも利用できない場合は動作未確認のスクリプトとして納品し、実行方法を案内する。画像・疑似コード・説明だけで実際の3Dモデルが生成済みとは言わない。
- 既存の .blend やシーンを無断で消去・上書きしない。生成物は専用コレクション・出力先に分離する。
- メートル単位、BlenderのZ上向き、植物の接地位置を原点とすることをデフォルトにする。ユーザー指定があれば従う。
- マテリアル、UV、法線、オブジェクト名を整理し、部位別に編集可能にする。用途に応じてインスタンス化・結合する。
- ポリゴン制約がない限り、形態を過度に簡略化しない。必要なら高品質版と軽量版を別々に出力する。
- テクスチャは必要に応じて自作するか、権利を確認できるものを使う。ウェブ写真を無断でテクスチャとして転用しない。

## 5. 品質確認と修正

実行できる場合、正面・側面・背面・斜め上・真上と、葉や分岐の拡大を確認する。照明やカメラで欠点を隠さない。チェック項目：

- [ ] 種に固有のシルエット、葉形、葉序、分岐、花や果実の特徴がある。
- [ ] 植物の全体比率と成長段階が自然で、鏡像・過度な規則性がない。
- [ ] 葉、枝、花、実が正しい位置でつながり、不要な浮きや不自然な貫通がない。
- [ ] 曲面、葉の反り、葉縁、法線、テクスチャの向きに問題がない。
- [ ] すべての視点で自然に見える。接地位置、サイズ、原点が仕様に合う。
- [ ] 出力先、ファイル形式、マテリアル、実ポリゴン数を確認した。
- [ ] 可能ならエクスポートしたモデルを再読み込みして確認した。

欠点があれば原因を特定し、生成コードまたはモデルを修正して再確認する。実行・目視・再読み込みをしていない場合は該当する検証を未実施と記録する。

## 6. 最終納品

長い説明よりも、作成物を優先して提示する。
- 実際に作成したファイルと形式。
- 植物名・成長段階・寸法・制作上の暫定設定。
- 実行できた検証、できなかった検証、参照資料（使用した場合）。
- 実行環境がない場合は .py と、Blenderでの実行手順を提示する。

## 使用例

- 「リアルなオリーブの木を3Dにして」→ 対象の枝ぶり、葉の形と表裏、樹冠を調べて立体化。季節・実の有無は指定や根拠を踏まえて扱う。
- 「キャベツの成長段階を3種類作って」→ 苗、結球前、結球後など指定の段階ごとに別個体を作る。単に同じモデルを拡大しない。
- 「画像の花をトゥーン調でGLB化して」→ 参考画像の形態を維持し、材質や色の表現だけを調整。見えない部分を補った場合は明示する。
