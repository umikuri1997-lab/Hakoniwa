# 制作工程と品質ゲート（必須）

## 0. 実行環境を確認
Blender MCPが接続済みならその実行能力を確認。ローカル Blender があればバージョンを取得し、`blender -b -t 4 --python build.py` などで実行する。Blender がなくても Python + numpy + trimesh が利用可能なら `scripts/plant_geometry.py` を利用して GLB を実生成できる。利用不可なら完成品を装わず生成コードを納品。インストールや外部操作に必要な許可は勝手に回避しない。外部から取得したコードはそのまま実行しない。

## 1. 対象ごとの形態設計書
制作ごとに `plant_spec.json` または同等の記録を作る。`examples/spec-template.json` を参照。観察値・文献値・制作上の仮定を区別する。高精度優先で、葉の数、花数、サイズなどは固定テンプレートで決めない。

## 2. 形態を段階的に構築
- ブロックアウト：樹高、幅、根元、主軸、枝の階層、花や葉の領域を配置。球の輪郭ではなく空間的な成長構造を評価。
- 骨格：分岐の根元と末端を連結し、節を明示。枝径は親枝と子枝の関係に沿って滑らかに変化。分岐は自然な枝元の膨らみを持つ。必要なら局所的なリメッシュやブーリアンでなじませるが、葉や細枝まで一律にボクセル化しない。
- 葉：中心線C(t)、左右幅W(t)、曲率、横断面、ねじれを別に設計。葉の輪郭、葉脈、枝の節を形状の手掛かりにする。葉表の主脈を必要に応じて微細な隆起にし、側脈は主脈から葉縁へつなげる。接写用は細分化したメッシュ、通常距離は法線/色/粗さ、遠景は適切なカードやLOD。葉脈を白線で機械的に描かない。
- 形態特有の部位：複葉の小葉軸、イネ科の葉鞘と葉舌、針葉樹の短枝・葉束、花の萼と花柄、ロゼットの芯、地下茎などを識別。対象にない構造は作らない。
- ばらつき：枝単位の密度や成長方向を先に決め、各葉に微差。左右対称コピー禁止（ただし種固有の対称性は維持）。全個体で同じ乱数パターンを使わない。シードを保存。
- 衝突：葉の完全な非重複は要求しない。自然な重なりは残す。明らかな貫通や浮きは局所的に修正。枝と葉の接点の距離を記録して検査できる構造にする。

## 3. マテリアルと表現
PBRの場合、葉のベースカラー、表裏差、粗さ、透過・SSS（レンダラーに応じる）、細脈・樹皮を分離。カラーはsRGB、粗さ・法線等は非カラー。GLB非対応のプロシージャルノードはベイクして確認。粗さや透過の値は種・環境・参照に合わせる。ゲーム向けトゥーンでは輪郭・曲面・葉序を保持して、色数やハイライトを整理。写真の質感を無条件に足さず、指定の無影・ノイズなし・背景なしなどを守る。照明は検査のためでモデルに焼き付けない（指定を除く）。

## 4. レビュー画像
以下のセットを出力できる環境で必ずレンダーする。背景は単色、モデル全体を画角内に入れ、同一スケールと露出を使用。正面/左右/背面/上面/斜め、細部（葉の付け根、葉裏、樹皮、花等）。クレイ表示とマテリアル表示を別々に評価。ゲーム用は実使用の距離とカメラでも確認。モデルと参照画像を同じ大きさに整えて比較する。シルエット一致だけでは合格にしない。

## 5. 合格判定と修正
各項目を0〜5点（0=未確認または破綻、3=最低限妥当、5=参照と整合し欠陥なし）で自己評価。実物の特徴、全方向のシルエット、葉と枝の接続・生長構造、曲面と葉縁、マテリアル、出力の正常性の6項目。各項目4点以上かつ検証済みを目標とする。点数は主観的なので、理由と比較画像で補強する。目視できない場合は未確認と明記、合格と呼ばない。

致命的な問題（対象種の誤り、反転法線、葉の浮き、多数の貫通、出力ファイル破損、形式違い、サイズ誤り）は点数に関係なく修正必須。最低1回の生成→画像確認→具体的な修正点の抽出を実施し、欠陥があれば修正→再レンダー。解消できない場合は未解決事項を明記。画像なしの自己採点だけで完成宣言しない。

## 6. 出力・検査
高品質版を先に完成させ、必要に応じて別LODを生成。ポリゴン数は用途・距離・対象に合わせる（未指定なら実測値を提示、決め打ちしない）。BLEND内ではパーツ名、コレクション、マテリアルを管理。GLBは標準Y-upに変換するのは一度だけ。Blender公式エクスポータは自動変換するので手動回転を重ねない。UV/マテリアル/テクスチャが同梱されているか確認。`trimesh.load(..., force='scene')` 等でGLB再読み込み、有限座標、空メッシュ、面積ゼロ面、寸法、三角形数を確認。葉は開いた片面メッシュを許容するが、両面描画を設定。用途が製造・印刷なら閉じた厚みを別途設計。

納品: 実モデル、再生成コード、プレビュー、参照・仮定・修正内容・検査結果の簡潔な記録。ファイルの存在と実行を検証してからリンクを提示。
