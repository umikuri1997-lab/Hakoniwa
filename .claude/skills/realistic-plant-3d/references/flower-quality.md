# 花・草花の造形品質：V3 必須追加規則

## 実際の出力から判明した問題
`assets/review_failure_example.jpg` はユーザー提供のゲーム内スクリーンショット。完成品質の見本ではなく、改善対象として参照する。画像から確認できるのは外観のみで、元メッシュ、法線、ポリゴン数、生成手法は未確認。以下は観察と改善方針であり原因の断定ではない。
- 葉が三角・菱形の平坦面や中央の鋭い折れに見える。葉の基部、葉幅の変化、葉先、葉縁、主脈の両側の緩い曲面を対象種ごとに設計する。
- 花弁が硬い板や厚い樹脂のように見える。縦方向の反り、横方向のカップ、先端と縁の薄さ、局所的なねじれを独立に制御する。
- バラに見える花は同心円状の段差が目立つ。内側の巻き込み、外側の開き、隣接花弁の重なり、層間の角度ずれを設計し、花弁の境界を硬い溝にしない。
- アジサイに見える花序は球に小花を配置した形に見える。実際の花序の分岐、個々の花柄、装飾花とその配置を作り、外形を完全な球にしない。球面配置はブロックアウト専用。
- ユリに見える花は硬い星形に見える。花被片を付け根から先端まで連続曲面にし、喉部と先端の反りを分け、雄しべと雌しべの接続を確認する。
- 画面内で株ごとに同じ高さ・開き方の花が繰り返される傾向がある。生長段階、花柄の傾き、葉の姿勢に相関した個体差を入れる。

## 最優先：対象種の構造を先に確定
植物ごとに全体・花正面・側面・裏面・葉と節の写真を実際に開いて観察。品種差を認識する。以下は一般的な観察ポイントであり種固有の事実は個別調査で確認する。ゲーム用のデフォルメは、実物構造が成立してから行う。対象の指定がある場合、花や品種を勝手に追加・変更しない。

| 対象 | 必ず個別設計するもの | 禁止する近道 |
|---|---|---|
| バラ | 花弁の幅・巻き・開き、重なり、層間角度、萼、複葉、葉柄 | 円盤や同心円リング、球に模様を貼る |
| アジサイ | 花序の分岐、花柄、装飾花の形、局所的な向きと密度、葉の鋸歯 | 球体に同じ花を均一に貼る |
| ユリ | 花被片の基部と反り、花筒の有無、花糸・葯・雌しべ、葉序 | 平たい星、硬い三角板、中央の浮遊部品 |
| ヒマワリ・デージー | 頭花、舌状花の基部と反り、筒状花の集合、総苞 | 単一球の花芯、均一な板状花弁 |
| パンジー | 花弁の異なる大きさ・重なり・方向、模様と喉部 | 同形の5枚の円盤、強い縁取り |
| アサガオ | 合弁の連続した漏斗状花冠、縁の波打ち、喉部、つる | 独立花弁の放射配置、底なし円錐 |
| チューリップ | 花被片のカップ、開花度、花被片の重なり、葉の包み込み | 球に溝を入れるだけ |
| ラベンダー | 花穂の節と小花、苞、細葉、穂ごとの開花差 | 紫の円柱、均一な球列 |

## 曲面の実装
- 花弁は中心線の曲率と横断面を独立に設計し、葉メッシュを形状変更なしで花弁に転用しない。曲面グリッドの各頂点に縦反り・横カップ・ねじれ・縁のうねりを与える。広い花弁先端は一点へ収束させず、丸い輪郭を保つ。
- 初期の実装目安：花弁の長手方向24〜48区間、横方向8〜16区間。花筒の周方向64以上、縦方向24以上。これは暫定のサンプル値であり、接写や形態に応じて増減。輪郭が角張る場合は増やす。単純に細分化しても元の造形が誤っていれば不合格。
- 葉・花弁は滑らかな法線。中央に意図しない折り目を作らない。薄い形状には両面材質、必要なら微小厚みを付ける。均一に厚い縁や白い輪郭線は不要。GLBの出力後も滑らかさと両面表示を確認する。
- `scripts/flower_geometry.py` は丸い花弁・連続花冠・重ね配置の実装例。`assets/flower_primitives.glb` は曲面の技術見本であって、完成植物ではない。サンプル形状をそのまま対象の完成品として使用しない。

## 株の構造・色
- 茎と花柄の曲線を先に生成し、その先端の接線に基づいて花を取り付ける。根元の位置、花の高さと方向、花柄の長さを関連づける。花数だけを増やさない。
- 葉と花の角度を全て同じにしない。生長点、茎の高さ、向光性、葉齢に対応するばらつきにする。左右対称の鏡像コピーを避けるが花の生物学的対称性は守る。
- つぼみ・開花途中・満開は指定や資料に合う場合に作る。全ての株に強制しない。色は葉の表裏、花弁の基部と先端で自然に変化させる。過度な彩度、均質な光沢、太い白線、汚れノイズで形状を隠さない。
- 写実的な形状＋整理した色のゲーム向け表現と、写真のようなPBR表現は別設定。スタイル指示がある場合に優先する。

## 納品前の比較検証（既存の品質評価に追加）
1. 代表1株を先に作り、同種の写真と正面・斜め・側面・真上・花の拡大を比較する。大量生成を先行しない。
2. クレイ表示で花弁の輪郭・反り・重なり、葉の曲面、節の接続を確認。マテリアル表示で色と光沢、GLBインポート後の見え方を確認する。
3. 実際のゲームカメラと同等の縮小表示でも、シルエットが崩れないことを確認。接写では見える折り目や段差を修正する。ゲームカメラが不明なら仮の斜め俯瞰で検査したと記録。
4. 最低1回は欠点を特定し、コードまたはモデルを具体的に変更して再描画する。修正前後の画像を保存する。欠点が見つからない場合は形状比較で理由を示す。
5. 代表株が合格してから他の種へ展開する。ただし種ごとに写真・形態・検査を繰り返す。一つの花冠テンプレートを全種へ使い回さない。
6. 画像を確認できない環境では目視未検証。自己採点やファイルの読み込み成功だけでは造形品質の合格にしない。問題が残る場合は具体的に報告する。
