# V6 実出力の検証と曲面品質（全植物に適用）

`assets/review_rose_v5.jpg` はユーザー提供のゲーム内画像。見える問題は内花弁の鋭い多角形・細い白筋・葉の平坦な輪郭・太く直線的な茎・均一な色。元モデル・描画エンジンは未確認なので原因の断定は禁止。白筋は交差、法線、片面表示、材質、Z-fighting 等を個別に検証する。

## 既存コードの具体的改善
- `plant_geometry.export_glb` は NORMAL 属性を明示して書き出す。Blenderのメッシュも必要な曲面でポリゴンの use_smooth=True を設定。鋭い折れを滑らかに見せるだけでなく、輪郭そのものの分解能も確保する。
- `flower_geometry.petal` はUVを持つ。花弁の基部をV=0、先端をV=1とする。花弁の薄い縁に明るい不自然な線を塗らない。ノーマルマップを一旦外して形状と法線を検査する。
- `scripts/rose_curved.py` は円周方向に巻く花弁を生成する実装例。外周は幅広く開き、中心は小さく立ち上がる。単純な平板を中心から放射する方式の代替。`assets/rose_bloom_prototype.glb` は花冠と萼・茎のみの技術試作で、完成したバラの株ではない。造形の目視合格を保証しない。花弁の貫通や品種固有の形態を確認・変更して使う。

## バラを作る場合
1. 対象の品種（未指定の場合は仮の園芸バラ）、開花段階、全体寸法を記録する。実物資料と `assets/plant-atlas/flowers-a.jpg` 等を開く。
2. 花弁を1枚ずつ曲面として形成。付け根が細く上部が広がる輪郭、中心から外への巻き、縁の外反、隣接花弁が覆う部分を設計。中心が三角形の破片や空洞に見える場合は、中心花弁の幅・巻き角・高さ・接続部を変更。単純なポリゴン増加は禁止。
3. 代表1花の正面、側面、斜め上、真上、クレイ接写を作る。交差が疑わしければ花弁単体表示・断面・ワイヤーフレームも調べる。見える交差線・白い筋を修正。自然な重なりを削除する必要はない。
4. 花冠が成立してから、細く先細りした曲線茎、花柄、萼、葉柄、対象品種に合う羽状複葉を作る。小葉には丸み、鋸歯、主脈から両側への緩い曲面、先端への反り、適度なねじれ。葉序・複葉構成を実物資料で確認し、左右で少し姿勢を変える。全葉を同じ三角形にしない。
5. 花冠、つぼみ、葉の位置や向きは成長に従わせる。色は花弁の基部・縁・表裏で緩やかに変化させる。茎も単色の太い棒にしない。色・粗さ・法線を別検証し、質感は形状欠陥を隠さない。

## すべての植物の納品前の強制ゲート
- 元メッシュとゲーム用エクスポート後のメッシュの両方を、同じカメラ条件の近景と想定使用距離で表示。Blenderで滑らかでもGLBで角張れば不合格。
- GLBの各曲面 primitive の NORMAL と TEXCOORD_0 を確認。テクスチャが適用されない場合はUV・画像・材質リンク・エクスポートを確認。doubleSided は薄い葉・花弁に必要な場合に使用。
- 形状だけ（クレイ、無地）、材質あり、最終ゲーム表示の3種類を比較。欠点の原因を一つずつ切り分け、修正前後を保存する。画像を実際に確認できない場合は目視未検証。未検証のまま品質合格とは言わない。
- 形状が自然でない場合はテクスチャ追加や自動平滑化だけで完了扱いにしない。種別に設計を変える。ユーザーの要求する画風と寸法を優先する。

## 実装検証の範囲
同梱試作のGLB再読み込み、有限頂点、非縮退三角形、NORMAL属性、花弁UVを機械検査済み。Blender・ゲームエンジンでの描画、貫通検査および実物との見た目の比較は未実施。試作は最終品質の見本ではない。
